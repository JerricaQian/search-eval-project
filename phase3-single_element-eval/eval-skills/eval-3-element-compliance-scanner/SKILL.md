## 三档解释与证据展示契约 / 统一输入与执行契约

通用条款见 [[单一元素评测通用契约]]（`phase3-single_element-eval/单一元素评测通用契约.md`），本 Skill 仅列专属部分：

- `observableFact` 书写要求：完整保留 `finding` 四字段用于校验；问题卡只展示"可见事实，评级为<评级>。用户影响。"，不重复展示规范条文和判定过程。`observableFact` 必须写清元素原文、所在分区及可见的样式或位置偏差。
- 示例输出：`C1 的"满减"标签出现在标题区且使用价格级红色强调，评级为不达标。用户会将营销信息误认为商品标题的一部分。`
- **Phase2 事实优先：**元素分区、卡型、可见文本、视觉规格桶和可取到的精确属性必须读取 `structure`、`render`、`textFacts`、`visual`；Phase3 仅对照规范作合规终判，事实未知不得臆测为违规。
- **标签位置不得单独定罪：**标签可出现在标签区以外的合法业务区域（如头图区角标、标题区履约标、价格/权益信息附近或下挂区）。标签位于非标签区本身不是不达标依据；只有当前页面版本的对应卡型/分区规范明确禁止该位置，且已从当前截图或 IMD 源值确认位置、样式和语义均冲突时，才可判不达标。不得把历史版本、其他卡型或“标签通常位于标签区”的经验当作规则。
- **版本隔离：**评测前必须以本次输入的截图或 IMD 源值确认页面版本；不得复用 1.0 页面颜色、底色、分区或标签样式来判定 2.0 页面。版本无法确认时记录“待确认”，不得输出不达标。

# 单一元素规范符合性评测（静态元素不复杂）

## 工具定位

本 Skill 服务于**评测人员**，用于评估搜索结果页/信息页中**单一元素**是否符合美团现有设计规范。
它的能力是：帮助评测人员处理复杂的信息页面，**识别页面/组件中的每个单一元素**，逐元素比对现有设计规范，
最终给出元素级的**合规性结论**——

- **元素设计符合现有设计规范 → 🟢 优秀**
- **元素设计不符合现有设计规范 → 🔴 不达标**

评估的核心问题是：**这个元素放在这个位置、用了这样的字号/字重/字体/颜色/底色/圆角/描边/阴影/层级，符不符合规范？**

**判定依据（三份规范，均见 `references/设计规范速查.md` 与 `references/商卡分区规范清单.xlsx`）：**

1. **分区规范清单**：9 个画板（商品卡/商家卡文字下挂/商家卡图文下挂/酒店卡/度假套餐卡/主点卡/演出电影卡/弱下挂容器/医美连锁容器）× 各分区的「允许元素 / 最大条数 / 优先级 / 可用样式 / 可用色值」。
2. **原子样式规范**：全画板统一的字体、字号阶梯（@2x px→@1x pt）、字重、颜色语义白名单、圆角、描边、阴影。
3. **组件源样式字典**：标签/角标底图的 CSS 级精确值（`linear-gradient(角度deg, #hex 位%)`、描边色+px、阴影 radius/offset/alpha），源自 IMD 组件底图（window.mg），是判定标签底色/描边/阴影是否合规的最精确依据。

**与同系列 Skill 的边界（口径不同，务必区分，勿混用）：**

- 本 Skill（`single-element-spec-compliance-scanner`）：判定**单一元素是否"符合规范"**（合规性，🟢/🔴 二分），关注放对分区没、样式对不对。
- `static-element-complexity-scanner`：**组件级**统计**异形/异色标签数量、icon 数量**（复杂度计数），关注多不多，不判合规。
- `single-element-color-scanner`：**元素级**统计**单一元素内的颜色数量**（≤2/=3/>3），只数颜色种类，不判是否放对分区/字号是否对。
- 若用户明确说「符合规范/合规/规范走查/静态元素不复杂」，用本 Skill；若说「颜色数量/36 色」，用颜色 Skill；若说「标签数量/复杂度」，用复杂度 Skill。

## 前置与依赖

- **规范依据（必读）**：`references/设计规范速查.md`（规范全量速查）；需要 CSS 级精确渐变/描边/阴影时读 `references/商卡分区规范清单.xlsx` 的「组件源样式字典」sheet。**判定前务必先加载规范速查，不要凭记忆判合规。**
- **输入来源**：支持两种——(a) 用户提供**本地整页/整卡截图**（PNG/JPG，可能已用红框圈出待评元素）；(b) 用户提供 **`imd.sankuai.com` 设计稿链接**（可用 window.mg 直接读节点的字号/字重/颜色/底图，比截图更精确）。
- **元素识别 / 分区定位只消费对应截图的 Phase2 manifest**：卡型、分区、图片/营销/金刚/标签归属和元素坐标均来自该单图 JSON。manifest 缺失、未通过整页门控或事实不确定时回退 Phase2；禁止调用历史 IMD/SceneSpec 工具重新定位，也禁止 AI 人工补判归属。
- **IMD 精确取值（强烈推荐用于设计稿链接）**：通过 `catdesk-browser` 完成内网登录态后，用 `window.mg` 读取目标节点的 `textStyles`（字号/字重/字体/字色）、`fills`（含渐变 `gradientStops`/`gradientHandlePositions` → CSS 角度与停止位）、`strokes`+`strokeWeight`、`effects`、`cornerRadius`。字号需按 @2x→@1x 换算（px÷2=pt）。
- **辅助工具**：图片读取/放大工具（image_read）用于看清字号、字色、底色、描边（看不清必须放大再判，见 Gotchas）。

## 主判定流程

```
拿到截图 / 设计稿
      │
      ├─ 已圈出元素？──是──→ 只取被圈元素为待评清单
      │                └─否──→ 拆出页面/卡片中所有单一元素为待评清单
      │
      ▼
对每个待评元素：
  ① 定位归属：属于哪张卡（9 画板）？哪个分区？
      │（排除项：商家头图/下挂图片/营销图·banner本体/金刚icon —— 标"非评测元素"跳过）
      ▼
  ② 逐维度比对规范（逐项核对，把所有"不符"维度都记下来，不要命中第一个就停）：
      ├─ [位置] 该元素是否被规范允许出现在此分区？是否超"最大条数"？层级优先级对不对？
      ├─ [字号/字重/字体] 是否落在标准阶梯、与该分区规定的字号字重一致？字体是否苹方-简？
      ├─ [颜色语义] 文字色是否属该分区允许的颜色语义白名单？有无越界用色？
      ├─ [标签样式] 若为标签/角标：底色渐变色系、圆角、描边、阴影是否匹配组件源字典？
      │            该分区是否允许彩色/是否要求去底色（如商品卡标签区去底色、套餐卡仅灰）？
      └─ [收敛规则] 是否违反分区收敛（如价格区仅红/棕/黑/灰、演出头图不放标签）？
      ▼
  ③ 全维度均符合 → 🟢 优秀；任一维度不符 → 🔴 不达标（记录不符维度与规范期望值）
      │（若命中"规范已知弱点 P1~P10 的灰区"，判 🟢 并注明"规范内部待统一"，不判元素违规）
      ▼
汇总：元素级明细表 + 非评测元素清单 + 🟢/🔴 分布与整改建议
```

## 核心概念

### 什么是「单一元素」（评估粒度）

粒度是**元素级**，不是整卡、不是整页。切分规则：

- **同一分区内、视觉/语义上独立的一块，算一个元素。** 例如：标题文字一个元素、标题右侧的「团购」履约标另一个元素、价格一个元素、每一个独立标签各算一个元素、营业状态一个元素、评分一个元素。
- 标题文字 + 旁边的标签属于**两个元素**，分别判定，不合并。
- **若用户已在截图上圈出元素，则只评被圈元素**，圈几个评几个，不自行扩展。
- **若用户未圈出**，则拆出该页面/卡片中所有单一元素逐一判定。

### 什么叫「符合规范 / 不符合规范」（判定维度）

一个元素**同时满足以下所有适用维度**才判 🟢，任一维度不符即判 🔴：

| 维度 | 符合规范的含义 | 典型违规（🔴） |
|------|---------------|---------------|
| 位置/分区 | 该元素被规范允许出现在其所处分区 | 元素放错分区（如把"优选新店"放进商品卡价格区而非商家卡评分/新店区）|
| 最大条数 | 未超过分区规定的条数上限 | 标题超 2 行、履约标签多于允许数、头图放了多个直播标 |
| 层级优先级 | 多元素排布顺序符合分区优先级 | 违反"一级>二级>三级""履约标签>商家名>标题" |
| 字号/字重 | 命中标准字号阶梯，且与分区规定一致 | 用了 14.5px 等非阶梯值；标题用了正文字号 |
| 字体 | 苹方-简 | 混用其它字体 |
| 颜色语义 | 文字色属该分区允许的颜色语义 | 价格区出现非红/棕/黑/灰；套餐卡标签用了彩色 |
| 标签底色/圆角/描边/阴影 | 匹配组件源字典的对应语义 | 标签色系错位、圆角非 6pt、加了规范外描边/阴影；应去底色的标签区标签带了底色 |
| 收敛规则 | 满足分区级收敛约束 | 演出卡头图放了标签；价格区标签化 |

### 排除项（非评测元素，不判合规）

以下**整体不作为待评单一元素**，标记"非评测元素"跳过：商家头图/实拍图、图文下挂里的商品缩略图、营销图片/banner 大图本体、页面金刚位图标。
**图片内嵌文字属排除项**：商家上传的商品主图/下挂图上“烧”进去的营销文字（如下挂图上的「招牌双人餐/尝鲜双人餐/特色尝鲜」等绿底金字）属**图片素材内容**，判为排除项，不作规范符合性判定。
**注意**：压在头图上的、由系统渲染的独立角标/标签（直播标/履约标/券标）、标签内部的小 icon（券 icon/闪电/榜单徽章）**要评**，不在排除之列。判断依据：文字是“图片像素的一部分（随图缩放）”→排除；是“系统可配置的独立渲染层”→评测。难以分辨时标待确认。

### 规范"灰区"（判 🟢 但注明，勿误判为元素违规）

规范本身存在已知弱点（`references/设计规范速查.md` 第四节 P1~P10），落在这些灰区的元素**判 🟢 并注明"规范内部待统一"**，不算元素违规。例如：新店绿裸字 #00A72D/#00B300 跨卡不一致（P2）、同语义近似色值（P4）、绿标渐变角度 135°/139°/144° 差异（P10）、"优选新店"绿裸字与标签区文字标签口径差异（P1）——这些是规范待收敛，不是元素做错。

## 评估标准

对**每个元素**独立评估：

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 所有适用维度均符合现有设计规范 | 合规 |
| 🔴 不达标 | 任一适用维度不符合现有设计规范 | 不合规（需记录不符维度 + 规范期望值）|

> 二分制，无中间档。落在"规范灰区 P1~P10"的判 🟢 并注明来源问题编号。

## 执行步骤

### Step 0：加载规范（判定前必做）

读 `references/设计规范速查.md`，建立三份规范的心智：字号阶梯、颜色语义白名单、9 画板各分区规则、组件源样式字典、已知弱点 P1~P10。需要标签底色/描边/阴影的 CSS 级精确值时，读 `references/商卡分区规范清单.xlsx` 的「组件源样式字典」sheet。**不要凭记忆判合规。**

### Step 1：接收输入并确认评测范围

1. 确认输入来源：
   - **IMD 链接** → 走下方「IMD 精确取值工作流」（登录→定位画板/节点→读 window.mg 精确属性；文字/底图能读到源值，判定最准）。
   - **本地截图** → 用 image_read 加载并**放大**（本指标最易因看不清字号/字色/底色而误判，见 Gotchas）。
2. 判断是否已**圈出待评元素**、用户是否限定范围：
   - 已圈出 → 只评圈出元素（记录每个框的位置与内容）。
   - 指定"只看某张卡/某分区" → 只拆该范围。
   - 未圈出未限定 → 进入 Step 2 拆全部元素。
3. 记录场景标识（搜索词/页面名/卡片序号/卡片类型），便于结果表定位。

### Step 2：拆分元素并定位归属（识别单一元素 + 判所属分区）

对每张图/每张卡：

1. **先判卡片类型**（对照 9 画板：商品卡/商家卡文字下挂/图文下挂/酒店卡/套餐卡/主点卡/演出电影卡/两类容器）。卡型判错会导致后续全部分区规则套错，**必须先定卡型**。
2. **再逐元素判分区**：头图区/头图角标/标题区/基础信息区/评分新店区/距离服务时间区/标签区/价格区/下挂区/免责声明区等。
3. **排除非评测元素**（商家头图/下挂图片/营销大图本体/金刚 icon），标记跳过。
4. 按「单一元素」粒度拆开（标题与相邻标签分开；每个独立标签各一条；营业状态、评分、价格各一条）。

> 分区定位是本指标关键，可复用 `phase2-card-annotation` 的《页面与商卡识别规则》。踩线归属（榜单腰封 vs 榜单标签、图文下挂 vs 文字下挂）先按规则判，不确定时在结论中标注假设或向用户确认。

产出待评清单：每条 `{元素名, 卡片类型, 所属分区, 位置/框, 内容}`。

### Step 3：逐元素比对规范（取值 → 比对 → 记录不符项）

对每个待评元素：

**Step 3a — 取该元素的实际属性：**

- **IMD 链接**：读 window.mg 节点的 `textStyles`（字号需 px÷2 换算 pt、字重、字体族、字色）、`fills`（底色/渐变，含角度与停止位）、`strokes`+`strokeWeight`、`effects`、`cornerRadius`。这是最精确的取值方式，优先使用。
- **本地截图**：放大后目视/取色读出 字号相对关系、字重、字色、底色、圆角、描边、有无阴影。截图无法精确到 px 时，以"是否落在标准阶梯、色相是否落在允许语义"为判据。

**Step 3b — 逐维度比对该分区规范**（对照 Step「判定维度」表）：

按 位置/分区 → 最大条数 → 层级优先级 → 字号字重 → 字体 → 颜色语义 → 标签底色/圆角/描边/阴影 → 收敛规则 顺序**逐项走完**（不要命中第一个不符就停）。**把所有"不符"维度都记录下来：不符维度 + 元素实际值 + 规范期望值。** 一个元素可能同时不符多个维度，需全部列出，便于评测人员一次性整改。

**Step 3c — 灰区豁免**：若某项差异命中 P1~P10 已知弱点（如新店绿值差异、近似色、渐变角度差异），不计为违规，标注"规范灰区 Px"。

### Step 4：逐元素评级

- 所有适用维度均符合（且无非灰区不符项）→ 🟢 优秀。
- 存在任一非灰区不符项 → 🔴 不达标，附"不符维度 + 期望值"。

## IMD 精确取值工作流

当输入是 `imd.sankuai.com` 设计稿链接时（属性能读到组件源值，判定最准）：

**1. 登录 + 打开文件 + 放大视口**（`window.mg` 需编辑器完全加载后才可用，导航后多等几秒）：

```bash
catdesk browser-action '{"action":"navigate","url":"https://imd.sankuai.com/file/<fileId>?page_id=<pageId>","waitUntil":"networkidle"}'; sleep 6
catdesk browser-action '{"action":"viewport","width":1600,"height":1000}'; sleep 4
```

**2. 定位目标节点/画板并读属性**（示例：读某节点的字号/字重/字色/底色/描边/圆角）：

```bash
catdesk browser-action '{"action":"evaluate","script":"(() => { const mg=window.mg; function hex(c){const f=x=>(\"0\"+Math.round(x*255).toString(16)).slice(-2).toUpperCase();return c?\"#\"+f(c.r)+f(c.g)+f(c.b):null;} function find(n,kw){let r=[];if((n.name||\"\").includes(kw))r.push(n);if(n.children)for(const c of n.children)r=r.concat(find(c,kw));return r;} const page=mg.document.currentPage; const hit=find(page,\"标签\")[0]; if(!hit)return \"not found\"; const ts=(hit.textStyles||[]).map(t=>({size:t.textStyle&&t.textStyle.fontSize, style:t.textStyle&&t.textStyle.fontName&&t.textStyle.fontName.style, fill:(t.fills||[]).map(p=>hex(p.color))})); const fills=(hit.fills||[]).map(p=>p.type===\"SOLID\"?hex(p.color):(p.type+\" \"+(p.gradientStops||[]).map(s=>hex(s.color)+\" \"+Math.round(s.position*100)+\"%\").join(\",\"))); return JSON.stringify({name:hit.name,type:hit.type,radius:hit.cornerRadius,textStyles:ts,fills:fills,strokeWeight:hit.strokeWeight}); })()"}'
```

> 关键点：字号是 @2x px，判定前 ÷2 换算成 @1x pt 再比对阶梯；渐变角度由 `gradientHandlePositions` 换算 CSS 度数（`atan2(dx,-dy)`），色系落在哪个语义才是判定重点，角度小幅差异属 P10 灰区。

**3. 导出高清底图佐证**（读不到属性或需目视核对时，scale=2；文字发糊多为资源未加载完，`scrollAndZoomIntoView` 定位后多等 10~15 秒重导）：

```bash
python3 <phase2-card-annotation>/scripts/imd_export_node.py "<画板id>" /tmp/scene.png 2
```

**4. 逐区看清 + 逐元素按 Step 3 比对规范。**

|------|---------|
| 用户圈出了若干元素 | 只评圈出元素，逐个出 🟢/🔴；不额外拆其他元素 |
| 用户未圈出、给整页/整卡 | 先判卡型，再拆该卡所有单一元素，逐一判合规 |
| 元素属排除项(商家图/下挂图/营销大图本体/金刚icon) | 标"非评测元素"，不判级，列入 5b |
| 商品图/下挂图上内嵌的营销文字（招牌双人餐绿底金字、下挂缩略图上的「特价团」角标/「享2.8折」/「直播特惠」/「金奖美式4选1」/「Cotti Coffee·库迪咖啡」等） | 属商家上传图片素材（随图缩放、烧录在像素里），标"非评测元素(图片内容)"，不判级，列入 5b；勿误当独立标签评规范。判据：随图缩放=图片内容(排除)，系统可配置独立渲染层=评估 |
| 卡片类型判不准（踩线卡型） | 先按最接近的画板判，结论中标注卡型假设；影响分区规则时向用户确认 |

## Gotchas（本指标最易踩的坑）

- **先定卡型再判分区。** 9 个画板分区规则不同（如价格居左/居右、标签区是否允许彩色、头图能放什么），卡型判错会把整卡规则套错。
- **"符合规范"是多维度联合判定，不是只看一处。** 一个标签色对了但放错了分区、或字号对了但字重错了，都判 🔴。任一维度不符即不达标。
- **区分"放错分区"与"样式错"。** 「优选新店」绿裸字在评分/新店区是合规的既定样式（🟢，注 P1）；是否放错分区必须由当前卡型的明确规范证明，不能因为标签不在“标签区”就推断违规。同一元素样式在不同位置的结论须以当前版本规则为准。
- **规范灰区不要误判为元素违规。** 新店绿 #00A72D 与 #00B300 跨卡差异（P2）、价格红两个近似值（P4）、绿标渐变 135°/139°/144°（P10）——这些是规范待收敛，元素判 🟢 并注明，别当元素做错扣分。
- **字号必须换算再比对。** IMD 读到的是 @2x px（如 30px），要 ÷2=15pt 再比对阶梯；直接拿 px 比 pt 会全判错。
- **标签底色比色系不比精确 RGB。** 判标签底色合规看"色相落在哪个语义（绿/黄/橙/蓝/黑金）"，渐变角度和停止位小幅差异属 P10 灰区；只有色系错位（该绿却蓝）或加了规范外描边/阴影才判 🔴。
- **商品卡标签区/套餐卡标签区有额外收敛约束。** 商品卡标签区要求去底色文字样式；套餐卡标签区仅允许灰色文字（比商家卡更严，不允许彩色高亮）。带底色/彩色即 🔴。
- **演出卡头图不放标签、价格居左。** 这是演出卡独有收敛，头图出现标签或价格居右即 🔴。
- **非阶梯字号是硬伤。** 出现 14.5px/13.9px 这类不在阶梯内的值，判 🔴（P5），并注明最近标准值。
- **看不清就放大 / 读源值。** 本指标结论完全取决于能否准确读出字号/字重/字色/底色/描边；IMD 优先 window.mg 读源值，截图务必放大，不要凭印象判。
- **只报 🔴 不给期望值等于没判。** 每个不达标必须给出"规范期望是什么、怎么改"，否则评测人员无法整改。
