# 单一元素颜色数量评测（指标 1.2.2 色彩运用有逻辑）

## 工具定位

本 Skill 服务于**评测人员**，用于评估搜索结果页/信息页中「色彩运用有逻辑」这一指标（编号 1.2.2）的**单一元素维度**。
它的能力是：帮助评测人员处理复杂的信息页面，**识别页面中的单一元素**，并对**单一元素内的颜色数量按 36 色标准进行统计**，最终给出元素级的评级结论。

评估的核心问题是：**单个 UI 元素内用了几种颜色？是否克制？** 颜色越少越克制、越有逻辑。

**与同系列 Skill 的边界（口径不同，务必区分，勿混用）：**

- 本 Skill（`single-element-color-scanner`）：**元素级**颗粒度，统计**单一元素内的有彩色数量**（底色、文字色、内部图形均扫描，黑白灰排除），阈值 ≤2 / =3 / >3。
- `color-logic-scanner`：**组件级**颗粒度，统计**有彩色系数**（黑白灰不计、同色相深浅合并为一个色系），阈值 ≤3 / 4~5 / ≥6。
- 两者均排除黑白灰，但「粒度、阈值和聚合对象」不同，不能相互套用结论。若用户明确说「1.2.2」「单一元素」「总颜色数量」「元素级」，用本 Skill。

## 前置与依赖

- **输入来源**：支持两种——(a) 用户提供**本地整页/整卡截图**（PNG/JPG，可能已用红框圈出待评元素）；(b) 用户提供 **`imd.sankuai.com` 设计稿链接**（需先按 `catdesk-browser` skill 完成内网登录态，再导出整页底图）。
- **元素归属与排除 mask 只消费对应截图的 Phase2 manifest**：头图、图文/文字下挂、营销元素、金刚图标、标签及其坐标必须来自该单图 JSON。manifest 缺失、`phase3Ready=false` 或归属不确定时回退 Phase2；禁止 AI 重新拆元素或调用历史 IMD 工具补坐标。
- **像素统计脚本**：`scripts/count_element_colors.py`（Python3 + Pillow + numpy）。对元素裁剪图按 36 色分格统计占比、感知合并深浅、可选剔除背景，输出色谱与候选评级。详见 `references/36色标准.md`。
- **辅助工具**：图片读取/放大工具（image_read）用于看清底色与字色；`phase2-card-annotation/scripts` 下的 `scan_rows.py`/`scan_textrows.py`/`scan_card_regions.py` 可用于定位元素像素坐标（裁剪框）；对彩色标签，可用「彩色标签带检测」（饱和度阈值找连通有色带）快速定位每个标签的 x/y 边界，避免反复盲裁（见下方「IMD 整页/单卡标签评测工作流」）。

## 核心概念

### 什么是「单一元素」（评估粒度）

粒度是**元素级**，不是整卡、不是整页。切分规则：

- **同一功能区内、视觉上独立的一块，算一个元素。** 例如：标题文字是一个元素、标题右侧的「外卖」标签是另一个元素、价格是一个元素、每一个独立标签各算一个元素。
- 标题文字 + 旁边的标签属于**两个元素**，分别评估，不合并。
- **若用户在截图上已用框（红框等）圈出元素，则只评估被圈出的元素**，圈几个评几个，不自行扩展。
- **若用户没有圈出元素**，则拆出页面中的所有元素（逐一识别标题、每个标签、价格、评分、提示条、按钮等），逐一评估。

### 什么颜色计入统计（计色口径）

统计对象是「单一元素中的有彩色数量」，按 36 色标准归一：

- **底色 / 背景色中的有彩色计入。** 例如「外卖」标签是黄底黑字，排除黑字后算 1 色（黄）。
- **文字中的有彩色计入。** 黑字、白字和灰字不计。
- **图形 / icon 颜色计入**（除非属于下方排除项，或面积占比 < 1%）。
- **同色格只算 1 色。** 两处颜色若按 36 色标准落在同一色格，合并计为 1 色。
- **不同有彩色格分别计。** 深棕等深色彩色仍要计；只有落入无彩色区间的黑白灰排除。
- **渐变：按其跨越的色阶（色格）数判单色或多色。** 若一块渐变底从青绿过渡到蓝，跨越了「青」和「蓝」两个色格，则该渐变底算 2 色；若始终在同一色格内深浅变化，则算 1 色。

### 排除项（不参与颜色统计）

以下元素**整体排除**，不作为被评估元素，也不贡献颜色：

- **商家图片**（商家头图、实拍图）。
- **下挂图片**（图文下挂区里的商品缩略图等）。
- **营销类元素**：营销图片、banner、腰封。**注意：标签不属于营销类元素，标签要评估。** 头图上整幅的促销大图（如“超大空间 15000m²”）属营销图片，排除；但压在头图上的独立角标/标签要评估。
- **金刚图标**（页面金刚位的独立入口 icon）。**注意：排除的只是页面金刚位图标；标签内部的小图标（如券形 icon、闪电 icon、榜单徽章、山形 icon等）不排除，其颜色计入所属标签的总颜色数（只要该颜色面积占比 > 1%）。**
- **黑、白、灰中性色**：无论出现在元素背景、文字、描边或内部图形中，均不计入最终颜色数；仅在原始色谱中保留供诊断。
- **宏观通栏组件的页面背景不属于元素**：状态栏、搜索框栏、Tab栏、快筛栏等通栏背景不进入元素裁剪。其上的黑字和灰色 icon 又属中性色，也不计；若存在选中黄、活动红等有彩色则正常计数。

以及元素内的**低占比颜色**：

- **元素内面积占比 < 1% 的颜色不计入**（避免抗锯齿、亚像素混色、极小 icon 等噪声虚增颜色数）。例如标签里一个极小的粉色闪电 icon，若面积占比 < 1% 则排除；脚本色谱里占比 ~1% 且零散分布的色格（如券 icon 边缘的“青 1%”）多为抗锯齿噪声，应排除。

> 元素归属判定可复用 `phase2-card-annotation` skill 的《页面与商卡识别规则》：它能识别并区分商家图片（头图区）、图文下挂、营销元素（营销图片/banner/腰封）、金刚图标与标签。先用它判定"哪些元素要算、哪些要排除"，再对纳入的元素做颜色统计。

## 36 色标准

「36 色标准」是本评测的颜色归一标准：所有颜色先从 RGB 转 HSV（H: 0–360°, S: 0–100, V: 0–100），
按饱和度分为无彩色与有彩色。**无彩色（黑/白/灰）仅作诊断，不计入总颜色数。**

**无彩色（S < 12）** 按明度分 5 格保留诊断：白色、浅灰、中灰、深灰、黑色；这 5 格均不计入总数。

**有彩色（S ≥ 12）** 按色相分 9 个区间，每区间按明度分深/浅两档，共 18 格；红色跨 0°/360°：

| 色相区间 | H 范围 | 深/浅 |
|---------|--------|-------|
| 红 | 0–15° / 330–360° | V>60 浅 / V≤60 深 |
| 橙 | 15–45° | 同上 |
| 黄 | 45–68° | 同上 |
| 黄绿 | 68–85° | 同上 |
| 绿 | 85–150° | 同上 |
| 青 | 150–195° | 同上 |
| 蓝 | 195–250° | 同上 |
| 紫 | 250–290° | 同上 |
| 品红 | 290–330° | 同上 |

**本指标「总颜色数量」= 元素内出现的、面积占比 ≥ 1% 的、去重后的有彩色相数量（不含无彩色格）。**
同一有彩色相的深浅变化合并为一个色系；跨色相渐变仍分别计数。

## 评估标准

对**每个元素**独立评估，看其「总颜色数量」：

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 总颜色数量 ≤ 2 | 颜色克制 |
| 🟡 达标 | 总颜色数量 = 3 | 颜色适中 |
| 🔴 不达标 | 总颜色数量 > 3 | 颜色过多 |

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 确认输入来源：若为 **IMD 链接**，走下方「IMD 整页/单卡标签评测工作流」（登录→定位画板→导出高清底图）；若为**本地截图**，直接加载。用图片读取/放大工具加载全部截图，确认尺寸与内容。**图小或看不清时必须放大再看**（本指标最易因看不清底色/字色而误判，见 Gotchas）。⭐ **若导出图文字发糊/马赛克，大概率是图片资源未加载完，应多等几秒后重新导出，并提高导出 scale（scale=2 比 scale=1 更清晰），不要在模糊图上猜色。**
2. 判断截图是否已**圈出待评元素**，以及用户是否限定了范围：
   - 已圈出 → 只评圈出的元素（记录每个框的位置与内容）。
   - 用户指定“只看某个商卡” → 只拆该商卡的元素。
   - 未圈出且未限定 → 进入 Step 2 拆分页面中的所有元素。
3. 记录场景标识（搜索词 / 页面名 / 商卡序号），便于结果表定位。

### Step 2：拆分元素并判定归属（识别单一元素）

对每张图，识别出待评估的单一元素清单。对每个候选区域做**归属判定**：

- 是否属于排除项（商家图片 / 下挂图片 / 营销图片·banner·腰封 / 金刚图标）？属于则标记「排除」，不评估。
- 是标签、标题、价格、评分、提示条、按钮等 UI 元素？则纳入评估，按「单一元素」粒度拆开（标题与相邻标签分开；每个独立标签各一条）。

**若任务是“评测所有标签”（需特别注意标签的位置）：**

- **优先评标签区的异形/异色标签**（挂在标题/基础信息旁的标签、榜单标签、优惠标签）。
- **但标签不一定在标签区：头图区的角标、图文下挂区内的标签、标题区内的标签（如标题右侧的“团购”标）也都要纳入**。逐卡逐区排查头图区/标题区/下挂区有无标签，勿只看标签区。
- **成行的文字下挂促销区（如“神券 券后¥x”“满xx减xx”“6.5折 商品名”等成行文字）属「文字下挂区」，不算标签，不评测。**

> 归属边界（榜单腰封 vs 榜单标签、图文下挂 vs 文字下挂等）可对照 `phase2-card-annotation` 的《页面与商卡识别规则》判定。遇到「必住榜」这类榜单条这种踩线情况，若用户已圈出则按纳入评估处理，并在结论中标注该归属假设。

产出一份元素清单：每条 `{元素名, 位置/框, 归属(纳入/排除), 排除原因}`。

### Step 3：对每个纳入元素做颜色统计（脚本初筛 + 人工语义终判）

**颜色统计采用「当前图重新裁剪 → 脚本输出 36 色格证据 → 人工核查裁剪与语义」三步，脚本不是全自动判分器。** 先确认当前截图/IMD 的页面版本，禁止复用历史图或 1.0 页面取色；目视直接数色格易漏底色/字色，而纯像素统计会受抗锯齿、背景混入影响，三步结合才可给出结论。

**Step 3a — 脚本初筛，拿客观色谱：**

1. 裁剪出元素区域：若用户已圈框，读框坐标；否则用 `scan_*.py` 定位或视觉估框。裁剪**尽量紧贴元素边界**，避免混入相邻元素或大片页面背景。
2. 运行 `python3 scripts/count_element_colors.py 元素.png`（圆角/非矩形元素、四角露出背景时加 `--drop-bg`）。脚本输出：细粒度 36 格色谱 + 各色占比 + 感知合并（同色相深浅并为一色）后的候选色数与评级。
3. 读脚本输出的 `colors_fine`（过阈 36 色格）和 `colors_all`（诊断色谱），将其作为**客观数量证据**；最终结论必须可追溯到当前裁剪、当前图和这些 36 色格，不能引用其他版本标签的色值或色数。

**Step 3b — 人工语义终判（脚本无法替代的判断）：**

对照色谱，按本指标口径人工确认最终「总颜色数量」：

- **深浅合并**：同一有彩色相的深浅一律合并为一个色系；人工只能剔除抗锯齿噪声或修正背景归属，不得把同色相因语义角色不同拆回多色。
- **背景归属**：确认脚本剔除的背景是否为页面背景（应剔）还是元素自身底色（不应剔）。
- **渐变色阶**：确认渐变跨越的真实色相数（如青→蓝 = 2 色），区分真实色阶与边缘抗锯齿噪声。
- **深黑字 vs 深彩字**：确认近黑字已作为中性色排除，而深棕/深红等仍有饱和度的深彩字未被误排除。
- **< 1% / 小 icon**：确认极小 icon、杂色是否已按占比排除。

把每个可见颜色逐项列出（底色 X、文字色 Y、icon Z…）再计数，得到该元素的「总颜色数量」。

> 详细阈值、脚本用法、三个标准 case 的答案与「脚本 vs 人工」边界见 `references/36色标准.md`。

**兜底：无法运行脚本时**，纯人工目视，仍须逐项列色（底色几色、每处文字什么色、有无 icon、渐变跨几色阶、有无 <1% 应排除项）后再计数，不得凭整体印象报一个数。

### Step 4：逐元素评级

对每个纳入元素，按「评估标准」表由总颜色数量得出 🟢/🟡/🔴。排除元素不评级、不计入。

### Step 5：输出结果

**5a. 问题元素明细表（颜色超标元素）：**

仅列出判定为 🟡达标 / 🔴不达标的元素（若全部 🟢优秀 则注明"无颜色超标元素"）。颜色构成必须逐项列出底色+文字色+icon，不能只报总数：

|----------|---------|---------|---------|---------|:------:|---------|---------|:----:|

**5b. 评测总览（按 Tab 维度）：**

| Tab/场景 | 元素总数 | 🟢优秀 | 🟡达标 | 🔴不达标 | 不达标率 |

**5c. 问题维度分布（按不达标原因归类）：**

**5e. 总结说明：**

在表格下方附一段文字总结，包含：整体色彩运用评价（优秀/存在问题）、超标元素的典型颜色构成、系统性问题分析（如"多个促销标签用了3种以上底色导致视觉杂乱"）、建议优先处理的元素。

### Step 6：自检

- 每个纳入元素是否都逐项列出了底色与文字色（不能只报一个总数）？
- 渐变底是否按跨越色格数计（跨 2 格必须计 2 色）？
- 是否有 <1% 的小色块被误计入？是否有排除项被误当元素评了？

## IMD 整页 / 单卡标签评测工作流

当输入是 `imd.sankuai.com` 设计稿链接、要求逐标签评测时，按此流程（命令在 `phase2-card-annotation/scripts/` 下执行）：

**1. 登录 + 打开文件 + 放大视口**（`window.mg` 需编辑器完全加载后才可用，导航后多等几秒）：

```bash
catdesk browser-action '{"action":"navigate","url":"https://imd.sankuai.com/file/<fileId>?page_id=<pageId>","waitUntil":"networkidle"}'; sleep 6
catdesk browser-action '{"action":"viewport","width":1600,"height":1000}'; sleep 4
```

**2. 定位目标画板拿 id + 偏移**（画板命名 `{场景名}_全部_{1|2|3}`）：

```bash
python3 imd_eval.py eval '(() => { const doc=window.mg.document; const page=doc.currentPage||doc.children[0]; return JSON.stringify(page.children.filter(n=>/关键词/.test(n.name||"")).map(n=>({id:n.id,name:n.name,x:Math.round(n.x),y:Math.round(n.y),w:Math.round(n.width),h:Math.round(n.height)}))); })()'
```

**3. 导出高清底图**（⭐ 用 scale=2；若文字发糊说明资源未加载完，`scrollAndZoomIntoView` 定位后多等 10~15 秒再重导）：

```bash
python3 imd_export_node.py "<画板id>" /tmp/scene.png 2
```

**4. 逐区看清并识别标签**：把整页按快筛区/各商卡分区裁剪放大（`image_read`），列出全部标签及其所在区域（含头图角标、标题区标签、下挂区标签）。

**5. 定位每个标签的裁剪坐标**——不要反复盲裁，用「彩色标签带检测」快速定位：对某区域按饱和度阈值（如 S>0.25 且非极暗）找连通的有色像素带，输出每条带的 `y` 区间与 `x` 范围，即为彩色标签的候选框；灰底标签则用 `scan_textrows.py` 或视觉定位。避免把头图彩色区误当标签带（可限定在文字区 `x>头图右边界` 内检测）。

**6. 逐标签裁剪 + 跑脚本 + 人工终判**：对每个标签裁剪后跑 `count_element_colors.py`（圆角标签加 `--drop-bg`），按 Step 3b 做语义终判。简单灰底 2 色标签可直接目视。颜色可能 ≥3 的标签（券icon标、榜单标、撞色标）必须跑脚本留占比证据。

**7. 汇总**：按 Step 5 输出「元素级明细表 + 排除清单 + 评级分布与结论」。整页评测时按快筛区/商卡 1/2/3/4 分组列表。

> 坐标定位是 IMD 评测最耗时的环节（导出图无节点级坐标）。优先用彩色标签带检测/分区扫描拿坐标，其次再视觉估裁；每次裁完务必 `image_read` 核对是否精确框住目标标签，裁偏了重定位，不要在裁偏的图上跑脚本下结论。

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 用户圈出了若干元素 | 只评圈出元素，逐个出结论；不额外拆其他元素 |
| 用户未圈出元素、给整页/整卡 | 拆出页面中所有 UI 元素（标题/各标签/价格/评分/提示条/按钮…），逐一评估 |
| 元素属于排除项（商家图/下挂图/营销图·banner·腰封/金刚icon） | 标「排除」，不评级，列入 5b 排除清单 |
| 榜单腰封（如"必住榜"）踩线，既像标签又像营销腰封 | 若用户已圈出→按标签纳入评估并注明假设；未圈且不确定→向用户确认归属 |
| 元素含渐变底 | 按渐变跨越的 36 色格数计色（同格深浅=1色；跨格=多色）；像素统计天然处理 |
| 元素含极小 icon（如小闪电） | 计算其面积占比，< 1% 则排除，否则计入其色格 |
| 元素只有底色无文字 / 只有文字无底色 | 有几个占比≥1%的色格就算几色，规则不变 |
| 元素文字含多种颜色（如价格红字+旁灰字同属一个价格元素） | 各颜色分别归色格去重后计入该元素总数 |
| 标签内含卡券/icon 图形（如"团购"券 icon） | icon 各有彩色若占比 ≥1% 计入该标签总数；例如橙券 icon+黄底+白字+红描边，排除白字后为橙/黄/红 3 个色系 🟡 |
| 标签不在标签区（头图角标、标题区标签、下挂区标签） | 仍纳入评估；靠分区图目视或彩色带检测定位后逐个评 |
| 成行文字下挂促销区（"神券 券后¥x""满xx减xx"等纯文字促销行） | 属文字下挂区，非"标签"，本次评测不评 |
| "神券"红→品红渐变字 | 按用户口径不算跨色阶多色，计单色 |
| 同色阶红框 + 红字（如"4.4折"红框标） | 边框与文字同色阶归一；白底+红 = 2 色 🟢 |
| 深黑字与深棕字并存 | 深黑字排除；深棕字若 S≥12 则按橙/棕色系计入 |
| 白底黑字纯文字元素 | 黑、白均排除，有彩色数为 0 → 🟢 |
| 图片看不清底色/字色 | 先放大（image_read/放大工具）再判定，切勿在低清晰度下猜色 |
| 多张截图 / 多场景 | 每张逐元素评估，最后统一汇总明细表与评级分布 |
| 无法运行像素脚本 | 走 Step 3 兜底人工目视，但必须逐项列色后再计数 |

## Gotchas（本指标最易踩的坑，均来自实测教训）

- **有彩底色一定要算。** 「外卖」黄底黑字排除黑字后仍有 1 个黄色系；不能因文字是中性色就把整个元素排除。
- **有彩文字一定要算。** 红字、棕字、渐变文字都按色相计入；黑白灰不计。
- **深色文字要区分饱和度。** 近黑文字排除，深棕/深红文字仍属有彩色，要保留对应色系。
- **渐变底按跨越的色相数计色。** 「NEW 闪电新品」的青绿→蓝渐变跨青、蓝两个色相，加黄底共 3 个有彩色系 → 🟡；黑字排除。
- **无彩色（黑/白/灰）始终排除。** 它们可保留在原始色谱中协助核对裁剪，但不得进入 `color_count`或人工终判色数。
- **同一有彩色相的深浅合并。** 深红、浅红均归为红色系；青→蓝这类跨色相渐变仍分别计数。
- **<1% 面积的颜色要排除。** 极小 icon、渲染杂色不计入，否则颜色数虚高。但阈值就是 1%，不要随意抬高而漏掉有意使用的小面积强调色。
- **元素粒度别切错。** 标题和它旁边的标签是两个元素，分开评；每个独立标签各算一个元素，不要把一排标签当成一个元素统计。
- **看不清就放大。** 本指标结论完全取决于能否准确辨色，低清晰度下目视极不可靠；先放大图片，能量化就用像素统计，不要凭印象报数。
- **先重读当前图，再做 36 色像素统计。** 人工数色格在深浅相近、渐变、低占比场景下稳定性差；必须对当前输入图重新裁剪并以 HSV 36 色格 + 1% 过滤取得可复现证据，禁止把 1.0 或历史批次标签样式、色值、结论带入 2.0 页面。
- **标签内的卡券/icon 有彩色要算。** 例如米黄底 + 深灰字 + 橙色券 icon + 白字 + 红描边，排除深灰和白字后为黄/橙/红 3 个色系 🟡。不要把 icon 当装饰忽略；但 <1% 的抗锯齿杂色仍要剔除。
- **"评测所有标签"不等于"只看标签区"。** 标签也会出现在头图角标、标题区、图片下挂区；务必对照分区图逐区排查，别漏了头图上的角标。反之，成行的纯文字促销下挂（神券/满减）属文字下挂区，不算标签，不要误评。
- **通栏组件的黑白灰不计。** 通栏页面背景本就不属于单一元素；其上的黑字和灰色 icon 又属中性色，也排除。只统计选中黄、活动红等有彩色。
- **IMD 导出发糊多半是资源没加载完。** 不是清晰度上限问题——`scrollAndZoomIntoView` 定位后多等 10~15 秒再 `imd_export_node.py`，并用 scale=2 导出，文字才清晰可辨色。scale=1 偶发导出损坏，可用 scale=2 图并把坐标 ×2。
- **裁偏了就重定位，别在错图上下结论。** IMD 导出图无节点级坐标，靠估裁极易裁到相邻元素/背景。每次裁完先 image_read 核对框住的就是目标标签，再跑脚本；优先用彩色标签带检测拿坐标而非反复盲裁。
