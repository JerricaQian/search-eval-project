# 单一元素评测

本目录的 4 项 Skill 逐个评 Phase2 已确认的最小 UI 元素，不自行拆分、合并元素，也不把组件或页面问题降到元素级。每项均按“评审对象与共同契约 → Phase2 事实/测量门槛 → 专属判定标准 → 评分与聚合 → 固定流程 → 输出与反误判 → Gotchas”执行。

## Skill 清单

| Skill | 只评什么 | 评级与 Tab 分数 |
|---|---|---|
| `eval-1` 供给呈现质量 | 当前只评文字的完整、准确、用户视角表达与相关性；图片质量暂缓 | 优秀 `0` / 不达标 `-2`，取最差元素 |
| `eval-2` 色彩运用有逻辑 | 一个元素按红橙黄绿青蓝紫七色统计的有效 UI 色数 | 优秀 `1` / 达标 `0` / 不达标 `-1`，取最差元素 |
| `eval-3` 静态元素不复杂 | 圆角、描边、阴影、颜色、字体、字号等是否符合对应规范 | 优秀 `1` / 不达标 `-1`，取最差元素 |
| `eval-4` 信息与功能真实无歧义 | 单个元素自身是否表意唯一、无可见虚假、夸大或诱导 | 优秀 `0` / 不达标 `-2`，取最差元素 |

## 阅读顺序

1. 依据任务选择上表中对应的一个或多个 Skill；不要因为同属单一元素维度就跳读目标 Skill。
2. 先读 `单一元素评测通用契约.md` 与当前截图的 Phase2 原子事实。
3. 再完整读取目标 `eval-*/SKILL.md`，按其专属门槛、测量、阈值、评分和 Gotchas 执行。`eval-2` 先用 JSON 样式色值筛出非中性色元素，只对这些候选运行 `scripts/count_element_colors.py`；`eval-3` 还读取规范速查和样式字典。
