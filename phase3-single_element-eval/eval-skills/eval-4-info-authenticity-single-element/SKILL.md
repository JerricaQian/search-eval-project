## 评审对象与共同契约

遵循 [[单一元素评测通用契约]]（`phase3-single_element-eval/单一元素评测通用契约.md`）。逐个评文案、标签、价格区或独立图标自身；多元素组合后的冲突交给组件“信息真实性”。问题卡只写可见的元素原文、歧义/误导事实、评级与用户影响。

## Phase2 事实门槛

- 元文案、语义角色、价格/促销归属、图标是否有文字伴随只读 `textFacts`、`visual`、`relations`；未确认文本、图标归属或优惠条件不能补判。
- 图标与明确文字共同表达同一含义时按一个元素处理；价格区的划线价、现价、会员价是同一价格表达，独立促销标签另评。
- **评审集：**只纳入信息性文本、标签、价格区、独立图标、按钮和提示条；照片本身不在本项，图片与标题冲突交组件信息真实性。
- **外部事实隔离：**下单后价格、活动是否长期存在、优惠券能否领取和市场价高低都不是当前截图可证实事实；只能标“需外部核验”，不能写不达标。

## 判定标准

仅两档：有确认的歧义或可见误导即“不达标”，否则“优秀”。

| 类型 | 不达标的可见条件 | 不应误判 |
|---|---|---|
| 表意 | 文案含义模糊或有两种合理理解（如“礼赠好物”无法判断是有赠品还是适合送礼）；无文字消歧的图标有多重常见含义（如爱心可表示收藏或点赞）；折扣、优惠或条件无法理解实际含义 | 上下文唯一明确的常规品类、履约、评分、距离、榜单和促销标签；有文字说明的图标 |
| 虚假/误导 | 当前画面能够证明的信息或功能与可见事实不符、夸大；与商品无关的引流/关键词堆砌；具有作弊、规避或强诱导性质的标题；当前画面已可证明的价格或优惠条件误导 | 需要下单、历史活动、实际功能执行或外部市场数据才能证实的虚假、伪限时、实际支付差异；这些只能标注需外部核验 |

正常末尾省略、已说明面额/类型/时效的券信息、可见优惠券支持的券后价、清晰的评分销量和配送信息均为优秀。

### 判定拆解

1. **表意唯一性：**检查一条文案是否存在两种合理解读，图标是否有文字消歧，折扣/优惠是否能判断已折还是再折、适用对象和条件。
2. **截图内虚假/误导：**只识别当前画面已经证明的虚假、夸大、作弊诱导、关键词堆砌、价格/优惠条件遗漏；“可能不真实”不是问题证据。
3. **平台语境白名单：**常规评分、销量、距离、履约、榜单、明确促销和已说明券条件按美团活跃用户的正常理解处理，不做过度解读。

## 评分与聚合

- 每个元素只有优秀/不达标；一个元素同时有歧义和可见误导仍只算一个不达标元素，但两类原因都要留档。
- 按 frontmatter 取 Tab 最差元素；最终 `weightedScore` 是优秀 `0` 或不达标 `-2`，不随问题元素数累加。

## 固定评审流程

1. **枚举：**从 Phase2 清单选择信息性元素，确认原文、角色、是否有辅助文字，以及价格区/促销标签的独立边界。
2. **歧义检查：**先写出可能的两种合理理解；若在当前上下文中只能成立一种，记录为优秀而非凭关键词判问题。
3. **误导检查：**只写当前截图可证明的诱导或条件遗漏；需要跨页、跨时或外部价格才能验证的内容移入“外部核验”。
4. **汇总：**分别统计歧义和可见误导，逐元素产出证据行后按最差元素写 Tab 评级和分数。

## 输出与反误判

- 固定字段：`elementId`、`componentId`、`elementType`、`elementText`、`issueType`、`rating`、`finding`、`observableFact`。
- 不达标必须写清至少两种合理解读，或写明截图内的矛盾/遗漏条件；“可能不真实”不是证据。
- 不得将搜索词相关性、图片质量或元素间冲突重复记入本项。

## Gotchas

- “享 X 折”“省 X 元”是高频歧义区；“立减 X”在条件明确时通常不是歧义。
- 有“收藏”“闪送”等明确文字的图标已消歧；不能把图标和文字拆开重复定罪。
- 券后价在页面已列出对应优惠券时是透明表达；标题图文冲突属于组件项，不应重复记到这里。
