# 单一元素评测通用契约

本文件是 `phase3-single_element-eval/eval-skills/` 下 4 个 eval skill 的共享契约来源，经逐字比对确认：除下方标记的「技能专属」行外，其余文字在 4 个 SKILL.md 中完全一致。新增/修改本维度 eval skill 时，通用部分改这里，技能专属部分改各自 SKILL.md。

## 三档解释与证据展示契约

### 问题解释统一契约（必填，4 个 skill 逐字相同）

- 文案引用具体对象时：标准商卡用「商卡N」，N 为该卡在**标准商卡序列**中的出现顺序（不含异构模块，与内部 `id`/`listPosition` 无关，需重新计数）；异构模块用其描述性类型名称（如「运营聚合卡」），仅当同页面同类型异构模块出现多次时才加独立序号区分（如「运营聚合卡1」「运营聚合卡2」），该序号与商卡序号完全独立计数。禁止出现内部 ID、字段名或脚本文件名，完整黑名单见 `scripts/forbidden_copy_terms.json`。
- 每条 `issues` 中评级为"达标"或"不达标"的记录都必须含非空 `finding` 对象：`observableFact` 记录当前元素的位置、原文、样式或可见状态等客观事实；`ruleOrThreshold` 记录本 Skill 命中的规则、阈值或比较基线；`verdictReason` 解释事实与规则如何导出本次评级；`userImpact` 写对扫读、比较、理解或决策的直接影响。
- `description` 仅是与 `finding` 一致的一句话摘要，不得用"信息不清晰""体验较差""建议优化"等笼统措辞替代结构化字段。`priorityReason` 必须基于影响范围、关键任务阻塞程度和可见频次；依据不足时填"待人工确认"，不得虚构。
- 每个待优化 issue 必须有独立且非空的 `recommendation`：基于本 issue 的 `elementId`、原文、坐标、可见状态或测量值，说明调整对象、具体动作和验收结果；不同 issue 禁止复用同一句建议。`finding` 四字段末尾不写标点，由报告层统一拼接为事实→依据→影响。
- `finding` 不可替代该 Skill 已要求的原始清单定位、裁剪/扫描产物或专属判定依据；统一四字段与这些证据必须同时保留。

### 简洁问题卡输出与示例（强制）

**【技能专属，SKILL.md 自行定义，不在本文件覆盖范围内】**
- `observableFact` 书写要求一句（说明本 Skill 该字段该写清什么）+ 示例输出一句（一条完整问题卡文案示例）。

**以下 4 条 4 个 skill 逐字相同：**

- 每个 Tab 的优秀、达标、不达标结论都必须输出非空 `reason`（评级与可见事实）、`details.criterion`（命中规则/阈值）和 `details.summary`（覆盖范围及正向/负向证据）；优秀不得只写"无问题"。
- 仅当 Tab 评级为达标或不达标时，才必须记录对应问题/待优化对象的 `assessmentRows`（元素 ID、适用检查项、可见事实、命中规则、评级）；优秀不要求保留 `assessmentRows`。
- `details.evidenceMode`：有可定位问题为 `annotated-region`；兼有局部与整体/关系结论为 `hybrid`；无唯一坐标的整体/关系结论为 `original-page`。`details.screenshot` 必须指向存在的原图。
- 优秀只在评测详情保留 `reason`、`criterion` 和 `summary` 解释，不得进入发现问题/治理项；达标、不达标才进入待优化项。

## 统一输入与执行契约

**以下 4 条 4 个 skill 逐字相同：**

- Phase2 清单中的每个最小独立元素是唯一评测原子；禁止合并、重拆，或将同一行多个独立标签、价格、评分字段视为一个元素。
- 必须完整阅读当前 Skill 的全部标准，并且仅按本 Skill 定义的对象、排除项、阈值和 `aggregate` 评分；不得迁移其他 Skill 的标准。
- 单一元素 Skill 必须逐元素执行自身规则；组件 Skill 必须逐组件执行自身规则；`overview.total` 始终以清单确定性计数。
- `issues` 必须引用当前清单中真实的 `elementId`、`coord`、`content`。

**【技能专属，SKILL.md 自行定义】**
- "Phase2 事实优先"一句，点名本 Skill 依赖的具体 Phase2 字段。
- 如需确定性测量脚本（如 eval-2-color-logic-single-element 的 `scripts/count_element_colors.py`），额外补一条"确定性测量优先"说明。

## 校验口径参考

机器可验证的部分由 `scripts/validate_eval_results.py` 统一实现（`require_structured_finding`、`require_no_forbidden_terms`、`require_recommendation_matches_threshold` 等），本文件是给 Skill 作者和评测 agent 看的契约文本，不是校验脚本本身。
