## 三档解释与证据展示契约

### 简洁问题卡输出与示例（强制）

- 【技能专属】`observableFact` 必须写清相邻分区及缺失的物理、空间或视觉边界。
- 【技能专属】示例输出：`C1 的基础信息区与价格权益区之间没有分隔线、背景差异或足够留白，评级为不达标。用户难以快速判断价格权益从何处开始。`

- 每个 Tab 必须输出覆盖全部评估组件的 `assessmentRows`（技能专属覆盖模式：达标/不达标才需要）；每行除既定字段外必须写出该组件的可见事实、命中规则和评级解释。

## 信息分区合理性评测

## 适用场景

帮助评测人员处理复杂信息页面（如美团搜索结果截图），完成一件事：

- 识别页面中每个**组件**内部的**信息/功能分区**是否**边界清晰**，按组件颗粒度统计"分区边界不清晰"问题项数量，并按搜索词输出评估结论。

> **组件**：页面中可独立识别的功能模块，如商卡（每张门店/套餐/商品卡片）、图筛（图片筛选区）、筛选项条、列表区头部等。
> **分区**：组件内部按信息/功能划分的子区域，如商卡内的"图区 / 门店信息区 / 价格区 / 营销标签区 / 评分销量区"。

## 判断标准（核心）

**分区问题数量 = 组件内信息/功能分区边界不清晰问题项数量总和**

**评级（按 N，两档）**：

| 评级 | 条件 | 含义 |
|---|---|---|
| 🟢 优秀 | N = 0 | 无组件内分区边界不清晰问题 |
| 🔴 不达标 | N ≥ 1 | 存在组件内分区边界不清晰问题 |

> 本评级只有「优秀 / 不达标」两档，无中间档。N 为所评层面（组件 / 页面 / Tab）的分区边界不清晰问题项数量；任一处不清晰即判不达标。

**分区边界三类**（命中"边界不清晰"即计 1 项）：

| 边界类型 | 判断要点 |
|---|---|
| 物理边界 | 分割线、描边、卡片容器。相邻分区若**应有而无**物理分隔（如两张商卡无描边/无卡片容器、列表项间无分割线），导致分区粘连 |
| 空间边界 | 间距、留白。要求**相邻区域间距明显大于区域内部间距**（内紧外松）；若相邻分区间距与区域内部间距接近，未形成空间区隔 |
| 视觉边界 | 背景色差异、色块区隔，或稳定的前景文字颜色/强调层级差异。相邻分区即使同为白底，若一行以黑色主体信息呈现、下一行以灰色辅助信息呈现，也已形成可感知的视觉层级；只有背景和前景层级均无差异时才可说无视觉边界 |

> **三类边界是"或"关系**：相邻分区只要通过其中任一类边界能清晰区分，即边界清晰、不计问题；只有当**三类边界都失效**（无物理分隔 + 空间间距不足 + 无视觉差异）时，才计 1 项"边界不清晰"。

## 不可违反的铁律

1. **只做页面内判断，不跨 Tab 比较**：每张截图（每个 Tab，如全部/外卖/团购）独立评测，禁止跨页面/跨 Tab 对比分区好坏。
2. **组件级定位**：每个问题必须指明是**哪个组件**（如"商卡1中""图筛中""商卡3中"），不能只说"页面存在 N 处"。
3. **只计边界不清晰，不计正常留白**：组件内子区域之间**正常的版式留白、字号差异、字段间距**不算边界问题；只有当相邻分区三类边界都失效时才计。严禁把"子区域之间正常的留白差异"夸大成"边界不清晰"。
4. **不发散、不臆造**：严格按三类边界标准逐条核对，标准未涵盖的现象不计入；看不清的文字/样式不得臆造；**没有问题就如实记 0**，不要为了显得"全面"而虚报问题。
5. **范围限于组件内**：边界判断只针对**单个组件内部相邻分区之间**（如"商卡1中"的图区与信息区、"图筛中"的筛选项组之间）。**组件与组件之间的边界**（商卡之间、图筛与列表之间、列表与底部导航之间）**不计入本指标**，仅可作为整体观感在结论中描述，不计数。
6. **基于可见内容**：所有判断必须落在截图中能看到的边界表现上；看不清的按可观察的样式/位置描述并注明局限。

## 评测步骤

### 第 0 步：准备与读图

- 一个搜索词通常对应多张截图（按 Tab：全部/外卖/团购…）。
- **逐张读取**截图（一次一张），避免一次性传入多图+大段文字导致图片加载失败。
- 若收到"当前模型不支持图片识别"之类提示，通常是加载失败而非能力限制，重新单张读取即可。

### 第 1 步：识别并编号组件

对每张截图，按从上到下、从左到右的视觉顺序识别组件并编号：

- **图筛区**：页面顶部的图片/筛选项条，记为"图筛"（单条记"图筛中"，多条可记"图筛1""图筛2"）。
- **商卡**：每张独立的门店/套餐/商品结果卡片，按屏+序编号。
  - 单屏页面：商卡1、商卡2、商卡3…
  - 多屏页面（可滚动/长截图）：第一屏商卡1、第一屏商卡2… 第二屏商卡1…；结论中定位写作"商卡1中""商卡2中…"。
- **其他组件**：筛选项条、列表区头部、底部导航等，按需识别命名。
- 记录总屏数与各组件数量，用于结论描述（如"三屏共 9 张商卡 + 1 个图筛"）。

### 第 2 步：划定组件内分区

对每个组件，识别其内部的信息/功能分区。以商卡为例，常见分区：

- 图区（商品/门店图片）
- 门店信息区（名称、地址、距离）
- 评价/销量区（评分、评分人数、月售）
- 价格区（现价、原价/划线价）
- 营销标签区（当地人推荐、榜单标签、活动标）

> 分区按"可见的信息/功能块"划分，不要求每个分区都齐全；某分区缺失则不参与判断。
>
> **组件全域核查铁律：**以整张商卡可见边界识别相邻分区，头图、标题/基础信息、标签/价格及文字或图文下挂都在范围内；Phase2 分区框用于辅助定位，不能只检查已标为「标签区」的边界，也不能将跨屏续接下挂错误地作为独立组件。

### 第 3 步：逐组件核查边界清晰度

对每个组件，检查其**相邻分区之间**的边界是否清晰，按三类边界逐一核对：

1. **物理边界**：相邻分区之间是否有分割线 / 描边 / 卡片容器等物理分隔？
2. **空间边界**：相邻分区间距是否**明显大于**区域内部字段间距（是否形成"内紧外松"）？
3. **视觉边界**：相邻分区是否有背景色差异、色块区隔，或稳定的前景文字颜色/强调层级差异？例如黑色商家名与灰色履约信息即使白底相同，也应视为视觉层级清晰。

判定：

- 三类边界中**任一类有效** → 该相邻分区边界清晰，**不计**问题。
- 三类边界**都失效** → 该相邻分区边界不清晰，**计 1 项**。

> 关键：只在"相邻分区"层面判断，不在单个分区内部再细分子区域去挑留白。组件内子区域之间正常的留白差异不算边界问题。

### 第 4 步：计数（组件颗粒度）

每个组件单独统计：

```
组件分区问题数量 = 该组件内"三类边界都失效"的相邻分区对数
页面分区问题数量 = 该页面所有组件分区问题数量之和
```

- 同一对相邻分区只计 1 次（不按三类边界分别累加）。
- 一个组件内可能有多对相邻分区都不清晰，则累加；也可能为 0。
- **只统计组件内**，组件间边界不计（见铁律 5）。
- **宁可少报、不可虚报**：当某对相邻分区乍一眼能清晰区分时，即使留白不算大，只要三类边界有一类生效，就不计。

### 第 5 步：按搜索词输出结论

对每个搜索词，按 Tab 逐个输出"评估结论"块（含**组件级明细表**），再加一张**页面汇总表**。

**结论块结构**：

```
评估结论
分区问题数量 = X

搜索词「<搜索词>」<Tab>Tab<共N屏，含M张商卡+图筛等组件>中发现 X 项组件内分区边界不清晰：
<逐条：组件定位（如"商卡1中"）的 <相邻分区A> 与 <相邻分区B> 之间，物理边界缺失 / 空间间距未明显大于内部间距 / 视觉无背景差异，边界不清晰>；
其余组件分区边界清晰，整体评级 <🟢 优秀（X=0）/ 🔴 不达标（X≥1）>。
```

- X = 0 时，说明"图筛、各商卡组件内分区边界清晰（物理/空间/视觉三类边界至少一类生效），无分区边界不清晰问题，评级 🟢 优秀"。
- 每个问题点必须带组件定位。

**组件级明细表**（每个 Tab 一张，按组件颗粒度统计）：

| 组件 | 分区问题数量 | 评级 | 说明 |
|---|---|---|---|
| 图筛中 | 0 | 🟢 优秀 | 筛选项成组，组内边界清晰 |
| 商卡1中 | 0 | 🟢 优秀 | 描边容器+图文分栏，边界清晰 |
| 商卡2中 | 0 | 🟢 优秀 | 同上 |
| 商卡3中 | 0 | 🟢 优秀 | 同上 |

**页面汇总表**（每个搜索词一张）：

| 页面 | 分区问题数量 | 评级 |
|---|---|---|
| 全部 | 0 | 🟢 优秀 |
| 外卖 | 0 | 🟢 优秀 |
| 团购 | 0 | 🟢 优秀 |

## 常见边界与分支

- **整页乍一眼清晰**：若页面整体分区清晰、无明显边界混淆，如实记 0，不要为"显得全面"而强行凑问题。这是本评测最常见的正确结论。
- **单组件页面 / 组件内只有一个分区**：无相邻分区可判断，该组件计 0。
- **商卡有描边容器**：卡片描边本身即物理边界生效，卡内各分区只要再有任一类边界（间距或背景）辅助，即视为清晰，一般计 0。
- **组件间边界不计入**：商卡之间、图筛与列表之间、列表与底部导航之间的边界属于组件间边界，**不计入本指标**（见铁律 5）；可在结论中作为整体观感描述，但不计数。
- **分区缺失**：某组件本应有某分区但未展示（如商卡无价格区），不参与边界判断，不计问题。
- **多 Tab 截图**：每个 Tab 独立走第 1–5 步，互不引用。
- **看不清具体边界**：按可观察的样式/位置描述（如"商卡2与商卡3之间未见分割线且间距与卡内接近"），不得臆造；必要时注明"边界不清，按可见样式判断"。
- **空结果页（无组件）**：无分区可判断，计 0；结论注明"无搜索结果，无法判断分区"。

## 示例（精简）

搜索词「万象城」三个 Tab（全部/外卖/团购），各含 1 个图筛 + 3 张商卡。判断范围限于**组件内**：

- **全部 Tab**：图筛中——筛选项成组、组内间距一致，边界清晰；各商卡中——描边容器（物理边界生效），卡内图区与信息区左右分栏、信息区与价格区有间距区隔（空间边界生效）。三类边界至少一类生效 → 各组件分区问题数量 = 0。
- **外卖 Tab**：各商卡中——描边容器清晰，配送信息区与门店信息区有明确间距（空间边界生效） → 分区问题数量 = 0。
- **团购 Tab**：各商卡中——描边容器清晰，套餐图区与文案/价格区左右分栏，价格区与销量区有间距区隔 → 分区问题数量 = 0。
