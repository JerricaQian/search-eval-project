## 三档解释与证据展示契约

问题解释统一契约（必填）通用条款见 [[组件卡片评测通用契约]]（`phase3-card_or_component-eval/组件卡片评测通用契约.md`），本 Skill 不重复列出。

### 静态元素复杂度问题文案口径（强制，技能专属，不套用通用简洁问题卡两句式写法）

- 每条 issue 的四段式文案均以同一组件的 `assessmentRows` 为唯一来源；`elementId` 只用于定位其中一个触发对象，不能把图标、标签或整卡混为不同的统计口径。
- `finding.observableFact` 必须先列出纳入计数的实际中文对象，再分别给出 `N` 种异形异色标签、`M` 种独立图标样式；仅有图标、仅有标签时也必须显式写另一类为 0 种。禁止只描述“3 种图标”而不说明该组件的完整标签/icon统计范围。
- `finding.ruleOrThreshold` 固定完整表达为：`组件内异形异色标签≤2种且独立图标≤1种为优秀；标签3–4种或图标2–3种为达标；标签≥5种或图标≥4种为不达标`。不得只截取命中的单条阈值。
- `finding.verdictReason` 固定表达为：`标签 N 种、图标 M 种，<触发达标/不达标的具体条件>；因此评级为<评级>`。不得重复罗列 `styleKey` 五要素，也不得以“达到阈值，结论为达标”替代完整计数回指。
- `finding.userImpact` 必须说明实际纳入标签/icon如何与标题、价格、履约或权益信息竞争注意力；不得把所有对象泛称为“图形对象”。
- 问题卡简洁展示示例：`C1存在「闪购」履约标、棕色「赠手套」、绿色「时令」、价格旁「神价」、「安心闪购 坏必赔」、「神券 立减5」，共6种异形异色标签；另有1种闪电履约图标，评级为不达标。多类履约、赠品、促销和保障标签同时竞争注意力，分散商品标题与价格的焦点。`

- 每个 Tab 的优秀、达标、不达标均须输出非空 `reason`（评级与可见事实）、`details.criterion`（命中规则/阈值）、`details.summary`（范围及正向/负向证据）；优秀不得只写“无问题”。（Tab 级 reason/criterion/summary 要求为 8 个 skill 逐字相同条款，详见共享契约）
- 每个 Tab 必须输出覆盖全部评估组件的 `assessmentRows`（技能专属覆盖模式：覆盖全部评估组件）；每行除既定字段外必须写出该组件的可见事实、命中规则和评级解释。
- `details.evidenceMode`、优秀排除规则同 8 个 skill 逐字相同条款，详见 [[组件卡片评测通用契约]]。

## 统一输入与执行契约

通用条款（Phase2 清单原子性、完整阅读标准、`issues` 引用真实 ID）见 [[组件卡片评测通用契约]]（`phase3-card_or_component-eval/组件卡片评测通用契约.md`）。以下为本 Skill 专属内容：

- 组件 Skill 必须逐组件执行自身规则；`overview.total` 必须等于实际评估**组件数**，Phase2 清单总数仅写入 `evidence.sourceManifestTotal` 作追溯，绝不得作为组件数。
- **结果证据门槛：**每个评估组件必须有一条 `assessmentRows` 记录，列出六分区扫描范围、纳入/排除的标签与 icon、可复查的 `styleKey`、去重后的标签/icon 样式数和评级；每行还必须含 `measurement.tool`、`measurement.artifactPath`、`measurement.parameters`。`evidence.evaluatedUnitCount` 必须等于行数且与 `overview.total` 一致；优秀结论同样必须保留这些可复核证据。
- **Phase2 属性优先：**完整可评组件必须具备 `visualInventory.complete=true`，且每个可见分区均有扫描记录；Phase3 只能以其中 `visualStatus=confirmed` 的 `entityKind`、`styleKey`、`sourceRegion` 为唯一计数输入，按当前组件去重后确定性评级。每个已确认 tag/icon 均必须同时存在于所属分区库存；不得重新按标签区猜测、不得漏掉头图/标题/下挂中的已登记标签。库存缺失、不完整或相关属性为 `uncertain` 时，必须发起 Phase2 回退复核；回退前不得把未确认项当作 0，也不得因此输出优秀。
- **确定性测量优先：**当本项目可运行 `<projectDir>/scripts/extract_component_metrics.py` 时，必须优先执行并在 `assessmentRows` 保留扫描分区、纳入/排除实体、`styleKey`、标签/icon 去重计数、输入组件范围和测量产物路径。Phase2 `visualInventory` 是实体与样式事实源，测量脚本用于复核可见样式/图标；LLM 只能解释不确定实体或脚本未覆盖的语义，绝不得目视改写已确认 `styleKey` 去重计数及其阈值评级。脚本不可用或发现事实冲突时，记录原因并回退 Phase2 复核，不得自行补零或伪造测量结果。

## 工具定位

本 Skill 用于评测搜索结果页截图中静态元素的复杂程度。对页面内的图筛组件和每张商卡组件逐一扫描，识别其中的异形/异色标签样式和icon样式，按组件颗粒度统计数量并给出评级结论。适用于单Tab评测、多Tab横向对比、多屏纵向合并等场景。

> **组件全域扫描铁律：**计数范围是整张商卡的可见边界，不是 Phase2 标注中的「标签区」。Phase2 的标签区仅用于定位一类独立标签行；标题区、头图区叠加角标、基础信息区、价格区、商家区、文字下挂区和图文下挂区内只要出现异形/异色标签或独立 icon，均必须纳入该商卡统计。不得因为元素被标注在非标签区而漏计。

## 核心概念

### 异形/异色标签

**定义：** 非纯文本、带有图形辅助表达（异形）或使用了非中性色（异色）的标签样式。

**判断标准：**

1. **异形**：标签带有图形元素辅助表达，如闪电图标、奖杯图标、特殊形状底框、角标贴片等，不是简单的文字排列。
2. **异色**：标签使用了非中性色（非黑/白/灰），如红色、橙色、绿色、蓝色、紫色等彩色底色、彩色边框或彩色文字。
3. 满足异形**或**异色任一条件即计入。

**算"异形/异色标签"的典型样式：**
- 红色/橙色底白字促销标签（如「神券」「冰爽价」「限时秒杀」）
- 彩色边框文字标签（如橙色边框「赠叉子」、绿色「时令」）
- 带图形辅助的标签（如闪电+「闪购」、奖杯+「榴莲榜第1名」）
- 蓝色品质标签（如「自营」）
- 绿色保障标签（如「安心闪购 坏必赔」）
- 商卡左上角的彩色活动价格角标/贴片（如橙底白字¥33.8）
- 红底折扣标签（如「X折」）
- 彩色活动标签（如「毕业季」绿色标签）

**不算"异形/异色标签"的情况：**
- 纯文本中性色（黑/灰/白）文字，无底色无边框（如商品名、店铺名、评分文字、月售量、距离、配送费等基础信息文字）
- **灰/黑/白单色的普通文字标签**：即使文案含有「公益」「保障」「活动」等业务词，只要视觉上为中性色、无彩色底/边框，且没有图形辅助或特殊贴片轮廓，就不属于异形/异色标签；例如灰色「青山公益商家」不得因业务语义或文字内容被计入。
- 图筛中的纯文本筛选项（如「金枕」「黑刺」「千层」等，仅为灰底/白底+黑字的文字按钮）
- 快筛中的纯文本排序项（如「综合排序」「价格」等）

### icon样式

**定义：** 商卡或图筛内出现的图标元素，指独立的、有辨识度的小型图形符号。

**算"icon"的典型样式：**
- 闪电icon（闪购旁的闪电符号）
- 奖杯/排行icon（榜单旁的奖杯符号）
- 品牌/店铺logo icon（如小象超市icon、切果乐logo icon）
- 星级评分星星icon

**不算"icon"的情况：**
- 商卡左侧的商品主图/大图（属于商卡结构，不是icon）
- 纯文字无图标的标签
- 图筛中的品类缩略图（属于图筛结构，不是icon）

### 样式去重原则

同一组件内只允许对**实体类别、颜色角色、语义角色、容器形态、图形辅助五项均一致**的已确认标签去重，且 Phase2 的 `dedupDecision` 必须点名可去重对象并说明视觉依据。颜色相近、都是圆角胶囊、文案相似均不足以合并。一个折扣胶囊中视觉上共用同一容器的「3.0折」「已减5」可作为一个最小标签实体；同卡中两个“时令”若五项完全一致，可计为 1 种。反之，“神券”（券标）、“鲜打”（商品卖点标）、“酒水热卖榜第1名”（榜单标）、“秒提 到店取”（履约标）、“直播特惠”（营销腰封）、“满85减15”（优惠金额标）即使均为橙色圆角容器，也必须分别计数。评分星、闪电、奖杯等独立图形按 icon 的完整 `styleKey` 另行计数，不能混入标签数。

## 评估标准

对**每个组件**（每张商卡或每个图筛）独立评估：

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 标签样式数量 ∈ [0, 2] **且** icon样式数量 ∈ [0, 1] | 静态元素精简，视觉干净 |
| 🟡 达标 | 标签样式数量 ∈ [3, 4] **或** icon样式数量 ∈ [2, 3]（且不触发不达标条件） | 元素适中，有优化空间 |
| 🔴 不达标 | 标签样式数量 > 4 **或** icon样式数量 > 3 | 元素过多，视觉负担重 |

> **评级判定顺序**：先判断是否触发不达标（任一条件满足即为 🔴），再判断是否满足优秀（两个条件必须同时满足），其余为 🟡 达标。

> **统计口径**：每个组件内部独立计数和评级。标签样式数量和icon样式数量均为该组件内去重后的种类数，不跨组件累加。

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 用户提供搜索结果页截图（单张或多张）。使用图片读取工具加载所有截图。
2. 识别搜索词（顶部搜索栏中的文字）。
3. 识别当前 Tab（全部/外卖/团购等）。
4. 若为多屏截图（如第一屏、第二屏、第三屏），记录屏次。

### Step 2：识别页面中的组件

从截图顶部到底部，按视觉顺序识别以下组件：

**2a. 图筛组件**
- 图筛是搜索结果页顶部的图片+文字筛选入口区域。
- 整个图筛区域作为**一个组件**统一评估。
- 若该截图中无图筛（已滚动不可见或该Tab不展示），记为"无图筛组件"。

**2b. 商卡组件**
- 商卡是搜索结果列表中的每一张商品/商家卡片。
- 每张商卡作为**独立组件**分别评估。
- 为每张商卡编号并记录商品/商家名称（取标题关键词简称）。
- 若商卡底部被截断，仅分析可见部分，在名称后注明"（部分截断）"。

### Step 3：逐组件按视觉清单统计标签样式和 icon 样式

对每个组件，从 Phase2 `visualInventory` 读取六分区已确认实体，按商卡整体边界过滤，再按 `styleKey` 去重统计；**不得只读取 `标签区`，也不得重新把 Phase2 已拆分实体合并**。标签可以出现在任意分区，区域归属不改变其是否计入本维度的结论。

1. 纳入 `entityKind=tag`、`visualStatus=confirmed`、`countedInComplexity=true` 且满足 `isColored || isShaped || hasGraphicAssist` 的元素，按完整五段式 `styleKey` 去重计入标签样式数。缺少语义角色、容器形态、图形辅助、计入理由或去重决定时，必须回退 Phase2，不能自行补全。
2. 纳入 `entityKind=icon`、`visualStatus=confirmed`、`countedInComplexity=true` 的独立图形，按完整五段式 `styleKey` 去重计入 icon 样式数。
3. `visualStatus=uncertain`、`entityKind=text`、主图/商品图以及中性色普通文字必须逐项列为“未计入”，并说明 Phase2 的可见视觉依据。普通下挂文案、票券说明和价格说明即使含“优惠”“年卡”“折”“减”等业务词，只要无彩色/异形视觉证据，均为 `text`，绝不得计作标签。
4. `visualInventory.complete=false`、标签扫描检查表缺失、或任一候选的去重事实不完整时，写入 `待回退Phase2复核`；该组件不产生正式评级，更不得输出“优秀”或把未确认项按 0 处理。回退完成后再生成正式评级。

**3a. 扫描异形/异色标签**

必须按以下路线逐区核查（区域不存在或截图自然截断时跳过，不补推）。**每一区都要先列出“发现元素 → 计入/排除原因”，完成 6 区后才可汇总；禁止看完标签区即下结论。**
- **头图区**：图片上的活动价格角标、折扣贴片、榜单角标、**品牌/业务角标**等 UI 叠加元素；主图/商品图片本体不计。头图左上角的品牌标签须单独判断其色彩/异形属性，不能按主图素材一起排除。
- **标题区**：标题前缀/方括号标签、标题同行 badge、标题下属性标签。
- **基础信息区 / 商家区**：评分、配送、商家信息附近的彩色保障、身份、服务或权益标签；灰色普通文字权益标签应明确记为排除。
- **标签区**：独立权益、资质、验真、榜单、保障和促销标签行。
- **价格区**：现价/划线价之外的促销标签、券标、活动标签；价格文字本身不因是彩色就自动视作标签。
- **文字下挂区 / 图文下挂区**：逐个检查每张下挂商品图片的左上/右上角及其文字区；**折扣贴片、时令/季节标签、券标、商品角标**等带底色、描边或图形辅助的独立标签均须纳入，不能因位于商品图片上而漏计。

在组件内部逐一检查以下典型位置：
- 商卡头图左上角区域（活动价格角标/贴片、品牌标签）
- 每张图文下挂商品图片的左上角和右上角（折扣贴片、时令/季节标签、券标）
- 标题行前方或内部的方括号标签（如「现剥」「剥肉」）
- 标题下方的属性标签（如「时令」「赠叉子」）
- 价格行的促销标签（如「冰爽价」「神券」「限时秒杀」「神价」）
- 品质/保障标签行（如「安心闪购 坏必赔」「自营」）
- 排名/榜单标签（如「榴莲榜第1名」）
- 图筛内的各个筛选项（判断是否为异形/异色）

对每个发现的标签，判断是否满足异形或异色条件。满足则记录其样式描述（如"橙色「闪购」闪电标签"），并在组件内去重计数。

**3b. 扫描icon样式**

同样按整张商卡的全部可见分区扫描，不限于标签区；头图区 UI 角标内、标题/基础信息/价格/下挂区中的独立 icon 均需检查。在组件内部检查是否存在独立的图标元素：
- 标签旁的辅助图标（如闪电、奖杯）
- 品牌/店铺logo图标（如小象超市icon）
- 评分星星图标
- 其他独立的小型图形符号

记录每种icon的描述，在组件内去重计数。

### Step 4：评级

对每个组件，将标签样式数量和icon样式数量代入评估标准，按判定顺序给出 🟢/🟡/🔴 评级。

### Step 5：输出结果

**逐组件明细表格：**

| 搜索词 | Tab | 组件 | 商品/商家名称 | 已计入标签（原文、区域、中文 styleKey） | 未计入对象及视觉依据 | 标签样式数 | 已计入图标 | 图标数 | 评级 |
|--------|-----|------|-------------|-----------------|------------------|:---------:|---------|:------:|:----:|
| 搜索词 | Tab名 | 图筛 | — | 逐项列举 | 逐项列举 | N | 逐项列举 | N | 🟢/🟡/🔴 |
| | | 商卡1 | 商品名简称 | 逐项列举 | 逐项列举 | N | 逐项列举 | N | 🟢/🟡/🔴 |

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 单张截图、单个Tab | 直接分析，输出明细表格 + 汇总 + 总结 |
| 多张截图、同一Tab不同屏 | 分屏分析，商卡按出现顺序统一编号（商卡1 ~ 商卡N），图筛以首次出现的完整内容为准，合并为一份报告。若同一张商卡横跨两屏截图（如第一屏底部露出、第二屏顶部完整展示），以信息更完整的一屏为准，只分析一次，不重复计入 |
| 多张截图、不同Tab | 每个 Tab 独立分析，分别输出明细表格，最终汇总所有Tab的评级分布 |
| 截图中无图筛区域 | 记为"无图筛组件"，不输出图筛行 |
| 截图中无商卡 | 记为"无商卡"，不输出商卡行（如团购Tab可能仅展示门店卡片） |
| 商卡底部被截断 | 仅分析可见部分，名称后注明"（部分截断）"，标签和icon只统计可见的 |
| 图筛/快筛被滚动隐藏 | 不可见区域不纳入分析 |
| 搜索词无法识别 | 询问用户确认搜索词 |

## Gotchas

- **按组件颗粒度独立计数，且必须整卡扫描**：每张商卡、每个图筛单独统计标签样式数和icon样式数，单独评级。商卡的统计边界是整张卡的可见范围，绝不将 Phase2 的「标签区」误当作唯一统计范围；标题区、头图区角标、基础信息区、价格区、商家区、文字/图文下挂区的标签和 icon 均要计入。也绝不将多个组件的标签累加后再评级。
- **只统计种类数，不统计出现次数**：同一商卡内出现3个外观相同的「时令」标签只算1种标签样式，不算3种；但它仍必须先从下挂图片角标中被识别出来。关注的是样式的丰富度，不是出现频次。
- **活动价格角标是标签**：商卡左上角常见的彩色活动价格贴片（如橙底白字"¥33.8"、"¥116.9 闪购活动结束倒计时"）属于异色标签，需计入标签样式数。
- **品牌logo icon与标签区分**：品牌/店铺logo（如小象超市icon）是icon而非标签。判断依据：logo是独立的图形符号，用于标识品牌身份；标签是带文字说明的信息元素。
- **快筛不在评估范围内**：本评测只关注图筛和商卡内的标签/icon。快筛区域（综合排序、价格等横向筛选栏）不纳入评估。
- **纯文本信息不算标签**：商品名、店铺名、评分数字、月售量、距离、配送费、起送价等基础信息文字，即使字号/字色不同，只要没有异形或异色装饰，就不算异形/异色标签。
- **评级是"且/或"逻辑**：优秀要求标签和icon两个条件同时满足（且）；达标和不达标是任一条件触发（或）。优先判断不达标。
- **图筛筛选项通常是中性色纯文本**：搜索结果页图筛中的品种/规格筛选项（如「金枕」「黑刺」「整个」「现剥」）通常为灰底/白底+黑字的纯文本按钮，不属于异形/异色标签。但若筛选项使用了彩色底色或特殊图形，则需计入。
- **标签内嵌图形与icon的区分**：当一个标签自身带有图形辅助（如「闪购」标签左侧有闪电符号），该图形是标签的组成部分，标签计为1种异形标签；同时闪电符号作为独立可识别的icon也计1种icon。标签和icon是两个独立维度，分别计数，互不影响。
- **多屏合并时注意商卡去重**：同一张商卡横跨两屏截图时，只分析一次（取信息更完整的一屏），不要在两屏中各计一次导致重复编号。
- **Phase2 分区不是静态元素的过滤条件**：Phase2 依据语义把信息行归入标题区、价格区、标签区或下挂区；同一类异形/异色标签可以合理地位于这些任一分区。评测时应以「元素是否落在商卡整体边界内」和「是否满足异形/异色或独立 icon 定义」为准，而非以其是否在标签区为准。
- **先看视觉、再看文案**：标签是否计入只能由可见样式决定。灰/黑/白单色的普通文字标签不能因“公益、保障、品牌”等文案语义被误记为彩色标签；反之，头图或下挂商品图上的品牌、折扣、时令等 UI 角标，若有彩色/异形样式，即使在图片区域也必须计入。
- **全域扫描须留痕**：输出明细至少列出头图区、标题/基础信息/标签/价格区、文字下挂区、图文下挂区的已计入标签和明确排除标签；未列出的分区不得宣称已经完成全卡扫描。
