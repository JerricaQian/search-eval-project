## 评审对象与共同契约

评审整张图筛或商卡内的异形异色标签和脱离标签容器的独立 icon。先读 [[组件卡片评测通用契约]]（`phase3-card_or_component-eval/组件卡片评测通用契约.md`）；标题、头图角标、基础信息、价格和各类下挂均在范围内。

## Phase2 与测量门槛

- Phase2 只提供原子、分区、坐标、`entityKind` 与确认状态。疑似新 blob 必须回 Phase2，不能直接计数。
- 每个候选对象先判它是标签、独立 icon 还是普通文字/图片。共用标签容器内的图形辅助和文字是一枚标签；脱离标签容器的功能 icon 才单独计 icon。
- 必须运行 `<projectDir>/scripts/extract_component_metrics.py`，以实体类别、颜色角色、语义角色、容器形态、图形辅助五段式 `styleKey` 去重；LLM 不得改写计数或阈值。
- 每个组件（包括优秀）输出扫描分区、纳入/排除对象、`styleKey`、标签/图标计数和 `measurement.tool/artifactPath/parameters`。

## 判定标准

异形或异色任一成立的标签样式计入；标签容器内的图形辅助与文字是一种标签样式，不另计 icon；纯中性色文字、主图、图筛缩略图不计。商卡内所有区域的标签均纳入，不限标签区；图筛内标签也纳入。计数的是样式种数，不是标签实例数。

| 评级 | 条件 |
|---|---|
| 优秀 | 异形/异色标签样式≤2 且独立 icon 样式≤1 |
| 达标 | 标签样式3–4 或 icon 样式2–3 |
| 不达标 | 标签样式≥5 或 icon 样式≥4 |

同文案但五段式 `styleKey` 不同，或不同文案但完整 `styleKey` 相同，都以脚本的去重结果为准。先完成对象归类，再读计数，不能先凭视觉拥挤感定评级。

## 评分与聚合

- 每个组件按两类计数得到一个评级；标签与 icon 的多个超标点不会生成多次组件扣分。
- Tab 取最差组件评级：任一不达标→不达标；否则任一达标→达标；全优秀→优秀。
- `weightedScore = weight[rating]` 且每个 Tab 只写一次：优秀 `0`、达标 `-1`、不达标 `-2`，不以标签或 icon 数量倍乘。

## 固定评审流程

1. 遍历组件全部已确认原子，先标出标签、独立 icon 与排除对象；不能把疑似 blob 当作已确认原子。
2. 运行测量，按完整 `styleKey` 去重，记录每个对象纳入或排除的理由。
3. 读取标签和 icon 的独立计数，按任一阈值触发组件评级。
4. 覆盖全部组件后按最差值聚合 Tab，并写唯一分数。

## 输出与反误判

- `overview.total` 为组件数；`assessmentRows` 覆盖所有组件。
- `observableFact` 同时写标签 N 种和 icon M 种；完整阈值必须保留。
- 不按文案、颜色相近或圆角相近擅自合并；共用容器的闪电+文字只能是一枚标签。

## Gotchas

- 标题、基础信息、价格等普通文字不因使用颜色就自动成为“异色标签”。
- 头图、图筛缩略图和营销素材不计入；但它们上方独立覆盖的 UI 标签需要保留。
- 每一张商卡的全部区域都要扫描，不能只统计价格区或标签最密集的一块。
