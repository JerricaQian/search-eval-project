## 评审对象与共同契约

只判组件内多个可见信息或功能元素组合后的矛盾，不判截图外的事实真伪或单纯召回不相关。单个元素自身的文案或图标歧义由单一元素维度处理；本 Skill 只处理其与同组件其他元素相互冲突后产生的多种解读或误解。先读 [[组件卡片评测通用契约]]（`phase3-card_or_component-eval/组件卡片评测通用契约.md`）。

## Phase2 与候选门槛

- 标题、副标题、图片、标签、下挂、尺码/规格、搜索词及其可见事实来自 Phase2；组件全域都要扫描。
- 必须运行 `scripts/extract_phase3_relation_candidates.py`，为标题—图片/副标题/标签/下挂/尺码建立候选；同时逐一处理 `internalCandidates` 中的价格语义和规格范围候选。候选枚举和冲突终判属于 Phase3，不使用 Phase2 的真实性结论；脚本候选不是冲突结论。
- 只用同卡可见信息判定。任何需要外部商品知识、商家真实库存或截图外事实才能证明的说法，记录为无法在本 Skill 终判，不能作为冲突。
- 每个完整可评组件（包括优秀）输出 `assessmentRows`：候选对、真实 ID、逐对核查、不适用原因、冲突数、`measurement` 和评级。

## 判定标准

| 评级 | 条件 |
|---|---|
| 优秀 | 信息冲突数=0 |
| 不达标 | 信息冲突数≥1 |

冲突包括图文主体不一致、主标题/副标题/标签区/基础信息区之间互相矛盾、标题与下挂不符、标题与独立尺码/规格范围矛盾、以及价格与价格标签的价格语义或计量范围不能同时成立。只有“主标题/图片不匹配且卡内另一信息声称相关”才将搜索词冲突计入。

对商品卡必须额外完成三类跨字段核对：

- **价格语义：**“起/起步价”只能表示最低起售门槛，不能在未写明对应规格、数量或优惠条件时与“到手价”混为同一价格承诺；两者同一行出现时，必须明确两者分别指什么，否则判歧义。
- **数量单位：**只有同一商品的数量单位确实指向不同计量对象、且无法在卡内语义中等价时才判口径冲突。一次性用品等场景中“3条/3片”若均表示同一商品的件数，是重复表达，归 `eval-8`，不作为真实性冲突。
- **范围换算：**比较重量、容量或数量范围时必须统一单位。范围上限超过“以下/以内”上限（如“3-6斤”与“约2kg以下”）即为同卡规格冲突；即使区间局部重叠，也不能以“存在交集”撤销冲突。

逐对先确认双方语义角色、服务对象和主体/规格，再判断它们是补充、不同维度并列，还是无法同时为真的直接矛盾。未适用的候选也必须保留不适用原因，避免“候选为空”掩盖了没有扫描。

## 评分与聚合

- 每个完整组件按确认冲突数评为优秀（0）或不达标（≥1）；同一组件多处冲突仍只产生一个组件评级。
- Tab 内任一组件不达标，Tab 为不达标；所有完整组件均无确认冲突，Tab 为优秀。
- Tab 的唯一分数为 `weightedScore = weight[rating]`：优秀 `0`、不达标 `-2`；不能按冲突对数相加。

## 固定评审流程

1. 运行候选提取，覆盖图筛、筛选条和每张完整商卡的可见范围，并核对候选对象 ID 真实存在。
2. 对每对及每个内部候选依次比较语义角色、服务对象、主体和规格；价格、数量单位和范围候选必须写出归一化过程。先排除补充说明、不同维度标签和无法证实的外部事实。
3. 对直接矛盾的双方记录可见事实与冲突依据；不适用候选也留下原因。
4. 按组件冲突数评级，聚合 Tab 并写唯一 `weightedScore`。

## 输出与反误判

- `overview.total` 为实际组件数；问题写冲突双方与可见事实。
- 副标题补充、不同维度促销标签、图片中的配菜、店名与菜品名的同词不构成矛盾。
- 标题与搜索词相同不是问题；整个卡无关但未声称相关是召回问题，不属于本 Skill。

## Gotchas

- “搜索词不在卡里”或“卡与搜索词不相关”不是本 Skill 的冲突；必须有卡内双方不能同时成立的证据。
- 图片中出现配菜、套餐赠品或背景物，不能自动反驳标题的主商品。
- 同一个词在店名与菜品名中出现只是同词，不代表主体冲突。
