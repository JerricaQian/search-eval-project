## 评审对象与共同契约

遵循本维度[共享契约](../../contract.md)。一页一结论，所有评级（含优秀）都保留一条 `assessmentRows`。只比至少两张完整、同业务语义、同卡型且均出现的客观字段。

## Phase2 JSON 比较门槛

- Phase2 JSON 提供卡型/变体、原子元素 `semanticRole`、原文、分区、槽位、坐标和样式事实。本 Skill 不运行任何比较候选脚本；Phase3 直接用这些字段完成同卡型分组、字段匹配和差异提取。
- 比较组至少有两张完整卡，且同业务语义、同卡型；不要求、也不得让 Phase2 生成 `same_field_across_cards`。
- 字段匹配键是“`semanticRole` + 服务对象/实体层 + 槽位”。主商家与下挂商品、商品价格与优惠条件、房价与预订/动态信任等服务对象不同，即使角色或文案相近也不得横向比较。
- 自然裁切、字段缺失、不同卡型和不同字段适用性均不构成不一致证据。字段是否真正可比及差异是否妨碍横向理解，仍由 Phase3 逐字段终判。
- 含优秀在内的唯一 `assessmentRows` 必须保留 `cardGroups`、`comparableFields`、`comparisons`、排除原因、`inconsistencyCount`、`evidenceSource=phase2_json_cross_card_comparison` 和评级，不得附带 `measurement`。

## 判定标准

在合格比较组中，只有同一决策字段的表达差异确实增加横向理解成本才不达标；否则优秀。一个字段同时有多种差异仍只计 1 项。页面只有一张可比商卡时无比较对象，判优秀。

| 判定维度 | 只比较的事实 | 计为候选差异 | 不计为差异 |
|---|---|---|---|
| 格式口径 | 同一服务对象的价格类型、计价单位/范围，评分指标/量表，距离、时长、销量或履约的单位与含义 | “起价”与“到手价”、按件与按人均、5 分制与好评率、分钟与预计送达等口径混用 | 实际数值不同；不同商家/商品名称的自然文案差异；不同服务对象的价格或优惠条件 |
| 位置锚点 | 字段相对标题、主价格、基础信息和同一阅读行的关系，以及由此形成的扫读顺序 | 同一主价格一张与标题同层、另一张被放入优惠条件/下挂层，导致需重新寻找或误认字段 | 文字长度导致的轻微横坐标、换行或卡片高度差，且字段仍处于同一信息层和扫读顺序 |
| 样式语义 | 主/次信息层级、价格/优惠/状态的颜色角色、删除线、标签容器及可点击/纯文本等语义编码 | 同一主价格在一张作为主决策信息、另一张被编码为附属优惠条件，或同一评分的量表/状态编码改变 | 无语义变化的色号、字重、间距或圆角微调；仅因活动内容不同而出现的普通装饰 |

客观字段优先比较价格、评分、距离、时长、销量和履约等直接决策事实。标题的“品牌 + 商品名”与“商品名 + 品牌”不作为默认格式差异；只有已确认同一服务对象且顺序变化会改变对象理解时，才进入终判。只比较同时出现且同样适用的字段；卡 A 没有某字段、卡 B 因业态不同展示不同字段，不是“格式不统一”。

**实质影响门槛：**候选差异只有导致至少一项结果时才计为不一致：用户需要换算口径或单位；无法一眼将同一字段横向对齐；误认价格、评分或履约的服务对象/条件；关键字段的扫读优先级被改变。否则写 `not_material`，说明排除原因，不得仅凭候选差异判不达标。

## 评分与聚合

- 一个页面先汇总确认不一致的信息项数：0 为优秀，≥1 为不达标；同一字段的格式、位置、样式多种差异只算一个字段项。
- 只有一个可比商卡或没有合格比较组时没有横向比较对象，按优秀输出并说明范围限制，不能虚构达标档。
- 页面只写 `weightedScore = weight[rating]`：优秀 `1`、不达标 `-1`，不按比较组、卡对或字段数累计。

## 固定评审流程

1. 直接遍历 Phase2 JSON 中完整结果卡，按业务语义、正式卡型和已确认变体形成至少两卡的比较组；先用“`semanticRole` + 服务对象/实体层 + 槽位”匹配字段。
2. 对每个字段分别核对格式口径、位置锚点和样式语义；先排除字段缺失、自然裁切、不同卡型、不同实体层和不适用差异，并写出排除原因。
3. 对保留候选逐项套用实质影响门槛；记录它是否要求换算、破坏横向对齐、混淆服务对象/条件或改变扫读优先级。同一字段多个表现差异仍合并成一个不一致项。
4. 统计不一致字段数，输出唯一页面评级、分数与一条完整测量行。

## 输出与反误判

- 固定字段：`cardGroups`、`comparableFields`、`comparisons`、`excludedReasons`、`inconsistencyCount`、`evidenceSource`、`rating`、`finding`。每个 `comparisons` 项保留比较组、字段匹配键、至少两条观测、格式口径/位置锚点/样式语义三类检测结果、实质影响依据和 Phase3 终判。
- `evidenceSource` 必须为 `phase2_json_cross_card_comparison`，且不得存在 `measurement`。
- 不得将“同类信息未出现”“标题横坐标略异”“实际数值不同”或不同业务卡/实体层的差异当问题；候选不是结论，必须说明比较对象、实质影响门槛和用户理解成本。

## Gotchas

- 可比性检查的是“同一字段的表达是否便于横向比较”，不判断字段真实与否，那是信息真实性 Skill 的范围。
- 只有一张完整卡时的优秀代表无比较对象，不表示卡内所有字段都完善。
- 同业务语义、同卡型是同时门槛；只满足其中一个的卡不能进入同组。
- 不得用原始像素坐标或色值作位置/样式结论；位置看信息层和阅读锚点，样式看其表达的字段语义。
