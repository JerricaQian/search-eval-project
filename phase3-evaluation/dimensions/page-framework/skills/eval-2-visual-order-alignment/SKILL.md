## 评审对象与共同契约

遵循本维度[共享契约](../../contract.md)。页面功能区与同类卡结构只作整页结论的证据，不从卡型名称猜测布局模式。

## Phase2 事实门槛

- 区域/元素坐标、卡型、`layoutMode`、`layoutSignature`、头图与文字区坐标、自然裁切只读 `pageFacts`、`structure`、`render`。
- 先核查搜索框、Tab 栏、头部卡、排筛区、列表卡等功能区域的整体左右边界及错层关系，无需以具体像素差为门槛，只识别明显整体偏移或不合理错层；再只在同类、可完整比较的卡间比较结构。数据量、评分缺失、标签多少、商品推荐数和运营叠加导致的局部高度差不是错位证据。
- 自然裁切、未完整显示或卡型无法确认的对象保留为不可比理由，不能拿来证明混排，也不能以此跳过整个页面检查。

## 判定标准

优秀：页面区域整体对齐，且同类卡关键结构一致。任一确认情形即不达标：

1. 功能区域有明显对齐错位或错层；
2. 同类卡存在有可见结构证据的布局模式混排；
3. 同类卡头图尺寸或比例混排，造成信息区高度或起始位置参差；
4. 同类卡头图、标题、价格等关键元素的相对位置关系根本不同。

“根本不同”只指关键布局结构发生改变，例如头图左右改为上下、信息区起始完全错开、价格从主信息区移到无关区域；绝对坐标、卡高或活动条数量不同不够。页面级评级取最明确、可定位的错位事实，不能把局部内容差异放大为整页问题。

## 评分与聚合

- 页面整体对齐且所有同类可比组关键结构一致为优秀；存在任一确认的页面错位或同类结构混排即不达标。
- 本 Skill 为二档制，不能创建“达标”缓冲档来表示证据不充分；证据不够时先补 Phase2。
- 页面只写 `weightedScore = weight[rating]`：优秀 `1`、不达标 `-1`，不按错位数量、卡数或比较组数累计。

## 固定评审流程

1. 按 Phase2 `pageRegions` 自上而下核查整体左右边界、起始线和相邻区域是否出现明显错层。
2. 按卡型建立可比组，逐卡比头图尺寸/比例、信息区高度和起始、价格/评分/标签的相对位置、关键行关系和下挂结构，排除自然裁切和内容差异。
3. 对每个比较写清“可比/不可比”原因，再确认差异是否改变关键相对关系。
4. 以最明确的错位/混排事实输出唯一整页结论和分数，保留全部实际比较对象。

## 输出与反误判

- 固定字段：`pageRegions`、`sameTypeComparisons`、`rating`、`finding`、`observableFact`，问题时写清区域、卡片 ID 和结构差异。
- 不得把不同业务、不同卡型或数据驱动的高度差误作同类卡混排；版本无法确认时只记录待确认。

## Gotchas

- 不能通过卡片绝对高度、首尾位置或优惠条多少判断布局模式混排。
- 两种业务、广告与自然结果即使都叫商卡，结构比较前仍要先验证其同类性。
- 只有一个同类卡时没有跨卡混排结论，但页面功能区本身仍需检查。
