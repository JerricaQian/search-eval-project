## 评审对象与共同契约

遵循本维度[共享契约](../../contract.md)。只评当前首屏功能区数量，每个页面一条结论；元素复杂度、标签/价格/票券等卡内信息不进入计数。

## Phase2 事实门槛

- 首屏边界、模块类型、坐标、部分可见状态、普通结果列表/主卡/异构卡、侧边栏与“大家都在搜”等模块只读 `pageFacts.modules` 和 `pageFactInventory`。
- 搜索框、状态栏和搜索框上方关联词不计；只露出一部分但用户可见且可理解的功能区仍计。长截图只能使用当前页面定义的首屏边界，不能把下方长页内容混入。
- 模块是否独立必须由 Phase2 的可见功能和几何边界支持。卡内价格、榜单、优惠、票券、标签和下挂信息均不是页面功能区，不能被拆出来增加数量。

## 判定标准

| 首屏独立功能区数 | 评级 |
|---:|---|
| ≤4 | 优秀 |
| 5 | 达标 |
| ≥6 | 不达标 |

功能区包括 Tab、图筛、业务图筛、快筛/筛选器/排序区、主卡（品牌秀、阿拉丁、地标卡）、商家卡列表、异构卡、侧边栏和“大家都在搜”等。普通商卡列表不论条数合计 1 个；商家卡即使没有文字/图文下挂，仍属于普通商卡列表，不能因此拆成异构卡或额外功能区；主卡、真正异构卡按独立实例计；图筛与业务图筛各计 1 个；图筛/业务图筛内部子 Tab 不重复计。营销栏按功能而非位置识别。

计数时先完成合并规则再求和：同一普通结果列表永远合并为 1；每个独立主卡/异构卡因承担不同展示功能按实例计；视觉紧贴不等于同一功能区。用户能在首屏识别其用途的底部部分露出模块仍计入。

## 评分与聚合

- 页面只统计一个 `moduleCount`：`≤4` 为优秀、`5` 为达标、`≥6` 为不达标。
- 多个模块只是构成同一页面计数，不分别生成模块评级或多次扣分。
- `weightedScore = weight[rating]`：优秀 `1`、达标 `0`、不达标 `-1`，只写一次。

## 固定评审流程

1. 以 Phase2 首屏坐标自上而下列出可见功能区，先排除搜索框、状态栏和搜索框上方关联词。
2. 对每项核对可见性和用途：合并普通结果列表，按实例保留主卡/异构卡，图筛和业务图筛分别计入。
3. 形成“模块 ID—类型—计数理由”清单，明确底部部分露出或不计入的依据。
4. 对唯一 `moduleCount` 套阈值，输出唯一页面结论和 `weightedScore`。

## 输出与反误判

- 固定字段：`firstScreenBounds`、`functionalModules`、`moduleCount`、`rating`、`finding`、`observableFact`。
- 不得把同一列表中的多张普通商卡、图筛子项或卡内元素拆为多个功能区；也不得因业态需要更多模块而放宽阈值。

## Gotchas

- 多张普通商卡（含无下挂商家卡）是一个结果列表功能区；多个主卡或真正异构卡才按独立实例分别计数。
- 图筛与业务图筛即使紧邻，功能不同也各计 1；其内部子 Tab 不另计。
- 只露出标题行/上沿、但用户能识别用途的底部模块仍要计入，不能漏算以获得优秀。
