# 36 色标准与颜色统计口径（指标 1.2.2 参考）

本文件是 `single-element-color-scanner` 的配套参考，定义 36 色分格阈值、渐变判定规则、
脚本用法，并沉淀三个标准 case 的答案与「脚本 vs 人工」的实测教训。

---

## 一、36 色分格阈值（HSV）

颜色先从 RGB 转 HSV（H: 0–360°，S: 0–100，V: 0–100），再分格：

### 无彩色（S < 12）——仅作诊断，不计数

| 色格 | 条件 | 中文 |
|------|------|------|
| white | V > 90 | 白色 |
| light-gray | 65 < V ≤ 90 | 浅灰 |
| mid-gray | 40 < V ≤ 65 | 中灰 |
| dark-gray | 15 < V ≤ 40 | 深灰 |
| black | V ≤ 15 | 黑色 |

### 有彩色（S ≥ 12）——按色相 H 分 9 相，每相分深/浅（V>60 浅 / ≤60 深），共 18 格

| 色相 | H 范围 |
|------|--------|
| 红 red | 0–15° / 330–360° |
| 橙 orange | 15–45° |
| 黄 yellow | 45–68° |
| 黄绿 yellow-green | 68–85° |
| 绿 green | 85–150° |
| 青 cyan | 150–195° |
| 蓝 blue | 195–250° |
| 紫 purple | 250–290° |
| 品红 magenta | 290–330° |

合计 5 + 18 = 23 个基础色格；沿用「36 色标准」的历史命名。黑、白和各级灰保留在原始色谱中用于核对裁剪与抗锯齿，**不计入最终总颜色数量**。

---

## 二、总颜色数量的计算口径

「总颜色数量」= 元素内出现的、面积占比 ≥ 1% 的、去重后的可辨识颜色数量。要点：

1. **底色 + 文字色 + icon 都要扫描，但只计有彩色**；黑、白、灰中性色一律排除。
2. **同一视觉颜色不重复计。** 抗锯齿/明暗在同一块颜色上产生的深浅过渡，属同一视觉颜色，合并为一色（如浅黄+深黄=黄）。
3. **渐变：按跨越的不同色相数计。** 青→蓝渐变跨「青」「蓝」两个色相 = 2 色；若仅在同一色相内深浅变化 = 1 色。合并深浅不影响此判定（合并的是同相深浅，跨相仍分开）。
4. **< 1% 面积的有彩色排除**；无彩色（黑白灰）无论占比多少都不计。
5. **背景剔除**：圆角/非矩形元素用方形框裁剪时，四角会露出页面背景色，应剔除后再统计。

评级：总颜色数 ≤ 2 🟢优秀 / = 3 🟡达标 / > 3 🔴不达标。

## 三、脚本用法（count_element_colors.py）

```bash
# 基本：对紧贴裁剪的元素图统计
python3 count_element_colors.py 元素.png

# 圆角/非矩形元素（四角有页面背景）：加 --drop-bg 剔除背景
python3 count_element_colors.py 标签.png --drop-bg

# 从整图里取一个矩形框统计
python3 count_element_colors.py 页面.png --box 762,74,150,74 --drop-bg

# 调占比阈值 / 输出 JSON
python3 count_element_colors.py 元素.png --min-ratio 1.0 --json
```

输出含三层信息：`colors_all`（细粒度 36 格全量，诊断用）、`colors_fine`（细粒度过阈）、
`colors`（感知合并后的最终计色）与 `color_count` / `grade`。

## 四、脚本的能力边界（务必知悉）

脚本给出的是**客观的颜色色谱 + 占比证据**，不是全自动判分器。以下判断脚本无法 100% 替代人工，需人工据脚本输出终判：

- **深浅合并边界**：同一有彩色相的浅橙底与深橙字合并为一个橙色系；人工不得仅因它们属于不同语义角色而拆回多色。
- **背景 vs 元素底色**：`--drop-bg` 靠四角一致性识别背景；当元素紧贴相邻元素（某侧无背景、四角不一致）时不触发，此时需人工确认或收紧裁剪框。
- **渐变的色阶计数**：脚本按落入的色相数体现渐变多色，通常与"跨几个色阶"一致，但边缘抗锯齿会引入额外相邻色相，需人工核对哪些是真实色阶、哪些是过渡噪声。

**推荐用法**：脚本初筛（列出色相与占比、标出渐变跨相）→ 人工看色谱做深浅合并/背景归属的语义终判 → 给评级。裁剪务必紧贴元素边界，这是误差最大的来源。

## 五、标准 case（回归测试基准）

以下为本指标打磨过程中确认的三个标准答案，用于校准脚本与人工判断。

### Case 1：外卖标签（黄底黑字）

- 元素：矩形黄底 + 黑色「外卖」二字。
- 人工标准答案：排除黑字后仅**黄 = 1 个有彩色系 → 🟢 优秀**。
- 脚本要点：需 `--drop-bg` 或紧贴裁剪去掉标签外的白色页面背景；黄底抗锯齿产生的深黄/浅黄应合并为"黄"。
- 教训：**底色必须算色**（黄底不能不算）；圆角标签四角背景白不能计入。

### Case 2：必住榜榜单标签（米底 + 深字 + 棕字）

- 元素：浅米色圆角底 +「必住榜」近黑深字/打钩 icon +「20XX年上榜酒店」棕黄字。
- 人工标准答案：排除黑字，米底与棕字同属橙/棕色相，合并为**1 个有彩色系 → 🟢 优秀**。
- 脚本要点：米底、棕字色相同属"橙"，正确合并为一个橙色系；黑字在诊断色谱中保留但不计数。
- 教训：近黑字属中性色应排除；深棕字仍属有彩色，但与同色相米底合并计数。

### Case 3：NEW 闪电新品标签（黄底 + 黑字 + 青绿→蓝渐变底 + 小粉 icon）

- 元素：左半黄底 +「NEW」深字；右半青绿→蓝**渐变底** +「闪电新品」黑字；一个极小粉色闪电 icon。
- 人工标准答案：排除黑字，黄底 + 渐变底跨青/蓝两色相（= 2 色），小粉 icon 面积 < 1% 排除 → **共 3 个有彩色系 → 🟡 达标**。
- 脚本要点：渐变底会落入黄绿/绿/青/蓝多个色相，需人工核对真实跨色相范围与边缘抗锯齿；最终只保留黄、青、蓝 3 个实质色系。
- 教训：**渐变按跨越色相计多色**，黑字排除，**面积 < 1% 的小 icon 排除**。

> 三个 case 共同的最大教训：结论对不对，首先取决于**能否看清底色/字色、裁剪是否紧贴**，其次才是计色规则。看不清务必放大；能量化就用脚本出色谱，再人工做语义终判。
