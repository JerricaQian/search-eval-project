## 评审对象与共同契约

评审每个可见商卡、图筛或筛选组件的功能区域、信息区域及其关键内容是否完整呈现。先读本维度[共享契约](../../contract.md)；它定义原子性、`finding`、问题卡和 Tab 聚合的共用要求。本 Skill 只判完整呈现，不判信息矛盾（eval-7）或重复（eval-8）。

## Phase2 事实门槛

- 只读取当前 Phase2 的 `render`、`textFacts`、`factInventory`、坐标和卡型事实；清单未列出字段、图片或状态不确定时回退 Phase2，不能从原图补判。
- 候选缺失必须同时满足两件事：`applicabilityEvidence` 证明该字段在这类组件中应出现，`visibleAbsenceEvidence` 证明组件可见范围内确实没有该字段。只有“看起来少了”或只有模板印象，均不建 issue。
- `uncertain` 的字段先补 Phase2：它既不能证明问题，也不能作为“全部完整”的优秀依据。Phase2 无法补足时，在该字段上不下结论，不以猜测拉低或抬高评级。
- 以整张商卡的可见边界核查头图、标题、基础信息、标签、价格及下挂。正常省略号、自然裁切、已展示的尺码 `S/M/L/XL/XXL` 都不是乱码；标题与尺码的语义冲突交 eval-7。

## 判定标准

| 评级 | 条件 |
|---|---|
| 优秀 | 所有有适用性证据的核心与基础元素均完整可见 |
| 不达标 | 任一适用元素不存在、不可读截断、乱码、加载失败或显式声明缺失 |

区域完整先核对当前卡型实际拥有的头图区、标题区、基础信息区、标签区、价格/履约区与下挂区；图文下挂、文下挂等卡型可有不同区域构成，不能要求所有卡复用一套模板。信息完整再核对每个适用区域内的关键内容：核心元素为标题、适用的下挂、交易价格；基础元素为评分、销量、人均、地址/距离、履约信息、头图、标签。下挂和价格必须按当前业态、同类卡对照或可见空白/占位确认适用，不能按模板补齐。图筛/筛选条只核查其应有图片、文字和图标是否可见。

判定时按下列顺序拆解，避免把“业态不同”误当“信息缺失”。

1. 先确认组件是商卡、图筛还是筛选条，以及哪些字段在其可见边界内本应适用。
2. 再确认字段状态是完整可读、可见但截断、不可读/乱码、加载失败，还是明确不存在。
3. 仅当“应适用”与“可见缺失”同时成立时记为缺失；任何一个适用字段命中问题，组件即不达标。

## 评分与聚合

- 组件先按上表得出 `优秀` 或 `不达标`；同一组件多个缺失仍只保留一个组件评级，不按缺失数扣分。
- 一个 Tab 内任一组件不达标，Tab 评级为不达标；所有组件优秀，Tab 为优秀。
- Phase3 只写一条 Tab 级分数：`weightedScore = weight[rating]`，即优秀 `0`、不达标 `-2`。不能把 `-2` 乘以问题组件数。

## 固定评审流程

1. 按 Phase2 卡型与可见边界列出组件；触底截断只评已经可确认的可见部分，不推断屏幕外内容。
2. 为每个组件写出适用元素基线，逐项记录存在性、完整性、`applicabilityEvidence` 和 `visibleAbsenceEvidence`。
3. 对有候选问题的字段先复核文本事实、占位和同类卡，不用业务常识替代证据。
4. 任一确认缺失即判组件不达标；无确认缺失才判优秀，再按 frontmatter 聚合并写唯一 `weightedScore`。

## 输出与反误判

- 非优秀 Tab 的每个问题组件保留一条 `assessmentRows`：组件 ID、可见范围、适用字段、缺失/截断/乱码核查和评级；`evaluatedUnitCount = overview.total`，后者是实际组件数而非元素数。
- `observableFact` 写组件、字段和可见状态；`reason`、`criterion`、`summary` 不能为空。
- 不把业态不适用、数据量差异或 Phase2 漏标当成缺失；显式“暂无”仍是信息缺失，但应如实注明不是渲染故障。

## Gotchas

- 商家 Logo 不是水印；与商品、门店或活动相关的图片不因“像广告”自动视为无关。
- 多个缺失只改变证据条目，不重复扣组件分；本 Skill 的最小单位始终是组件。
- 卡片底部自然出屏、正常截断和加载失败是三种不同事实，不能用同一“缺失”描述替代。
