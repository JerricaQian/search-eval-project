## 评审对象与共同契约

评审整张图筛或商卡内的异形异色标签和脱离标签容器的独立 icon。先读本维度[共享契约](../../contract.md)；必须按 Phase2 为当前组件声明的全部区域逐区扫描，标签可出现在标题、头图、评分与推荐理由、基础信息、价格、权益和各类下挂中的任意位置，不能把 `title/tags` 或其他固定区域列表当作完整范围。

## Phase2 JSON 扫描门槛

- Phase2 JSON 提供原子、分区、坐标、语义角色、样式色值、`entityKind`、容器形态、图形辅助角色与确认状态，不把 `entityKind=tag` 当作标签候选的唯一入口。原子库存不完整或存在 `uncertain` 时必须回 Phase2，不能在 Phase3 从截图新增 blob。
- 先遍历全部已确认原子，再判断它是标签、独立 icon、明确排除的核心字段还是普通文字/图片；不得先按元素类型或所在区域过滤。共用标签容器内的图形辅助和文字是一枚标签；脱离标签容器的功能 icon 才单独计 icon。
- 标签不要求存在独立底色、描边、胶囊容器或角标形态。没有容器但文字前景为有彩色，且表达促销、权益、履约、状态、动态提示、评价说明或其他辅助信息时，是彩色文本标签；其容器形态写 `无容器`。例如橙红色“服务很好非常喜欢”必须进入标签计数。
- 主标题、核心评分值和主价格不是标签，即使它们使用彩色也明确排除。评分值如“4.9分”与评价说明分开；主价格如“¥375起”与“夏日特惠”“立享9.3折”等促销说明分开。
- 标签身份先于 `styleKey`：先确认对象是标签，再以实体类别、颜色角色、语义角色、容器形态、图形辅助五段式 `styleKey` 去重。`styleKey` 负责统计样式种类，不是标签成立的前提；键中颜色角色只能由 JSON 样式色值按七色/中性色口径归并得出。
- **履约标排除：**`到店`、`外卖`、`快递`、`酒店`、`住宿`、`上门`、`在线`、`景点`、`闪购`，以及 Phase2 语义槽位为 `fulfillment`、`fulfillment_tag`、`delivery_time`、`delivery_time_tag` 的标记，属于履约/业态入口，不计标签或 icon 复杂度。其橙、黄、绿、蓝等填充或文字色、圆角实底/无容器样式均不改变排除结论；必须在 `candidateLedger` 记为 `excluded` 并说明“履约标排除”。
- 本 Skill 禁止运行 `extract_component_metrics.py`、OpenCV 或其他像素扫描脚本。每个组件（包括优秀）直接输出 `expectedRegions/scannedRegions/unscannedRegions`、`scannedElementIds`、逐对象 `candidateLedger`、纳入/排除对象、`styleKey`、标签/图标计数和 `evidenceSource=phase2_json_visual_inventory`，不得附带 `measurement`。
- `expectedRegions` 必须来自当前组件的 Phase2 分区，`scannedRegions` 必须与其集合相等，`unscannedRegions` 必须为空。每个活动原子必须出现在扫描账本中；每个标签候选必须明确写入 `included_tag`、`included_icon`、`excluded` 或 `phase2_review_required`，禁止静默忽略。
- `phase2ReviewCandidates` 只承载 JSON 中已显式标为未确认、归属缺失或样式事实不完整的原子；不从照片饱和色块反推疑似角标。存在复核项时不得给出正式评级。

## 判定标准

异形或异色任一成立的标签样式计入；无容器彩色辅助文字属于异色标签。标签容器内的图形辅助与文字是一种标签样式，不另计 icon；履约标、主标题、核心评分值、主价格、纯中性色普通文字、主图、图筛缩略图不计。商卡内所有区域的标签均纳入，不限标签区；图筛内标签也纳入。计数的是去重后的 `styleKey` 种数，不是标签实例数。

| 评级 | 条件 |
|---|---|
| 优秀 | 异形/异色标签样式≤3 且独立 icon 样式≤1 |
| 达标 | 标签样式4–5 或 icon 样式2–3 |
| 不达标 | 标签样式≥6 或 icon 样式≥4 |

同文案但五段式 `styleKey` 不同，或不同文案但完整 `styleKey` 相同，都以当前 JSON 字段派生的去重结果为准。先完成对象归类，再读计数，不能先凭视觉拥挤感定评级。

## 评分与聚合

- 每个组件按两类计数得到一个评级；标签与 icon 的多个超标点不会生成多次组件扣分。
- Tab 取最差组件评级：任一不达标→不达标；否则任一达标→达标；全优秀→优秀。
- `weightedScore = weight[rating]` 且每个 Tab 只写一次：优秀 `0`、达标 `-1`、不达标 `-2`，不以标签或 icon 数量倍乘。

## 固定评审流程

1. 从 Phase2 JSON 读取当前组件全部分区和活动原子，逐区建立扫描账本；不回看截图新增或重拆原子。
2. 对每个原子先完成履约标、标签、独立 icon、核心字段、普通文字/图片归类；彩色文本不得因 `kind=text`、无容器或不在标签区而跳过，履约标必须明确排除。
3. 为已确认标签生成完整五段式 `styleKey`，按键去重，并记录每个候选纳入或排除的理由。
4. 校验全区域、全原子和全候选覆盖；存在未扫描区域、静默原子或 Phase2 复核项时停止评级。
5. 读取标签和 icon 的独立计数，按任一阈值触发组件评级。
6. 覆盖全部组件后按最差值聚合 Tab，并写唯一分数。

## 输出与反误判

- `overview.total` 为组件数；`assessmentRows` 覆盖所有组件。
- 每行 `evidenceSource` 必须为 `phase2_json_visual_inventory`，且不得存在 `measurement`。
- `observableFact` 同时写标签 N 种和 icon M 种；完整阈值必须保留（标签≤3/4–5/≥6，icon≤1/2–3/≥4）。
- 不按文案、颜色相近或圆角相近擅自合并；共用容器的闪电+文字只能是一枚标签。
- `includedTagStyles` 每项代表一种去重后的样式，并保留该样式覆盖的全部 `elementIds`；不能为同一 `styleKey` 重复写多项。

## Gotchas

- 不要把“彩色文字”和“必须有标签容器”绑定；彩色辅助文字本身即可构成文本标签。
- 不要把所有彩色核心字段都升级为标签；主标题、核心评分值、主价格是明确例外。
- 不要把履约标的颜色、圆角或实底当作装饰性标签复杂度；上述白名单和履约语义槽位始终排除。
- 头图、图筛缩略图和营销素材不计入；但它们上方已有独立 Phase2 原子的 UI 标签需要保留。
- 每一张商卡的全部区域都要扫描，不能只统计价格区或标签最密集的一块。
