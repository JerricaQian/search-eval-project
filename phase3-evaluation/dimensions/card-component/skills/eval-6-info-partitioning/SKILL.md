# eval-6-info-partitioning：用 JSON 内容包围盒间隔判断分区边界

---

## 你是谁

你是一位资深的美团搜索结果页体验评测专家。职责链是：**基于 Phase2 JSON 的分区、元素归属、坐标与可见状态 → 扫描每个组件内确认独立且实际相邻的功能分区对 → 按组件计数 → 产出评级、问题项数、排除项、复核项与可追溯证据**。

**证据只来自 Phase2 JSON，绝不像素级主观扫描。**不达标组件记为一个问题项，优秀不是问题项；同一组件命中多条问题也只计一个问题项，不按问题条数倍乘。

---

## 触发场景

- 输入形态：经 loader 校验的 Phase2 JSON 坐标事实。
- 关键词：信息分区、contentBounds、gapX、gapY、gapPx、边界接触、excludedPairs。
- 场景变体：商卡头图、基础信息、标签/价格、下挂等相邻分区。

---

## 评审契约（开工前必读）

评审单个组件内部、且由 Phase2 确认的相邻功能分区；不评组件之间、跨 Tab 或跨屏的边界。先读本维度[共享契约](../../contract.md)。

1. **先完整读取本维度共享契约和当前 Skill，当前 Phase2 事实优先。**
2. **排除项必须显式入账，全部适用区域/组件/比较组必须覆盖，不擅自合并。**
3. **事实或覆盖不足必须进入复核；宁可不出结论，不得静默产出优秀或问题。**

---

## 评审流程（4 步）

### Step 1：读取 Phase2 JSON，确定评测目标

- 通过 `scripts/phase2_bundle_loader.py` 校验并读取 Phase2 JSON；分区、元素归属、坐标与可见状态是唯一事实来源。不得为本 Skill 运行 `extract_component_metrics.py`、OpenCV 或其他截图像素测量脚本。
- 每个分区的内容包围盒取该分区全部活动元素坐标的并集，不使用可能重叠或留白较大的分区外框判断间隔。整张商卡范围包含头图、基础信息、标签/价格和下挂，不能只看“标签区”。
- 候选只能是 Phase2 已确认、同一组件内、坐标并集彼此独立且实际相邻的两个功能分区。组件之间、跨 Tab、跨屏续接、分区内部的字段间距都不进入候选集。两个分区内容并集发生二维重叠时，可能是图片角标、父子容器或价格/权益覆盖关系，写入 `excludedPairs`，不得仅凭并集重叠判为边界不足。
- 若任一分区没有可用活动元素坐标，当前分区对写入 `excludedPairs` 并回退 Phase2；不得用区域外框、截图观感或默认值补造间隔。
- 执行时直接计算每个目标组件的 `partitions`、`adjacentBoundaryChecks`、`excludedPairs`、`issueCount` 和评级；只将问题组件写入 `assessmentRows`，优秀组件和优秀 Tab 不要求保留。`overview.total` 为实际评测组件数。

### Step 2：先排除，再成立，最后处理例外

1. **先排除：**执行本 Skill 原文规定的所有不适用对象、白名单、自然裁切、非候选关系与证据不足项，并逐项记录理由。
2. **再成立：**只对满足当前 Skill 对象、事实门槛和成立条件的候选继续计数或比较。
3. **最后处理例外：**执行原文的核心字段、业务变体、运营差异、嵌套/覆盖或其他专属例外；不得因位置、文案或视觉印象擅自合并。

### Step 3：执行专属扫描、测量或关系核查

1. 遍历整张组件，从 Phase2 JSON 枚举已确认的相邻功能分区对；先写清哪些对因非相邻、跨组件、自然截断或坐标不足而排除。
2. 对每个分区汇总活动 `elementIds`，直接计算元素坐标并集 `contentBounds`。
3. 对称计算两个 `contentBounds` 的 `gapX/gapY`：最大值≥1 为清楚，等于0计一项，两者均为负则按嵌套/覆盖关系进入 `excludedPairs`；坐标不足同样排除，不评级为问题。
4. 汇总组件与 Tab 的问题项数和唯一评级；输出证据来源 `phase2_json_coordinates`，不得附加像素测量产物。

### Step 4：覆盖校验、评级与问题投影

1. **校验覆盖完整性：**执行时确认全部目标组件和相邻分区对均已分流；有未扫描对象、静默原子或复核项即停止相应评级，宁可不出结论。
2. **先归类后读数：**先完成纳入、排除、例外与候选终判，再读取计数、间隔、层级或冲突/重复数量。
3. **按阈值判级并落问题项：**严格使用下方原始判定标准；不达标组件各计一个问题项，优秀不计问题项。

- 日常结论只呈现**评级 + 问题项数**；不输出“评级分布汇总（按搜索词×Tab）”表。
- 评级聚合备注如下：

> 每个组件的 `issueCount` 是 JSON 坐标确认 `gapPx≤0` 的相邻分区对数；同一对最多计一次。
> 所有组件的 N=0 时 Tab 为优秀，任一组件有 N≥1 时 Tab 为不达标。测量不足的对必须被排除并保留原因，不能转写为问题。

- **禁止运行 `extract_component_metrics.py`、OpenCV 或其他截图像素测量脚本；不得附加像素测量产物。**

---

## 判定标准

只对确认独立且相邻的分区对判断 JSON 内容包围盒间隔。水平与垂直方向使用对称间隔 `gapX/gapY`，任一方向存在至少 1 像素正向间隔（`max(gapX,gapY)≥1`）即认为分区清楚；两方向都为负表示二维重叠，进入 `excludedPairs` 而非问题。只有独立分区边缘恰好接触（最大间隔为 0）才是不达标。不再与区域内部间距比较，不计算 `1.5×` 阈值，也不计算 RGB、前景色或背景色差值。

| 评级 | 条件 |
|---|---|
| 优秀 | 当前 Tab 所有可测独立相邻分区对的 JSON 内容包围盒均有至少 1 像素正向间隔，且问题数为 0 |
| 不达标 | 两个确认独立的相邻分区边缘恰好接触（`max(gapX,gapY)=0`），计 1 项；任一组件累计≥1 |

“未测得”“坐标缺失”“无法确认”“非候选对”不是边界接触或重叠，必须排除并回退 Phase2，不能制造问题或优秀证据。`gapPx` 直接由两个分区的内容包围盒计算，LLM 不得改写。

## 输出格式模板

📐 **组件信息分区评测结果**

📌 **评测概述：** 搜索词 {X} · {Tab名} · 完整可评组件 {N} 个

Phase5 问题卡由 `assessmentRows` 中评级为达标或不达标的问题行一对一生成：`description` 写该行事实、命中规则、评级原因与直接影响；`recommendation` 写“调整对象 + 具体动作 + 本 Skill 优秀档验收条件”；Phase4 回写 `evidenceImage`。

---

**评测明细（assessmentRows）**

| 组件 | 组件类型 | 分区对/元素文案 | 问题数 | 评级 |
| --- | --- | --- | :---: | --- |
| 商卡3 · {名称} | 标准商卡 | 基础信息区 ↔ 价格区 | 1 | 🔴 不达标 |

**填写示例：** 上表最后一行展示真实文案、实际数量和对应评级；正式输出时逐一替换为当前页面事实，不使用内部 ID 充当用户可读文案。

> `description` 必须基于对应问题行写清实际对象、计数或比较结果、命中规则、评级原因与直接影响；`recommendation` 必须给出调整对象、具体动作和本 Skill 优秀档验收条件。

**建议示例：** `恢复商卡3基础信息区与价格区之间的正向间隔；验收时确认所有可测独立相邻分区对均至少有 1 像素正向间隔且 issueCount=0，评级达到优秀。`

**结构化证据（随 `assessmentRows` 附出）**

```json
{
  "componentId": "",
  "partitions": [],
  "adjacentBoundaryChecks": [],
  "excludedPairs": [],
  "issueCount": 0,
  "evidenceSource": "phase2_json_coordinates"
}
```

**排除对象（excludedUnits）**

| 组件/分区对 | 标签/元素文案 | 排除原因 |
| --- | :---: | --- |
| 商卡3/图片角标↔头图 | 图片角标↔头图 | 二维重叠，进入 excludedPairs |

**Phase2 复核项（phase2ReviewCandidates）**

- 列出组件、分区对、`elementIds/contentBounds`、阅读轴或 `gapPx` 的事实缺口；有复核项停止评级。
- 复核项只承载当前 JSON 中未确认、归属缺失或事实不完整的对象；**存在复核项时不得给出正式评级**。

**总结说明：** 汇总不达标组件的分区边界问题、优秀组件的分区特征与改进建议；不达标组件计问题项。 Phase5 只展示达标/不达标问题项；优秀仅保留评级解释，不进入发现问题或治理项。

## Gotchas

- **至少 1px 正向间隔 ≠ 还需更大间距/分割线/色差**；只要两个独立内容包围盒在任一方向存在至少 1 像素正向间隔就已经分区清楚，不要求该间隔大于内部间距，也不要求分割线或颜色差；内容并集重叠本身不是失败证据。
- **信息分区评测 ≠ RGB 中位数比较**；不计算区域整体 RGB 中位数，不用颜色差阈值推断边界。
- **分区未展示 ≠ 分区边界问题**；分区本身未展示属于供给问题，不把它转化为“两个分区没有边界”。
