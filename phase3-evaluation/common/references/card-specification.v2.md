# 搜索结果卡片规范知识库 v2

本文件把 2026-08-27 导入的 8 份卡片规范转化为 Phase3 可使用的结构知识。它解释**当前图中已经确认的**卡型、变体、区域和槽位关系；不把设计样板补写到当前 Phase2 manifest，也不改变任何叶子 Skill 的评分阈值。

## 使用边界

- 先以当前 Phase2 已验收的 `cardType`、`variant`、区域、槽位、原子和可见性确定事实；本文件只用于判断字段是否适用、同类卡是否可比较，以及字段服务对象是否不同。
- “最多几行”“固定居左/居右”“仅支持”等展示规范，只有在当前卡型和变体已确认、且相关槽位已出现或有可见占位时，才可作为布局/供给的依据。可选业务模块、自然截断、未确认的 OCR 或截图外内容不得据此判缺失。
- 标签、价格、履约、销量、距离、评分、规格、营业状态和下挂服务的是不同事实；相邻或同色不代表重复，同一文字也不自动代表冲突。

## 卡型映射与结构基线

| Phase3 正式卡型 | 来源规范 | 已对齐的变体/关键结构 |
|---|---|---|
| 商品卡片 | `商品卡片.md` | 闪购、医药、外卖、团购、到店服务；头图、标题、副标题、价格、商家区 |
| 商家卡片-图文下挂 | `商家卡片-图文下挂.md` | 到店/到家主商家 + 商品、组合、特殊或服务下挂 |
| 商家卡片-文字下挂 | `商家卡片-文字下挂.md` | 主商家 + 商品、组合、服务文字下挂，可有 AI 推荐理由 |
| 主点卡片 | `主点卡片.md` | 非商主点、商场、景点、医院；单/多下挂及领域服务 |
| 酒店卡片 | `酒店卡片.md` | 标准酒店/民宿与双列电竞房紧凑变体 |
| 度假/酒店套餐卡片 | `酒店套餐卡片.md` | 自由行、跟团游、酒店套餐 |
| 演出/电影卡片 | `电影卡片.md` | 演出卡与影院卡 |
| 异构卡/广告卡 | `异构卡.md` | 横滑、直播、中插、下拉、大卡、横幅、会员、人物、内容、服务、品宣、剧本杀 |

## 商品卡片

- **头图**：右上角最多一排，优先承载特殊 IP 与属性；活动/自营腰封属于限时或自营氛围表达；补货中、广告和医药广告是状态/标识，不是商品标题。
- **标题与副标题**：标题最多两行；外卖、团购、酒店商品的商家名称可随标题尾部出现。副标题最多三行，优先级为推荐理由 → 增值服务 → 属性说明，且为灰色辅助说明。
- **价格与商家**：价格、价格说明、销量和平台保障是独立槽位。特价/价格说明可为红色、会员价可为橙色、平台保障可为黑色，其余辅助价格信息可为灰色。履约仅表达 `到店/外卖/快递/酒店`，不得把业务类型误当履约标签；配送费、距离、时长、营业状态、评分也各自独立。

## 商家卡片-图文下挂

- **主商家层**：头图左上最多一排可承载直播、5A 营销或资质；底部最多一排为营业状态。标题前有履约标，标题最多一行，到家配送时长可固定在右侧；基础信息按到店（评分、评价、人均、品类、AOI、距离）或到家（评分、销量、起送、配送费、距离）解释。
- **标签层**：一级为强 IP/榜单/神券，二级为高优保障、属性或服务，三级为普通保障、次履约与动态信任；三者的等级和颜色语义不能互换。
- **下挂层**：下挂商品与主商家是不同实体层。下挂可含商品图、商品名、属性、价格/价格说明、推荐菜、环境图、补货、代金券或取号/等位服务；优惠券只因头图尺寸不同可有小/中/大形态，不能据此拆为不同卡型。

## 商家卡片-文字下挂

- 头图、标题、商家信息与三级标签的基本解释同商家卡片族；标题最多一行，景点等级可在标题后，距离/到家履约/上门时间可固定在信息行右侧。
- AI 推荐理由是至多一行的可选文本。下挂只支持：商品（价格 + 名称 + 可选销量）、组合（预约状态 + 商品列表）或服务（按钮 + 副标题/可约状态）；商品和服务下挂可并存，不能要求图文下挂的扩展坑位。

## 主点卡片

- **非商主点**：实体名称、评分、评价数、分类、地址、描述、距离后，可有路线、团购、拍照点、游玩路线等单下挂或 3/4 项多下挂。
- **商场/景点**：商场的文字下挂可表示入驻商户或新店；景点可含等级、榜单/可订标签、门票价格、门票/附近酒店/景酒套餐服务下挂及人流提示。
- **医院**：医院标签、门诊时间/服务、距离和地址外，可显示预约挂号、在线问诊、服务预约、科室排名和医生信息；“有号/无号”是医生操作状态变体。主点不得套用普通商卡或商品卡的必备价格/规格模板。

## 酒店卡片

- 标准变体为头图、标题、评分/推荐理由、位置、标签、价格。头图左上可承载住宿认证体系（美团住宿、认证影音/电竞/好房、优美会等），右上是视频标，底部为营业状态；广告标独立表达。
- 标题前为住宿履约标、标题最多两行，酒店等级为标题后语义；评分/满房、推荐理由、距离、近区位、AOI 是不同基础信息。会员权益、保障/属性/服务/统计等标签按层级解释；动态房价、券/折扣、预订、动态信任、销量和榜单不得混为一项价格事实。
- 双列紧凑变体标题最多一行，头图和信息密度不同；其基础信息两行分别表达房间与设备，价格行可含销量。不能用标准单列的行数或字段排列强判双列异常。

## 度假/酒店套餐卡片

- 头图左上“超级团购/酒店套餐”只适用于酒店套餐；底部出发城市只适用于旅游出发场景。
- 自由行套餐概要优先 `住 → 景 → 享 → 吃 → 行`；跟团游优先团服务/保障，再解释住行服务；酒店套餐以住宿补充、餐饮与权益为主。三种变体的概要字段不能相互强制。
- 标签是灰色文字。价格区为“左侧评分/销量 + 右侧套餐价格”的关系，价格可为划线前后价或起价；不应以电影/演出卡的左置价格基线评判。

## 演出/电影卡片

- 演出卡由海报头图、`演出`履约标 + 城市 + 标题、评分/日期/场馆、左置价格和预约抢票/倒计时组成。海报仅承载海报，不把它上的非系统视觉内容识别成 UI 标签。
- 影院卡由影院标题、地址/商场、近期场次、距离和左置起价组成；它不要求演出卡的海报、日期或场馆字段。

## 异构卡与广告卡

- 异构子形态包括：拼好饭/特价团/旅游/榜单/酒店/医美横滑，酒店/横屏直播，中插商家或笔记视频，图/文下拉，商墙下挂，酒店/打车大卡，横幅/补货/满意度，会员、医生、科普、体检服务、品宣和剧本杀。
- 广告卡必须有当前图已确认的广告/推广标识或素材；直播必须有直播标识。没有这些证据的未知稳定结果单元仍按异构卡处理，不能凭高价、图片或位置猜广告。
- 异构卡承担的聚合、内容、操作或推广功能不同于自然商卡。横滑内的子项目、会员权益、医生条目或大卡内的表单字段不自动拆成独立页面功能区或标准商卡；只有 Phase2 已确认的独立边界和功能才能进入相应页面/组件计数。

## 跨卡判读约束

- 视觉顺序与可比性只在相同正式卡型、同一已确认变体和同业务语义下比较。标准/双列酒店、演出/影院、商品/主商家下挂、不同异构子形态均不是默认比较组。
- 供给完整性只核对本页已确认适用且可见的槽位；设计规范中列举的可选标签、权益、下挂、榜单、状态与服务不因未出现而构成缺失。
- 真实性与冗余判读先区分实体层与服务对象：主商家与下挂商品、门票与景酒套餐、商品价格与优惠条件、酒店房价与预订/动态信任信息均可共存。
