# 搜索结果卡片结构与适用性规范

本文件说明 Phase3 如何解释当前图中已确认的卡型、变体、区域、槽位和实体关系。它只用于判断字段适用性、同类卡可比性和字段服务对象；不补写当前 Phase2 manifest，也不改变任何叶子 Skill 的评级阈值。

## 使用边界与事实优先级

- 先以当前 Phase2 已验收的 `cardType`、`variant`、区域、槽位、原子和可见性确定事实；卡型 `id`、展示名称和正式/兜底属性以根目录 [`card-type-registry.v1.json`](../../../card-type-registry.v1.json) 为唯一来源。
- 行数、固定位置、颜色和坑位等展示规则，只有在卡型、变体已确认且相关槽位已出现或有可见占位时，才可作为布局或供给的依据。可选业务模块、自然截断、未验收的识别候选与截图外内容不得据此判缺失。
- 标签、价格、履约、销量、距离、评分、规格、营业状态和下挂服务分别表达独立事实；相邻、同色或同文案不自动表示重复或冲突。
- 评分阈值、`weight` 和 `aggregate` 只以叶子 Skill 为准。本文件不产生评分结论。

## 卡型与变体总表

| 卡型 | 典型区域 | 变体与判读重点 |
|---|---|---|
| 商品卡片 | 头图、标题、可选副标题、价格、商家 | 闪购、医药、外卖、团购、到店服务；履约、价格口径、规格、促销和商家信息是不同角色。 |
| 商家卡片-文字下挂 | 头图、标题、商家信息、标签、可选 AI 推荐理由、文字下挂 | 下挂可为商品、组合或服务；商品与服务可并存，不套用普通商品卡的价格/规格模板。 |
| 商家卡片-图文下挂 | 头图、标题、商家信息、标签、商品/套餐/服务图文下挂 | 主商家与下挂商品属于不同实体层；券头图尺寸变化不形成卡型变化。 |
| 商家卡片-无下挂 | 头图、标题、商家信息、标签/权益 | 商家卡片族的正式变体；没有下挂不等同异构卡，也不按商品卡模板要求价格或规格。 |
| 主点卡片 | 实体标题、实体信息、领域下挂 | 非商主点、商场、景点、医院；位于结果头部，领域下挂随业务变化。 |
| 酒店卡片 | 头图、标题、评分与推荐理由、位置、标签、价格 | 标准酒店、民宿与双列房型的结构不同；动态房价、预订、动态信任和榜单具有独立语义。 |
| 度假/酒店套餐卡片 | 头图、标题、套餐概要、标签、价格 | 自由行、跟团游、酒店套餐采用各自的概要与价格关系。 |
| 演出/电影卡片 | 标题、演出信息或影院信息、价格 | 演出和影院分别使用不同的头图、时间、场馆、场次与价格结构。 |
| 特殊广告卡 | 已确认的广告/推广标识或广告素材 | 只有明确广告证据才能归入此类。 |
| 异构卡 | 不满足已知卡型的稳定独立结果单元 | 可为横滑、直播、中插、下拉、大卡、横幅、会员、人物、内容、服务、品宣或剧本杀等；未知不等同广告或体验问题。 |

## 通用区域、槽位与实体边界

`头图`、`标题`、`基础信息`、`标签/权益`、`价格`、`下挂`是区域，不可互相替代。履约、价格口径、销量、距离、评分、时间、规格和业务标签各有独立服务对象；判断冗余或矛盾时，先确认是否表达同一事实、能否无损删除，以及是否存在单位或口径冲突。

不同业态不共用同一必备字段：外卖/即时零售不强套餐饮人均或商圈；酒店动态房价入口不因未给固定金额判缺失；主点卡不按普通商家卡的下挂模板判定。

## 商品卡片

- **头图**：右上角最多一排，承载特殊 IP 与属性；活动/自营腰封表达限时或自营氛围；补货中、广告和医药广告是状态或标识，不是商品标题。
- **标题与副标题**：标题最多两行；外卖、团购、酒店商品的商家名称可随标题尾部出现。副标题最多三行，优先级为推荐理由 → 增值服务 → 属性说明，且为灰色辅助说明。
- **价格与商家**：价格、价格说明、销量和平台保障是独立槽位。特价/价格说明可为红色、会员价可为橙色、平台保障可为黑色，其余辅助价格信息可为灰色。履约只表达 `到店/外卖/快递/酒店`，不得把业务类型误作履约标签；配送费、距离、时长、营业状态、评分也各自独立。

## 商家卡片族

### 图文下挂

- **主商家层**：头图左上最多一排可承载直播、5A 营销或资质；底部最多一排为营业状态。标题前有履约标，标题最多一行，到家配送时长可固定在右侧；基础信息按到店（评分、评价、人均、品类、AOI、距离）或到家（评分、销量、起送、配送费、距离）解释。
- **标签层**：一级为强 IP/榜单/神券，二级为高优保障、属性或服务，三级为普通保障、次履约与动态信任；三者的等级和颜色语义不能互换。
- **下挂层**：下挂商品与主商家是不同实体层。下挂可含商品图、商品名、属性、价格/价格说明、推荐菜、环境图、补货、代金券或取号/等位服务；优惠券可因头图尺寸呈现小/中/大形态，但不形成不同卡型。

### 文字下挂

- 头图、标题、商家信息与三级标签的基本解释同商家卡片族；标题最多一行，景点等级可在标题后，距离、到家履约或上门时间可固定在信息行右侧。
- AI 推荐理由是至多一行的可选文本。下挂只支持：商品（价格 + 名称 + 可选销量）、组合（预约状态 + 商品列表）或服务（按钮 + 副标题/可约状态）；商品和服务下挂可并存，不能要求图文下挂的扩展坑位。

### 无下挂

- 头图、标题、商家信息、标签/权益构成完整商家主体；不因没有文字或图文下挂降级为异构卡。
- 与其他商家卡比较时，只比较共同可见且已确认适用的主商家区域；不以未出现的下挂、商品价格或规格作为异常依据。

## 主点卡片

- **非商主点**：实体名称、评分、评价数、分类、地址、描述、距离后，可有路线、团购、拍照点、游玩路线等单下挂或 3/4 项多下挂。
- **商场/景点**：商场的文字下挂可表示入驻商户或新店；景点可含等级、榜单/可订标签、门票价格、门票/附近酒店/景酒套餐服务下挂及人流提示。
- **医院**：医院标签、门诊时间/服务、距离和地址外，可显示预约挂号、在线问诊、服务预约、科室排名和医生信息；“有号/无号”是医生操作状态变体。主点不得套用普通商卡或商品卡的价格/规格模板。

## 酒店卡片

- 标准变体为头图、标题、评分/推荐理由、位置、标签、价格。头图左上可承载住宿认证或标识（美团住宿、认证影音/电竞/好房、优美会等），右上是视频标，底部为营业状态；广告标独立表达。
- 标题前为住宿履约标、标题最多两行，酒店等级为标题后语义；评分/满房、推荐理由、距离、近区位、AOI 是不同基础信息。会员权益、保障/属性/服务/统计等标签按层级解释；动态房价、券/折扣、预订、动态信任、销量和榜单不得混为一项价格事实。
- 双列紧凑变体标题最多一行，头图和信息密度不同；其基础信息两行分别表达房间与设备，价格行可含销量。不能用标准单列的行数或字段排列强判双列异常。

## 度假/酒店套餐卡片

- 头图左上“超级团购/酒店套餐”只适用于酒店套餐；底部出发城市只适用于旅游出发场景。
- 自由行套餐概要优先 `住 → 景 → 享 → 吃 → 行`；跟团游优先团服务/保障，再解释住行服务；酒店套餐以住宿补充、餐饮与权益为主。三种变体的概要字段不能相互强制。
- 标签是灰色文字。价格区为“左侧评分/销量 + 右侧套餐价格”的关系，价格可为划线前后价或起价；不以电影/演出卡的左置价格基线评判。

## 演出/电影卡片

- 演出卡由海报头图、`演出`履约标 + 城市 + 标题、评分/日期/场馆、左置价格和预约抢票/倒计时组成。海报仅承载海报，不把其中的非系统视觉内容识别成 UI 标签。
- 影院卡由影院标题、地址/商场、近期场次、距离和左置起价组成；它不要求演出卡的海报、日期或场馆字段。

## 广告与异构卡

- 广告卡必须有当前图已确认的广告/推广标识或素材；直播必须有直播标识。没有这些证据的未知稳定结果单元按异构卡处理，不能凭高价、图片或位置猜广告。
- 异构卡承担的聚合、内容、操作或推广功能不同于自然商卡。横滑内的子项目、会员权益、医生条目或大卡内的表单字段不自动拆成独立页面功能区或标准商卡；只有 Phase2 已确认的独立边界和功能才能进入相应页面/组件计数。

## 跨卡判读约束

- 视觉顺序与可比性只在相同正式卡型、同一已确认变体和同业务语义下比较。标准/双列酒店、演出/影院、商品/主商家下挂、不同异构子形态均不是默认比较组。
- 供给完整性只核对本页已确认适用且可见的槽位；本文件列举的可选标签、权益、下挂、榜单、状态与服务未出现时不构成缺失。
- 真实性与冗余判读先区分实体层与服务对象：主商家与下挂商品、门票与景酒套餐、商品价格与优惠条件、酒店房价与预订/动态信任信息均可共存。
