# 商品卡轻量识别算法（v2）

## 最小契约

商品卡必须同时具备稳定边界、商品重复拓扑、主图/左侧媒体、标题和价格证据。规格、履约和结果列表位置只能辅助，不能补齐必需证据。完整机器规则见 `card_recognition_contracts.v1.json`。

## 边界

1. 以同列重复的单商品主图为主要卡头。
2. 将右侧标题、规格、价格、销量和商家/配送信息吸附到下一商品卡头之前。
3. 当前截图存在至少两张稳定重复卡时，可用本图纵向周期回填至多一张被 OCR/图片检测漏掉的前置卡；不得使用黄金坐标或期望卡数。
4. 图筛、业务图片筛选、悬浮服务和商家下挂商品图不能成为商品卡头。

## OCR 与价格

标题、价格、评分、销量、距离和履约按坐标与字段形态分开。价格证据可来自可直接读取的货币格式、明确价格上下文，或价格合理位置且排除分钟/距离/评价/配送费/券门槛的红橙色多位数字。

疑似价格仅允许有界复读；恢复的货币符号必须与原 OCR 数字锚一致。不得从配送费、券门槛或黄金字段覆盖当前文字。

## 密集价格/促销行（2026-08-19 校准）

- 一件商品的一行价格可包含主价、原价、每件价和优惠说明，但它们必须分别归属同一商品；一条元素不得包含其他商品的货币值。出现三处及以上货币符号（如 `¥30.6¥10.9¥17¥18.04`）视为跨商品串扰，阻断并以单商品列重新 OCR。
- `前2件¥82/件` 等被 OCR 切成 `82/`、`前2件￥`、`/件` 时，必须在同一商品价格行重组为一个完整价格字段；不得把碎片作为独立元素发布。
- 相邻促销 chip 按视觉边界拆分：`神券`、`52减18`、`62减20`、`坏必赔` 分别记录，不能拼为 `神券52减1862减20坏必赔`。同理，价格末尾不得吞入“已优惠”或“已售”，配送时长不得带多余数字前缀。

## 媒体与黄金样本

除多色照片轮廓外，允许以大面积、高像素方差、足够彩色像素和非细长几何确认低色相商品照片。该规则不检测圆角容器，不按商品词推断图片。

`golden_product_page_structure.v1.json` 和 `cardElementOverrides` 只描述历史样本，供推理后回归；生产识别不得读取它们来补当前卡的坐标、卡型或字段。
