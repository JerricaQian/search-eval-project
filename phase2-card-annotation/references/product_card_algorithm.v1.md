# 商品卡片：CV 定位 + PaddleOCR 局部识别算法（v1）

## 目标与边界

输出嵌套在 `pageStructure.components[].results_list.components[]` 内的商品卡；每张卡只拥有 `头图区 / 标题区 / 副标题区 / 价格区 / 商家区`。本算法只记录截图可见事实，不给出达标、缺失、问题或优秀结论。

## 执行顺序

1. OpenCV 识别页面/结果列表及商品主图候选，建立卡片 y 轴锚点。
2. 对每张卡按固定区域坐标局部裁剪，并以 `PHASE2_ENABLE_PADDLEOCR=1` 调用本地 PaddleOCR。禁止整页 OCR；同一 Python 进程只初始化一次模型。
3. 每个局部 OCR 框保留原始坐标和置信度。履约、标题、价格、商家标签、商家名、起送费、配送费、配送时长、距离分别生成元素，绝不拼接相邻字段。
4. 匹配不成立、字符乱码、坐标跨区域或置信度不足时，保留 `uncertain` 或不发布该候选；不得推断元素缺失。

## 标题与副标题拆分

- 商品名可以占一行或两行，但规格属性、保质期、成分、卖点等第二行必须进入 `副标题区`。
- 当前可执行切分锚点包括：`≥数字`、`保质期：`、`麦香浓郁`、`口感均衡/醇厚/清爽`、`酒精度：`。
- 示例：`燕京U8啤酒8P瓶装500ml度｜≥2.5%vol｜保质期：360天` 应拆成商品标题 `燕京U8啤酒8P瓶装500ml度`，副标题 `≥2.5%vol｜保质期：360天`；`喜力啤酒11.4P听装500ml*12｜麦香浓郁｜一口感均衡` 同理拆分。
- 新增模式须先通过元素级黄金样本确认，再写入规则或 `cardElementOverrides`。

## 区域隔离规则

- 价格区高度不得覆盖商家区；`神券`、价格说明和销量必须用短、封闭表达式匹配，不能使用贪婪的“到行尾”规则。
- 商家区必须分开裁剪：商家标签、商家名、起送费/配送费行、配送时长、距离。普通商家名若 OCR 无法验证，不输出乱码名称。
- 若图片检测遗漏但黄金组件样本已给出卡片 y 锚点，可用锚点生成候选文字区域；头图标记为 `uncertain` 且来源为 `gold_layout_anchor`。

## 黄金储备与回归

`golden_product_page_structure.v1.json` 是商品卡页面结构与用户确认元素的权威来源。`cardElementOverrides` 仅覆盖已确认的卡号/字段；OCR 输出不得覆盖它。每次改动须重建七张商品卡黄金 JSON，并检查：

- 标题区不包含副标题；
- 商家字段未合并；
- 价格/券未吞入商家文本；
- 结果卡仅出现在 `results_list.components[]`；
- `uncertain` 不被解释成缺失、问题、不达标或人工复核。
