# 页面与商卡识别规则

> **适用范围**：IMD 搜索结果页/信息页的本地截图与在线画板标注。
>
> **优先级（从高到低）**：当前截图可见的文案与几何边界 → `SKILL.md` 的硬性约束 → 本文的卡型规则 → IMD 图层名、模板名、颜色、位置、扫描结果和历史案例。低优先级证据不得推断当前图中不可见的区域。

## 1. 总原则

1. **逐行语义优先**：先锁定当前卡的文字列，读出可见文案，再按语义划分区域。模板、颜色、位置和扫描结果只用于辅助确认。
2. **真实存在才创建**：没有可见且可证实的组件、信息行或字段时，不创建对应标注。不得为凑卡型补副标题、价格区、商家区、Tab、图筛或营销横幅。
3. **逐图逐卡独立**：历史场景脚本仅可参考任务字段、标签命名、配色和交付格式；不同截图的坐标、卡序、字段存在性和组件类型均不可复用。对同页同类卡的参考只能作为候选，写入任务表前必须逐边核对当前卡。
4. **扫描只辅助几何**：`scan_rows.py` 可以单次辅助发现宏观留白和当前卡文本列的内容行/留白边界，不能决定区域语义；与读图冲突时以读图为准，不通过调参或重扫凑结果。
5. **输出必须反向审图**：对照原图检查组件存在性、卡边界、头图四边、文字列、标签/下挂切割、异构卡以及不存在的区域。

## 2. 宏观组件

| 组件 | 当前图中的识别条件 | 标注边界与禁令 |
| --- | --- | --- |
| 顶部导航/搜索框 | 页面顶部可见返回、搜索词、定位等导航内容 | 仅标实际可见范围。 |
| Tab | 可见一排频道文字，且有选中态或明确导航语义 | 不能把普通文字、留白或续屏顶部当 Tab。 |
| 图筛 | 多个品类图片或图标与其**全部分类文字**组成的筛选模块 | 必须整体框住图标/图片行和文字行；图筛文字不得另标为快筛。 |
| 快筛/排序/筛选器 | 独立的纯文字或文字+功能 icon 的筛选胶囊/排序行 | 仅框实际存在的行；不能因图筛下有文字而创建。 |
| 营销/权益横幅 | 独立通栏，且有明确优惠、领券、促销或活动文案 | 不能仅凭颜色、高度或位置判定；不属于商卡头图。 |
| 标准商卡 | 当前图中有可识别的商家/商品主体及其信息行，并形成一张独立列表卡 | 卡与卡边界以当前内容、留白和视觉容器综合判断。 |
| 相似推荐提示 | 如“大家还在搜”标题与关键词胶囊网格 | 整体标注，不创建商卡边界或卡内分区。 |
| 运营聚合卡 | 费力度/满意度/调研解释、品牌或运营聚合等非标准重复卡 | 整体标注，不套商卡模板。 |
| 侧边栏 | 位于列表外的地图、客服、回顶部等悬浮功能 | 作为独立组件标注，不参与商卡拆分。 |

### 2.1 分屏续页

- `_全部_2`、`_全部_3` 通常是列表续页，**默认不含** Tab、图筛和首屏营销横幅。
- 只有当前截图能直接读到完整组件时才标注；不得从 `_全部_1` 复制、推断或补画任何顶部组件。
- 当前可见内容优先于常见页面顺序。页面组件的上下顺序不能作为存在性证据。

## 3. 标准商卡与异构卡

### 3.1 判定顺序

1. 先按当前卡可见的标题主体与逐行文案判断其展示对象：商家、商品、酒店/房型、演出、电影或交通。
2. 再观察实际布局：左图右文、上图下文、纯文本或双列瀑布流。
3. 最后使用 IMD 模板名/图层名、颜色和固定位置进行交叉核验。

> 模板名是卡型候选和复核证据，不是字段存在性证据。即使已知模板，也不得标注当前图中不可见的字段。

### 3.2 常见标准卡

| 卡型 | 常见当前图证据 | 可能区域（以实际可见行为准） |
| --- | --- | --- |
| 商家卡 | 商家名称、评分/品类/距离等商家信息；可带图文或文字下挂 | 头图区、标题区、商家信息区、标签区、AI 推荐理由、图文下挂区、文字下挂区 |
| 商品卡 | 商品/团单/实物主体；可带价格、属性、所属商家信息 | 头图区、标题区、副标题区、价格区、标签区、商家区 |
| 酒店/房型/套餐卡 | 酒店等级、房型、床型、套餐、评分、位置或划线价等 | 头图区、标题区、基础信息/套餐概要、标签区、价格区、酒店名称区 |
| 演出/活动卡 | 海报、演出名称、日期、场馆、票价或预约信息 | 头图区、标题区、演出信息区、价格区、下挂区 |
| 电影/交通卡 | 影院场次或出发到达时间、航班/车次等纯文本信息 | 按实际可见文本行划分；头图区可能缺省 |

区域数量没有目标值。稀疏卡、被截断卡只标当前可见且能证明的区域。

### 3.3 异构卡

品牌秀、广告聚合、直播横插、地标、阿拉丁、大家还在搜、费力度/满意度/调研解释等不满足标准卡结构时，默认作为整体异构组件标注。

只有当前内容能够逐项证明其确属标准商卡形态，并且各信息行真实可见时，才可按商卡规则拆分；不能因“广告”“视觉相似”或模板名称推断并拆分。

## 4. 卡内分区规则

### 4.1 几何约束

1. **头图区**：以实际图片像素边缘为准，不包含卡片白边、圆角 padding、右侧文字或图片下方留白。
2. **先锁列，再分行**：左图右文卡先确定头图列与文字列；标题、信息、标签、价格和文字下挂默认位于文字列，实际横跨全卡时才越过头图。
3. **卡边界与下挂归属**：图文下挂或文字下挂若与上方同一商卡的标题/信息连续，且下一张独立卡从其下方开始，则属于上一张商卡；不可误拆为新商卡。
4. **截断处理**：只标截图中可见范围，并在任务数据中记录 `cropped: true`；不推断截图外内容。

### 4.2 语义决策

| 区域 | 当前图中的判断条件 |
| --- | --- |
| 标题区 | 商家名、商品名、履约标识等标题主体所在行。 |
| 商家信息/基础信息区 | 评分、销量、人均、品类、地址、距离、房型/演出等与主体说明连续的信息行。 |
| 副标题区 | 独立的推荐理由、属性说明、增值服务等补充说明行；没有则不创建。 |
| 标签区 | 资质、验真、榜单、保障、独立权益 badge，或与标题/基础信息并列的“神券”等标签行。 |
| 价格区 | 独立表达价格、划线价、销量、履约时效等的价格信息行。红色或棕色仅为辅助证据。 |
| 文字下挂区 | 位于卡下半部、由商品/满减/券后价等组成的连续促销文字行。若“神券、券后价”等属于这条连续促销文案，应整体归此区，而不是因红色价格拆为价格区。 |
| 图文下挂区 | 横向商品小卡、商品图片+商品名/价格组成的下挂内容；可跨多行但必须是同一连续模块。 |
| 商家区 | 商品卡中真实可见的所属商家名、评分、配送等商家信息；不存在时不创建。 |

## 5. 官方设计线索（辅助）

- 商品卡常见主顺序为：头图区 → 标题区 → 副标题区（可缺省）→ 价格区（可缺省）→ 商家区（可缺省）；若有独立可见的保障/IP 标签行，可额外标注标签区。
- 商家卡常见信息行是：头图区 → 标题区 → 商家信息区 → 标签区（可缺省）→ AI 推荐理由（可缺省）→ 下挂区（可缺省）。
- 商品头图的横跨图片底部的条状腰封，以其**实际几何位置**为准；“坑位”名称不代表它一定在物理右上角。
- 酒店商家卡的评分常在标题下方；房型商品卡的评分/酒店名称常在价格下方。仅在当前图实际出现时标注。
- 颜色、字重、角标、IMD 图层模板名和 `absBox` 均只做辅助核验。图层树提供几何候选与节点线索，最终区域语义与可见边界仍须核对当前导出图。

## 6. 统一执行流程

1. 核对用户指定的输入截图/画板范围与标注颗粒度；已明确时不重复询问。
2. 读取当前原图或导出当前画板，确认实际画布尺寸和组件。
3. 对同一目的、同一参数的扫描最多执行一次：允许一次整图扫描；必要时对每张当前卡的已确认文字列各执行一次限区扫描。
4. 先标宏观组件和异构组件，再标标准卡边界，最后按当前可见文案拆卡内分区。
5. 本地 PNG/JPG 路径：把当前图确认的语义与坐标写入 SceneSpec；`coordinate_space` 始终为 `image_pixel`，再由 `annotation_scene.py` 校验、渲染并生成审计报告。在线 IMD 路径：当前没有通用的“SceneSpec → IMD”适配器；新建当前场景专用的 `imd_run_<scene>.py`，使用同一份局部坐标数据并由该脚本加画板偏移后调用 `run_scene`。两条路径均不填写绝对设计坐标到 SceneSpec。
6. 本地路径运行统一执行器生成 PNG 与审计报告；在线路径执行场景脚本并导出视觉验证。两者都只负责校验/渲染，不参与语义识别。
7. 对照原图反向审图；发现语义或边界错误时，仅修改当前路径的任务数据后重绘：本地路径修改 SceneSpec，在线路径修改当前场景专用 `imd_run_<scene>.py` 中的局部任务数据。

## 7. 交付自检

- 所有框都有当前图中的可见语义与几何依据。
- 图筛完整覆盖图标/图片和文字，且未把图筛文字误标为快筛。
- 续屏未继承首屏 Tab、图筛或营销横幅。
- 异构卡未套标准商卡模板。
- 头图区只覆盖真实图片；右侧文本区不压入头图。
- 价格、标签、商家区和下挂区依当前文案归属，而非仅依颜色或模板。
- 截断卡只覆盖可见部分；无真实字段不补齐。
- 输出 PNG、审计报告和任务数均已核对。
