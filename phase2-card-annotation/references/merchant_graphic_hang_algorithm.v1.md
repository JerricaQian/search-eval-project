# 商家卡片-图文下挂识别算法（v1）

## 输入与目标

输入为原始截图的本地 OCR、照片候选、内容块和页面模块候选。算法只输出可审计的卡片、区域、元素**候选**；不输出缺失、问题、评级或人工复核任务。

## 先决页面条件

1. 识别搜索栏、Tab、可选组件与排序筛选。
2. 仅在已确认“排序筛选”下边界之后寻找结果卡。
3. 图筛中的图片、业务运营卡、主点卡和排序筛选本身不能成为商卡种子。

## 图文下挂卡的确认拓扑

在同一列表纵向区间，同时满足下列三项才确认：

1. 左侧窄列存在近方形商家头图：`x <= viewportWidth * 0.16`、宽高均至少 88px、宽高比 0.65–1.35。
2. 该头图下方、下一张商家头图之前，右侧商品列存在宽高至少 96px 的商品图片组：`x >= viewportWidth * 0.18`。
3. 同一卡纵向区间存在本地 OCR 文本候选。

左侧竖版神券/代金券属于特殊下挂，不能作为右侧商品图片组；它既不触发图文下挂确认，也不替代商品图。

确认结果的证据必须记录：商家头图 photo id、商品图 photo ids、`left_square_merchant_head`、`right_side_attached_product_image_group`、`left_coupon_art_excluded`。

## 区域与元素候选

确认卡型后才按 `search_card_taxonomy.v1.json` 打开以下区域：头图区、标题区、商家信息区、标签区、下挂商品区、特殊下挂、服务下挂。

- 头图区：左侧方图及其左上角/底部附属标；附属标随头图排除。
- 商家信息区：评分、新店、评价数、人均、品类、AOI、距离，或到家的销量、起送费、配送费、配送距离。
- 标签区：仅将 OCR 与颜色/位置共同支持的一级、二级、三级标签确认为候选。
- 下挂商品区：右侧横向商品图组、商品名、商品图角标、钻石属性、特殊售卖、价格说明与价格。
- 特殊下挂：神券/代金券、推荐菜、环境图等；不能与商品图片混淆。

元素没有人工框时，OCR + 几何 + 颜色/形状只产生伪标注。低置信或读不清元素保持 `uncertain`；不得由此推断元素不存在。

## 元素级对照样本（库迪）新增规则

库迪元素标注将图文下挂卡的最小输出单位固定为：

1. **头图区**：商家头图；头图内部/贴边的直播标等角标属于头图附属元素。
2. **标题区**：履约标识、商家标题、配送时长（仅到家卡适用）。
3. **商家信息区**：评分/新店、评价条数、人均价、品类、AOI商圈、距离；到家变体为评分/新店、销量、起送费、配送费、配送距离。
4. **标签区**：神券标签、服务/次履约标签、动态信任标签等，每个独立文本/图形标签单列。
5. **下挂商品区**：每个横向商品位分别包含商品图片、商品名称、价格；右侧截断商品仍保留为 `cropped` 候选，不能抄写不可见文字。
6. **特殊下挂**：左侧竖版神券/代金券独立于下挂商品区，包含券面/金额/使用入口等可见元素。

元素 JSON 必须带 `coord`、`visibleText`、`status`、`confidence`、`source` 与 `sourceRegion`。区域几何可确认但文字读不清时，区域保留、元素标为 `uncertain`。

## 当前黄金样本用途

六组“标注前/标注后”截图用于校准页面组件、排序后列表起点、完整卡和截断卡边界。后图不含元素级真值，因此不能用于计算元素分类准确率；它们是组件/卡片级的黄金样本，元素级数据需后续补标或抽检。
