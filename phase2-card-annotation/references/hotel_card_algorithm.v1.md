# 酒店卡轻量识别契约

## 事实约束

- 把截图而不是 query 作为识别实例；相同 query 的两次结果页分别生成 JSON。
- 先切独立渲染单元，再逐卡判型；禁止用页面多数卡型覆盖单卡。
- 单列酒店以本卡头图/标题锚开始、下一同列稳定锚结束。头图高度逐卡检测。
- 双列房型页先识别重复的双列网格，再按单元格切分；左右单元分别分类，不能整行成卡。
- 页尾自然截断酒店格只可继承同列上一张已确认酒店卡；右列异构卡不能成为左列继承源。

## 酒店身份的三条路径

满足共同的稳定边界、媒体、标题和价格后，酒店身份可由以下任一条确认：

1. 酒店/民宿/等级等显式语义。
2. 双列房型格中的房型标题 + 面积/人数/床型 + 电竞/房间设备组合。
3. 民宿房源、超赞房东/入住经历，或三居/整套房 + 住宿设施组合。

显式套餐概要存在时转入度假/酒店套餐契约。演出卡必须同时具有演出/影院身份与场次证据；时间文本和竖图不能单独覆盖酒店身份。

## 混排和内部图片

商家图文下挂的头图必须同时具有邻近商家指标。券图、菜品图和促销图即使近方形，也不能成为下一卡头；它们归属到下一商家头之前的当前商家卡。酒店/民宿卡在同一结果流中仍单独应用酒店边界和身份契约。

## Phase3 元素

逐卡登记头图、标题、评分/推荐、位置、标签、基础信息、价格和销量。双列房型格的视觉顺序为头图 → 标题 → 基础信息 → 价格 → 评分。每个文本/标签保留当前像素测得的颜色角色和精确前景色；图片保留准确坐标并标记 `isPhoto=true`，不在 Phase2 猜测图片综合色。
