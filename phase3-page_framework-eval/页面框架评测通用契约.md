# 页面框架评测通用契约

本文件是 `phase3-page_framework-eval/eval-skills/` 下 7 个 eval skill（eval-1-supply-module-completeness、eval-2-visual-order-alignment、eval-3-page-color-logic、eval-4-static-component-complexity、eval-5-browsing-flow-smoothness、eval-6-info-comparability、eval-7-info-redundancy）的共享契约来源，经逐字比对确认。

## 三档解释与页面级证据展示契约

### 问题解释统一契约（必填，7 个 skill 逐字相同）

- 文案引用具体对象时：标准商卡用「商卡N」，N 为该卡在**标准商卡序列**中的出现顺序（不含异构模块，与内部 `id`/`listPosition` 无关，需重新计数）；异构模块用其描述性类型名称（如「运营聚合卡」），仅当同页面同类型异构模块出现多次时才加独立序号区分（如「运营聚合卡1」「运营聚合卡2」），该序号与商卡序号完全独立计数。禁止出现内部 ID、字段名或脚本文件名，完整黑名单见 `scripts/forbidden_copy_terms.json`。
- 每条 `issues` 中评级为"达标"或"不达标"的记录必须含 `finding` 对象，且四个字段均为非空字符串：`observableFact`（页面区域、可见对象、文本/样式/计数等客观事实）、`ruleOrThreshold`（命中的本 Skill 规则、阈值或比较基线）、`verdictReason`（由事实对照规则得出的本次评级理由）、`userImpact`（对扫读、比较、理解或决策的直接影响）。
- `description` 仅为与 `finding` 一致的一句话摘要，不能用"信息不清晰""体验较差""建议优化"等笼统语替代任一字段；`priorityReason` 必须以影响范围、关键任务阻塞程度及可见频次解释优先级，依据不足时明确写"待人工确认"。
- 每个待优化页面 issue 必须有独立且非空的 `recommendation`：基于本 issue 的 `pageArea`、可见模块、计数/测量值或阈值，说明调整对象、具体动作和验收结果；不同 issue 禁止复用同一句建议。`finding` 四字段末尾不写标点，由报告层统一拼接为事实→依据→影响。
- 页面级问题仍只能以 `pageArea`、`evidence` 和页面事实表达，禁止将组件或元素评级伪装成页面问题；`finding.userImpact` 不得超出截图可见证据可支持的影响范围。

### 简洁问题卡输出与示例（强制）

**【技能专属，SKILL.md 自行定义，不在本文件覆盖范围内】**
- `observableFact` 书写要求一句 + 示例输出一句（一条完整页面级问题卡文案示例）。

**以下 1 条 7 个 skill 逐字相同：**

- 每个 Tab 的优秀、达标、不达标结论均必须输出非空 `reason`（评级与核心可见事实）、`details.criterion`（命中的规则/阈值）及 `details.summary`（页面核查范围与正向/负向证据）；优秀不得只写"无问题"。

**`assessmentRows` 要求——技能专属，按下表选择：**

| 模式 | 适用 skill | 原文 |
|---|---|---|
| 达标/不达标才需要 | eval-1、eval-2、eval-4、eval-5、eval-7 | 达标或不达标结论的 `assessmentRows` 必须保留整页核查事实、命中规则及评级解释；优秀不要求保留 `assessmentRows`。 |
| 每个结论恰一条（含优秀） | eval-3、eval-6 | 每个结论必须保留恰一条 `assessmentRows`，记录整页核查事实、命中规则及评级解释；优秀同样不得省略。 |

**以下 2 条 7 个 skill 逐字相同：**

- 页面框架的每条“达标”或“不达标” issue 都必须提供存在的 `evidenceImage`，报告必须直接渲染该图，不得只显示文字结论。有精确可标注的问题必须生成当前原图的红框/高亮证据图，并使用 `details.evidenceMode: annotated-region`；同时含精确问题与整页统计时使用 `hybrid`。整页统计、跨区域关系或无唯一坐标的问题使用 `original-page`，并把 `details.screenshot` 原图路径同时写入 issue 的 `evidenceImage`，不伪造红框、不写“待人工定位”。
- 优秀仅在评测详情展示 `reason`、`criterion`、`summary` 解释及原图，不进入发现问题/治理项；达标和不达标才进入待优化项。

## Phase2 事实输入契约（整节技能专属，不共享）

普通单图 manifest、黄金 `normalized + evidence` 与 `phase2.atomic-manifest.v3` 必须经 `scripts/phase2_bundle_loader.py` 转为同一只读事实视图。Phase2 只提供页面模块、卡片、元素、归属、坐标和基础可见事实；首屏范围过滤、候选功能区遍历、列表位拼接、跨卡可比字段匹配、差异比较、计数和评级属于 Phase3。禁止要求 Phase2 输出与某个页面评测 Skill 绑定的预计算结论。

7 个 skill 的"Phase2 事实输入契约"节各自点名不同的 Phase2 字段（`pageFacts.modules`、`cards[].structure`、`render`、`textFacts`、`relations` 等）和判定边界，内容完全不同，不构成共享骨架。各 SKILL.md 保留自己的该节全文，不引用本文件。
