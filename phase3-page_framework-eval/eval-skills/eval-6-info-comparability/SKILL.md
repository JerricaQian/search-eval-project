## 三档解释与页面级证据展示契约

问题解释统一契约（必填）通用条款见 [[页面框架评测通用契约]]（`phase3-page_framework-eval/页面框架评测通用契约.md`），本 Skill 不重复列出。

### 简洁问题卡输出与示例（强制）

- 【技能专属】`observableFact` 必须写清同类字段在不同卡片中的格式、位置或样式差异。
- 【技能专属】示例输出：`同类商卡的评分分别使用“4.8分”和“好评率98%”两种表达，评级为不达标。用户无法直接横向比较商家的口碑表现。`

- 每个结论都必须保留一条 `assessmentRows`，包含 Phase3 现场提取的同卡型分组、可比字段、逐卡观测、差异候选、排除原因及评级解释；优秀也不得省略。
- `details.evidenceMode`、优秀排除规则同 7 个 skill 逐字相同条款，详见 [[页面框架评测通用契约]]。

## Phase2 事实输入契约

- Phase2 只提供卡型/布局基础事实、原子元素的 `semanticRole`、原文、规格桶、分区、坐标和样式事实。本 Skill 必须运行 `scripts/extract_phase3_comparability.py`，在 Phase3 内完成同卡型分组、同语义角色字段匹配和格式/分区/位置/样式差异提取；不依赖、也不得要求 Phase2 生成 `same_field_across_cards`关系。
- 自然裁切的元素仍可参与其他只评可见像素的 Phase3 Skill，但不作为完整字段进入横向比较；真正 `uncertain` 的基础事实才回退 Phase2。
- 提取脚本标记的差异只是 Phase3 候选证据，Phase3 仍须按本 Skill 判断其是否真正增加横向比较成本，不得把任一字符串或坐标差异直接计为问题。

## 工具定位

本 Skill 用于评测搜索结果页/信息页截图中的"信息可比性"：在**同一页面**内，多张商卡展示的同一类信息（如标题、优惠标签、评分）是否用了**一致的表达方式**，使用户能够方便地横向比较。若表达方式不一致，导致用户难以比较或比较困难，则判定为不达标。

适用场景：单张截图评测、同一搜索词多 Tab 截图评测、同一 Tab 多屏截图评测。

---

## 核心概念

**信息可比性** = 同一页面内，多张商卡对同一类信息的表达方式是否一致，是否方便用户横向比较、做出选择判断。

**表达方式不一致** = 同一类信息在不同商卡上使用了不同的呈现方式，导致用户无法直接比较或需要额外理解成本才能比较。

本 Skill 只判断**页面内的横向一致性**，不判断信息本身是否真实、是否冗余、是否缺失（这些分别属于 info-authenticity、info-redundancy、supply-completeness 等其他评测项）。

**与相邻评测项的边界：**

- 与 info-redundancy（信息无冗余）的区别：本 Skill 关注同一信息在不同商卡间的表达方式是否一致；info-redundancy 关注单张商卡内部是否有语义重复的信息。两者互不重叠，不要把表达方式不一致误判为语义重复，反之亦然。
- 与 visual-order-alignment（视觉秩序统一对齐）的区别：本 Skill 关注具体信息字段的呈现方式（格式/位置/样式）是否一致；visual-order-alignment 关注整体卡片布局结构（对齐关系、卡片版本、头图比例等）是否一致。新旧卡混排等既可能影响布局也可能影响信息表达，两个评测项可以同时命中，各自独立判断即可。
- 只评客观、可比字段，不评主观营销文案：本 Skill 只判断标题、名称、价格、评分、销量、优惠标签等客观信息的表达方式是否一致；商家自定义的推荐语、营销口号等主观性文案，其措辞不同不属于表达方式不一致（措辞本就应该不同），不纳入本评测范围。

---

## 三类判断标准

对同一页面内、同一类信息，逐一检查是否命中以下任意一类。**命中任意一类即视为该信息项存在"表达方式不一致"问题**：

| 子类 | 判断要点 | 示例 |
|---|---|---|
| 内容格式不统一 | 同一类信息在不同商卡的文案构成方式、数据格式、单位、书写习惯不同 | 商品名一处"品牌+商品名"、一处"商品名+品牌"；距离一处"1.2km"、一处"1200m"；价格一处"¥9.9"、一处"9.9元" |
| 展示位置不统一 | 同一类信息在不同商卡的摆放位置、相对关系不同 | 优惠标签A卡展示在价格右侧、B卡展示在价格下方；评分A卡紧跟标题、B卡沉底展示 |
| 展示样式不统一 | 同一类信息在不同商卡的呈现制式、量纲、视觉样式不同 | 评分A卡用10分制、B卡用5分制；销量A卡用"月售"、B卡用"半年售"；口碑A卡用评分数字、B卡用好评率百分比 |

> **子类之间会合并计数**：若同一类信息（如"优惠标签"）在页面内同时存在格式、位置、样式多种不一致，仍只判定该信息项本身"表达方式不一致"，不重复累加子类数量（详见"评分标准"中的计数口径）。

**关注的信息类型（不限于）**：标题/副标题、商品或门店名称、评分与评价数、价格与优惠标签、销量/口碑类信息、距离与配送时效、规格/份量信息等只要在页面内出现在 2 张及以上商卡中的客观可比字段。

> **角标/标签的特别说明**：功能性标签（如"神券""闪购""自营""可随时退"）若在页面内多张商卡都出现，需要比较的是其展示位置/样式是否一致，仍属于本评测范围；但标签本身的语义是否与其他信息重复，属于 info-redundancy 范畴，不在本评测判断。

## 评分标准

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 页面内无表达方式不一致 | 同类信息在各商卡表达方式统一，用户可直接横向比较 |
| 🔴 不达标 | 页面内存在任意一处表达方式不一致 | 至少一类信息在不同商卡间的格式/位置/样式不统一，影响用户比较 |

> **统计口径**：以"页面内存在表达方式不一致的信息项数量"为核心指标，数量 = 0 → 🟢 优秀；数量 ≥ 1 → 🔴 不达标（不设中间档，命中即不达标）。评级颗粒度为"搜索词 × 页面"，即每个搜索词的每张页面（Tab）独立给出一个结论，互不合并、互不比较。

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 用户提供搜索结果页/信息页截图（单张或多张）。使用图片读取工具逐张加载截图，避免一次性传入多图导致识别遗漏。
2. 识别搜索词（顶部搜索栏中的文字）；若同一批截图对应多个搜索词，需分别归组。
3. 识别当前页面/Tab（全部/外卖/团购/地点/笔记等）。
4. 若为同一 Tab 的多屏截图（第一屏、第二屏…），记录屏次，最终按"同一页面"合并统计（不因为分屏而拆成多个评测单元）。
5. 明确本次评测单元划分：**同一搜索词的同一 Tab（含其所有屏次）视为一个评测单元**，独立给出一个结论。

### Step 2：识别页面内可比信息项

1. 逐张浏览本单元内所有可见商卡，列出重复出现在 2 张及以上商卡中的信息类型（如标题、评分、价格、优惠标签、销量等）。
2. 只出现在单张商卡、其余商卡没有对应信息的字段，无法比较，不纳入本次判断（但如信息缺失本身有问题，应提示用户该内容更适合 supply-completeness 类评测）。仅在同一业务语义、同一卡型的至少两张完整卡之间比较；不同卡型、不同字段适用性、自然裁切字段均不得作为位置或样式不一致证据。

### Step 3：逐信息项横向比对

对 Step 2 中列出的每一类信息，在本单元所有商卡间横向比对，依次检查三类判断标准：

1. **内容格式**：文案构成顺序、数据单位、书写习惯是否一致。
2. **展示位置**：在卡片内的摆放位置、与其他元素的相对关系是否一致。
3. **展示样式**：呈现制式、量纲、视觉样式（含是否带图标、字号字色等影响理解方式的样式）是否一致。

命中任意一类即记录该信息项为"表达方式不一致"，并注明：

- 比较对象已确认属于同一业务语义、同一卡型；
- 至少两张卡均实际展示该客观字段，且其差异不是内容缺失或卡型差异造成；

- 涉及的具体商卡（第几屏第几张，或商卡名称简称）
- 命中的子类（格式/位置/样式，可多选）
- 具体不一致的表现（如"评分一处4.9分（10分制）、一处5.0分（5分制疑似，需结合上下文判断）"）

### Step 4：汇总与评分

1. 统计本单元内"表达方式不一致"的信息项数量。
2. 数量 = 0 → 🟢 优秀；数量 ≥ 1 → 🔴 不达标。

### Step 5：输出结果

**单个搜索词 × 单个页面（Tab）输出格式：**

可采用表格或结构化文字段落两种形式，按信息项数量与说明复杂度选择更易读的一种；信息项较多、需要横向比较时优先用表格，说明性文字较长时可用分点文字叙述，二者信息量应等价。

表格形式，先给出信息项级别的详细分析表格：

| 信息项 | 涉及商卡 | 不一致子类 | 具体表现 |
|---|---|---|---|
| 标题格式 | 商卡2、商卡4 | 内容格式 | 商卡2为"品牌+商品名"，商卡4为"商品名+品牌" |
| 优惠标签 | 商卡1、商卡3 | 展示位置 | 商卡1在价格右侧，商卡3在价格下方单独一行 |
| … | … | … | … |

文字段落形式，逐条列出信息项名称、涉及商卡编号、命中子类、具体表现，每条一句话即可。

无论采用哪种形式，末尾均需附评测结论：

> 🟢/🔴 **评级** — 搜索词「XXX」XX页面，表达方式不一致信息项数量 = N
>
> 一句话总结：列出具体不一致点，或说明"页面内各商卡同类信息表达方式统一，无不一致问题"。

**多个搜索词 / 多个页面输出格式：**

按"搜索词 × 页面"为最小颗粒度，逐个独立输出上述表格与结论，最后附一张汇总总表：

| 搜索词 | 页面 | 不一致信息项数量 | 评级 |
|---|---|:---:|---|
| 理发 | 全部Tab | 0 | 🟢 优秀 |
| 酸奶 | 全部Tab | 3 | 🔴 不达标 |
| 良品铺子猪肉铺 | 全部Tab | 3 | 🔴 不达标 |

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 单张截图、单个搜索词、单个页面 | 直接分析，输出单表格 + 评测结论 |
| 多张截图、同一搜索词同一页面不同屏 | 合并为同一评测单元统一统计，不按屏拆分结论 |
| 多张截图、同一搜索词不同页面（Tab） | 每个页面独立分析，分别输出表格和评测结论，互不比较 |
| 多张截图、不同搜索词 | 每个搜索词独立分析，颗粒度为"搜索词×页面"，禁止跨搜索词比较 |
| 页面内仅 1 张商卡 | 无横向比较对象，直接判定为 🟢 优秀，结论中注明"仅1张商卡，无法比较，默认判优秀" |
| 页面内商卡数量少（2~3张） | 仍按标准执行，但注明"商卡样本量较少，结论可能随更多商卡出现而变化" |
| 某信息项仅部分商卡展示 | 若缺失源于业务类型差异（如到店卡与外卖卡本就字段不同），不计入本评测（属于供给完整度问题）；若同类型商卡本应都展示但部分缺失，视为"展示位置/样式不统一"的一种极端情况，计入不一致 |
| 图片模糊、文字看不清 | 仅依据可辨识的样式/位置/结构判断，不得凭空猜测文字内容，并在结论中注明"部分文字不清，按可观察样式判断" |
| 商卡部分被截断（页面底部） | 仅分析可见部分，若截断部分恰好是待比较信息项，注明"该商卡内容被截断，暂不纳入该项比较" |
| 同一页面出现可确认的同类新旧卡片样式混排（1.0/2.0） | 仅当同类卡片对同一客观字段采用不同且不可直接换算的表达/位置/制式、并造成真实横向比较障碍时计入；不得只根据视觉风格差异或推测版本判定 |
| 不同业态或不同卡片类型混排（如商家卡、外卖卡、团购套餐卡同屏） | 不互相比较；仅在同一业务语义、同一类型且同一客观字段的至少两张完整卡片之间比较。类型差异、字段适用性不同或字段缺失属于其他维度，不计入本指标 |
| 用户要求与之前分析合并 | 回溯之前的分析结果，按"多屏合并为同一页面"的规则重新整理为完整报告 |
| 搜索词或页面/Tab 无法识别 | 询问用户确认搜索词与当前 Tab |

## Gotchas

- **只做页面内横向比较，不跨页面/跨搜索词比较**：不同搜索词、不同 Tab 之间的表达方式差异不属于本评测范围，颗粒度必须严格锁定在"搜索词×页面"。
- **同一信息项多子类命中只算 1 项**：若"优惠标签"同时存在位置不统一和样式不统一，仍只记 1 处"表达方式不一致"，但需在说明中列全命中的子类，避免漏记。
- **单卡无对比对象直接给优秀**：页面内只有 1 张商卡时无法判断可比性，默认判优秀，不能因信息单一而判不达标。
- **信息缺失 ≠ 表达不一致**：某信息项在部分商卡完全不出现，本身是"供给完整度"问题（对应 supply-completeness 类评测），只有当"同类商卡本应展示但表现形式不同"时才计入本评测。
- **新旧卡混排是常见的不一致来源**：1.0/2.0 卡片版本混排、大小头图混排等，本质上是同类信息的展示样式不统一，应重点关注（也与 visual-order-alignment 评测有交叉，但本评测聚焦"是否影响信息比较"这一角度）。
- **评分制式不统一是高优先级检查项**：不同商家可能使用 5 分制、10 分制或好评率百分比，是最容易被忽略但对用户决策影响最大的不一致类型，需重点核查评分数值的量纲。
- **不臆造看不清的文字**：截图模糊、文字被遮挡时，只依据可观察到的结构、位置、样式判断，不确定的地方明确标注局限性。
- **先确认可比对象，再比较位置**：标题或基础信息的横坐标差异本身不构成问题。只有同一卡型、同一字段在至少两张完整卡中均存在，且截图能证明位置/格式/制式差异增加横向理解成本时，才可判为不达标。

## 示例

### 示例 1：无不一致 → 🟢 优秀

搜索词「理发」全部Tab（首屏5张商卡）：标题均为"品牌名(门店定位)"格式；评分均为10分制展示；神券标签均展示在评分行下方居左位置；价格均为"¥价格 【标签】商品名"格式。

结果：表达方式不一致信息项数量 = 0 → 🟢 优秀

### 示例 2：多处不一致 → 🔴 不达标

搜索词「酸奶」全部Tab（首屏4张商品卡）：

- 优惠标签展示位置不统一：商卡1、商卡3的折扣标签紧跟现价右侧展示；商卡2、商卡4的折扣/促销信息在价格下方单独一行展示。
- 口碑展示样式不统一：商卡2、商卡4使用"好评率百分比"（如99%好评）；商卡4同时又展示"4.4分"评分制；商卡1、商卡3完全没有该维度信息。
- 标题内容格式不统一：商卡1、商卡3为"营销文案+商品名(规格)"描述型标题；商卡2为"【卡类型】商品名+数量"标注型标题；商卡4为纯商品名的简单命名型标题。

结果：表达方式不一致信息项数量 = 3（优惠标签位置、口碑展示样式、标题格式）→ 🔴 不达标

### 示例 3：价格展示样式不统一 → 🔴 不达标

搜索词「良品铺子猪肉铺」全部Tab（首屏4张商品卡）：

- 标题详略不一致：3张为简洁"品牌+品类+规格"标题，1张附加大段营销文案，构成内容格式不统一。
