## 三档解释与页面级证据展示契约

问题解释统一契约（必填）通用条款见 [[页面框架评测通用契约]]（`phase3-page_framework-eval/页面框架评测通用契约.md`），本 Skill 不重复列出。

### 简洁问题卡输出与示例（强制）

- 【技能专属】`observableFact` 必须写清可见列表位及异构形态。
- 【技能专属】示例输出：`结果流前 6 个可见列表位中有直播大卡、横滑推荐和相关搜索 3 种异构形态，评级为不达标。用户连续浏览同类结果时会多次被不同阅读模式打断。`

- 达标或不达标结论的 `assessmentRows` 必须保留整页核查事实、命中规则及评级解释（技能专属覆盖模式：达标/不达标才需要）；优秀不要求保留 `assessmentRows`。
- `details.evidenceMode`、优秀排除规则同 7 个 skill 逐字相同条款，详见 [[页面框架评测通用契约]]。

## Phase2 事实输入契约

- 列表起点、`isListPrefix`、`isListItem`、连续 `listPosition`、卡型、布局签名和异构候选均必须读取 Phase2 `pageFacts.modules` / `cards[].structure`；列表前置营销不得占位。
- Phase3 仅按标准 POI 卡定义和本 Skill 阈值判定异构形态，不能把 `isHeterogeneous` 候选直接等同问题；`uncertain` 列表位应请求复核。运营卡、相关搜索卡、“大家还在搜”等只要位于结果流内部并占据独立列表位，必须逐个记录为异构形态，不能遗漏或与相邻标准商品卡合并。
- **先位表、后结论：**`assessmentRows[0].listPositions` 必须逐位写出当前截图实际可见的列表位：`位次、组件/卡片 ID、卡型、是否异构、判断依据、可见状态`。直播大卡必须以“直播画面 + 紧邻横滑商品流”的整体结构登记；若存在于可见结果流中，即使只看到前 3 位，也必须计入异构数。截图未覆盖到第 10 位时，`coverageStatus` 单列记录范围，但异构数为 0 不得仅因覆盖不足降级。
- **业务归属边界：**同屏有不同业态结果只影响每张卡的 `businessCode`/`ownershipScope`，不能据此把标准结果卡判成异构；单张卡的双业务提示必须保留为当前卡事实，不能把“同屏混合业务”错误改写为“单卡双归属”。

## 工具定位

本 Skill 用于评测搜索结果页截图中的**浏览动线顺畅**程度。AI 的能力是帮助评测人员处理复杂的信息页面，识别页面列表中打断纵向浏览动线的**异构形态**数量，并给出评估结论。

评测的核心问题是：**用户在纵向滚动浏览搜索结果列表时，有多少个与标准 POI 卡不同的异构形态插入，打断了连续浏览的节奏？**

最终按**搜索词 × 页面**颗粒度输出评测结论。

**与同系列 Skill 的边界：**

- 本 Skill 关注"列表中有多少个异构形态打断浏览动线"（动线顺畅问题）。
- `eval-visual-order-alignment` 关注"页面各区域是否对齐，同类卡片视觉结构是否统一"（视觉秩序问题）。
- `card-complexity-scanner` 关注"单个商卡的信息量是否过载"（信息复杂度问题）。
- `static-element-complexity-scanner` 关注"组件内异形/异色标签和 icon 的样式数量"（静态元素复杂度问题）。
- 四者互不重叠：同一页面可能同时被多个 Skill 分别评测，互不影响。

## 核心概念

### 什么是「标准 POI 卡」（基准形态）

标准 POI 卡是搜索结果列表中最常见的商家/景点/商品信息卡，通常为「左图右文」结构，包含头图、标题、评分、分类/商圈、标签、价格等信息，卡片之间结构一致，用户可连续纵向浏览。标准 POI 卡是浏览动线的主体，它们构成了用户浏览的"基准节奏"。

**判定标准 POI 卡的要素：** 左图右文布局、包含标题+评分+基础信息+价格等核心要素、与列表中其他同类卡片结构一致。

### 什么是「异构形态」（打断动线的元素）

异构形态是指列表中与标准 POI 卡结构明显不同的组件，它们打断了用户纵向浏览的连续性。异构形态包含两类：

**异构卡：** 虽然占据一个列表位，但卡片结构与标准 POI 卡显著不同。典型例子包括：旅行社/旅游产品卡（以商家 logo 替代实拍头图、下方出现多商品横滑图片流、带角标如「旅游」）、直播大卡模块（含直播画面+横滑商品卡片流，占据大面积）、品牌聚合卡等。

**异构组件：** 不是商家/商品卡，而是**插入搜索结果列表流内部**、占据独立结果位的功能性或内容模块。典型例子包括：「大家还在搜」推荐词模块（一组关键词标签，引导跳转其他搜索）、笔记/攻略内容横滑模块（如「"景点"相关内容」，展示 UGC 图文卡片带作者头像和点赞数）。

> **营销横幅边界（硬规则）**：Tab/快筛之后、首张结果卡之前的优惠券腰封、活动 banner、营销提示条属于页面框架的列表前置区域，**不是结果列表中的异构形态**；不占列表位次、不计入异构数量，也不能单独作为本维度的不达标问题。只有营销内容实际穿插在两张结果卡之间，且作为独立结果位持续打断列表流时，才按其在列表中的实际形态判定。

### 什么不算「异构形态」

以下情况不算异构形态，不应计入异构数量：

- **标准结果卡之间的数据或类型差异**：商家卡、商品/套餐卡等均属于结果供给流；即使卡片类型、头图比例、数据量、标签数量或下挂行数不同，只要仍是承载可浏览供给的独立结果卡，而非插入的内容/功能模块，就不算异构。
- **卡片上的运营叠加元素**：POI 卡上附加的直播中角标、神券浮层、优惠角标等运营元素不改变卡片的基础结构，不算异构。
- **Tab 栏/快筛/排序/筛选器**：这些属于列表上方的功能区域，不占列表位次，不算异构形态。
- **列表前置营销横幅**：位于 Tab/快筛之后、首张结果卡之前的优惠券腰封、活动 banner、营销提示条属于页面框架，不在结果列表流内；不占位、不算异构形态。

### 列表位次计算规则

**起始位置：** 先跳过 Tab、排筛条及列表前置营销横幅，从**第一张结果卡或实际插入结果流的内容模块**开始计数。如果结果列表最顶部是异构组件（如直播大卡），它也占一个位次，不跳过。

**计数范围：** 前10位（小于等于第10位），即列表中的第1位到第10位。

**合并规则：** 视觉上紧密关联、构成一个整体模块的多个区块合并为一个位次。例如"直播画面区 + 紧跟其下的横滑商品流"共同构成一个"直播大卡模块"，算1个位次。

## 评估标准

按**搜索词 × 页面**颗粒度评估，统计前10个列表位中的异构形态数量：

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 异构形态数量 = 0 | 前10位全为标准 POI 卡，浏览动线完全顺畅 |
| 🟡 达标 | 异构形态数量 = 1 | 仅1个异构形态插入，对浏览节奏干扰可控 |
| 🔴 不达标 | 异构形态数量 > 1 | 2个及以上异构形态打断浏览动线，影响浏览体验 |

> **注意：** 这里统计的是页面内所有异构组件的**出现数量**（包括异构卡），每出现一个异构形态计1个。例如前10位中出现1个直播大卡、1个旅行社异构卡、1个"大家还在搜"模块，则异构形态数量=3。

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 用户提供页面截图，通常需要**至少第一屏 + 第二屏**（建议第一屏、第二屏、第三屏共3张）才能覆盖前10个列表位。仅依据第一屏截图通常无法看到10个列表位，应提醒用户补充后续屏截图。
2. 使用图片读取工具加载所有截图。
3. 识别每张截图的**搜索词**（顶部搜索栏文字）。
4. 识别当前 **Tab/频道**（全部、外卖、团购、景点等），若页面无 Tab 可省略。
5. 记录屏次（第一屏、第二屏、第三屏），确认多张截图的连续性。
6. 按搜索词分组——每个搜索词作为一个独立的评测单元。

### Step 2：确定列表起点并逐一编号

**2a. 确定列表起点**

从 Tab 栏和排筛条（全部分类/距离/综合排序等筛选器）之后的第一个内容组件开始，即为列表第1位。若列表最顶部紧接的是异构组件（如直播大卡），它占据第1位。

**2b. 逐一编号前10个列表位**

从列表起点开始，自上而下逐一为每个组件编号（第1位、第2位……第10位）。编号时注意：

- 每个标准 POI 卡占1个位次。
- 每个异构组件（无论大小）占1个位次。
- 视觉上紧密关联构成一个整体的区块合并为1个位次（如直播画面+横滑商品流 = 1个"直播大卡模块"）。
- 若截图未能覆盖到第10位，则在可见范围内尽可能编号（并在结果中注明"截图仅覆盖到第N位"）。

### Step 3：逐位判定是标准 POI 卡还是异构形态

对每个已编号的列表位，判定其类型：

**3a. 判定是否为标准 POI 卡**

检查该位置的组件是否符合标准 POI 卡特征（左图右文、含标题+评分+基础信息+价格等核心要素、与其他 POI 卡结构一致）。若是，标记为"标准 POI 卡"。

**3b. 判定是否为异构形态**

若不符合标准 POI 卡特征，则判定为异构形态，并记录：

- **异构形态类型**：给出描述性名称（如"直播大卡模块"、"旅行社异构卡"、"笔记攻略横滑模块"、"大家还在搜推荐模块"等）。
- **异构特征描述**：说明它与标准 POI 卡的结构差异（如"以商家 logo 替代实拍头图 + 下方多商品横滑图片流"）。
- **所在位次**：记录该异构形态出现在第几位。

### Step 4：统计异构形态数量并评级

**4a. 统计异构形态数量**

统计前10位中所有异构形态的出现数量（每个异构卡或异构组件各计1个）。

**4b. 依据评估标准评级**

- 异构形态数量 = 0 → 🟢 优秀
- 异构形态数量 = 1 → 🟡 达标
- 异构形态数量 > 1 → 🔴 不达标

### Step 5：输出结果

**5a. 列表位次明细表：**

| 位次 | 组件内容 | 形态类型 |
|------|---------|---------|
| 1 | 上海迪士尼度假区 | 标准景点POI卡 |
| 2 | 上海海昌海洋公园 | 标准景点POI卡 |
| ... | ... | ... |
| N | "大家还在搜"推荐模块 | **异构组件** |

**5b. 评测汇总表：**

| 搜索词 | 异构形态数量 | 异构组件明细 | 评级 |
|--------|------------|------------|:----:|
| 迪士尼 | 3 | ① 直播大卡模块（位次1）② 旅行社异构卡（位次7）③ "大家还在搜"模块（位次9） | 🔴 |
| 景点 | 2 | ① 笔记攻略横滑模块（位次6）② "大家还在搜"模块（位次8） | 🔴 |

**5c. 总结说明：**

在表格下方附一段文字总结，包含：

- 每个搜索词页面的浏览动线顺畅度评价。
- 🔴 不达标页面的异构形态具体描述（类型、位置、对浏览节奏的影响）。
- 🟢 优秀页面的亮点（如"前10位全为标准 POI 卡，浏览动线完全无中断"）。
- 跨搜索词的整体结论。

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 仅提供第一屏截图 | 提醒用户需补充第二屏、第三屏截图以覆盖前10个列表位。若用户无法补充，仍按可见范围逐位判定实际异构数量并给出该范围的体验评级；另在 `coverage`/审计说明记录“截图仅覆盖到第N位，未覆盖完整前10位”。覆盖不足不是页面体验问题，绝不得仅因未满10位将优秀降为达标，也不得生成待优化问题。 |
| 多张截图、同一搜索词不同屏 | 按屏次拼接连续列表，跨屏连续编号前10位，输出一份整体结论 |
| 多张截图、不同搜索词 | 每个搜索词独立评测，最终汇总所有搜索词的评级分布 |
| 同一搜索词多个 Tab | 每个 Tab 独立作为一个评测单元，分别评级 |
| 前10位中出现同一类型异构形态多次（如两个"大家还在搜"） | 每个异构组件各计1个，2个"大家还在搜"则计2个异构形态 |
| 异构组件横跨两屏截图 | 以组件完整可见的一屏为准，只识别一次 |
| 无法判定某组件是标准 POI 卡还是异构形态 | 记录该组件的具体特征，列出判断依据，标注"待确认"交由用户决定 |
| 同一模块包含多个视觉区块（如直播画面+横滑商品流） | 若视觉上紧密关联构成一个整体，合并为1个位次、1种异构形态 |
| 列表中出现分隔线/间距但无实质内容 | 不占位次，忽略 |
| 截图中列表不足10位 | 在可见范围内评测：异构=0仍为优秀、异构=1为达标、异构≥2为不达标；结论注明“前N位可见，共发现X个异构形态”，覆盖范围单列为审计限制而非问题。 |
| 用户自定义了不同的判断标准 | 以用户自定义标准为准，替换本 Skill 的默认评估标准 |
| 页面为空结果/无搜索结果 | 不评测浏览动线（无列表内容），注明"该搜索词无搜索结果" |
| Tab/快筛后、首张结果卡前出现优惠券腰封或活动 banner | 这是列表前置营销横幅，跳过后从首张结果卡开始编号；不占列表位、不计入异构数量 |
| 营销内容位于两张结果卡之间 | 仅当其以独立结果位插入列表流、而非附着于某张结果卡或页面固定区域时，才按实际结构判定是否为异构形态 |
| 列表上方有二级推荐 Tab 栏（如"推荐/景点/酒店/美食/旅游产品"） | 二级推荐 Tab 栏属于列表上方的功能区域，与排筛条同层，不占列表位次 |
| 列表中出现不同业态的标准 POI 卡混排（如景点卡与酒店卡交替） | 只要卡片结构均为标准 POI 卡（左图右文+核心要素齐全），不算异构形态。业态混排属于视觉秩序问题（由 `eval-visual-order-alignment` 评测），不属于本指标 |

## 自检 checklist（出结论前逐条核对）

- 是否正确识别了列表起点（Tab 栏/排筛条之后的第一个内容组件）？
- 顶部异构组件（如直播大卡）是否计入了列表位次，而非跳过？
- 是否逐位编号了前10个列表位？是否有遗漏或跳号？
- 视觉上紧密关联的区块（如直播画面+横滑商品流）是否合并为1个位次？
- 每个异构形态是否都记录了类型名称、特征描述和所在位次？
- 异构形态数量是否按出现次数逐个计数（每个异构卡/组件各计1个）？
- 标准 POI 卡之间的数据差异（高度不等、标签多少）是否未被误判为异构？
- Tab 栏/快筛/排序/筛选器是否未被计入列表位次？
- 截图是否覆盖了前10个列表位？若未覆盖完整，是否在结论中注明？
- 异构形态数量的统计是否与明细表一致？
- 评级是否与评估标准对应（0=🟢、1=🟡、>1=🔴）？

## Gotchas

- **结果列表内的顶部异构组件才计入列表位次。** 列表起点前的营销横幅、优惠券腰封不是结果位，必须跳过；从第一张结果卡或实际插入结果流的内容模块开始编号。若结果流第1位就是直播大卡等异构组件，才计入第1位。
- **前10位 = 小于等于第10位。** 检测范围是第1位到第10位（含第10位），不是"前10个标准 POI 卡"。异构组件也占位次，所以实际看到的标准 POI 卡可能不足10个。
- **一张截图通常不够。** 一屏通常只能展示3-5个列表位，需要至少第一屏+第二屏（建议三屏）才能覆盖前10个列表位。收到仅一张截图时应提醒用户补充。
- **异构形态数量按出现次数逐个计数。** 前10位中每出现一个异构卡或异构组件就计1个。例如出现1个直播大卡+1个旅行社卡+1个"大家还在搜"=3个异构形态。
- **合并为整体模块的区块只算1个位次。** 直播画面区+紧邻的横滑商品流构成的"直播大卡模块"算1个位次和1种异构形态，不拆成2个位次。
- **数据差异不等于异构。** 同类 POI 卡因商家数据不同导致的高度差异、标签数量差异、下挂行数差异，不算异构形态。只有卡片的结构和布局发生根本性变化（如 logo 替代实拍头图、出现商品横滑图片流）才算异构。
- **Tab 栏和排筛条不占列表位次。** Tab 栏（推荐/景点/酒店/美食等）和排筛条（全部分类/距离/综合排序）属于列表上方的功能区域，是列表的前置控件，不计入列表位次。列表位次从排筛条之后的第一个内容组件开始。
- **运营叠加元素不影响 POI 卡身份。** POI 卡上附加的直播中角标、神券浮层、"7天最低"标签等不改变卡片的基础结构，不应将带有这些叠加元素的 POI 卡误判为异构卡。

## 示例

### 示例 1：全为标准 POI 卡 → 🟢 优秀

搜索词：咖啡，全部 Tab

前10位全部为标准 POI 卡（左图右文结构，含商家名/评分/分类/价格），无任何异构形态插入。用户可从第1位连续浏览到第10位，纵向浏览动线完全顺畅。

异构形态数量 = 0，评级：🟢 优秀

### 示例 2：1个异构形态 → 🟡 达标

搜索词：火锅，全部 Tab

前10位中，第7位为"大家还在搜"推荐词模块（一组关键词标签如"重庆火锅""铜锅涮肉"等），其余9位均为标准餐饮 POI 卡。

异构形态数量 = 1（"大家还在搜"推荐模块），评级：🟡 达标

### 示例 3：多种异构形态 → 🔴 不达标

搜索词：迪士尼

前10位中，第1位为直播大卡模块（含直播画面+横滑商品卡片流），第7位为旅行社异构卡（北京黑马环球专营旗舰店，logo 头图+多商品横滑图+「旅游」角标），第9位为"大家还在搜"推荐词模块。其余7位为标准景点 POI 卡。

异构形态数量 = 3（直播大卡模块、旅行社异构卡、"大家还在搜"模块），评级：🔴 不达标
