## Phase2 事实输入契约

- 页面区域坐标、卡型、`layoutMode`、`layoutSignature`、头图/文字区坐标及自然裁切状态必须读取 Phase2 `pageFacts`、`structure` 与元素 `render`；不得重新凭印象识别布局。
- 本 Skill 仅据这些事实判断页面对齐、同类结构一致性和是否影响节奏；不从卡型名称推断 1.0/2.0，设计版本必须有可见结构证据。

## 工具定位

本 Skill 用于评测搜索结果页或信息页截图中的**视觉秩序统一对齐**程度。AI 的能力是帮助评测人员处理复杂的信息页面，识别页面中的不对齐、视觉结构不统一的情况，并给出评估结论。

评测的两个核心维度：

- **页面布局对齐**：各功能区域（搜索框、Tab栏、头卡、排筛、列表卡片）左右边界是否整体对齐。
- **同类卡片视觉结构统一**：结果列表中同类卡片的视觉结构是否一致（头图尺寸比例、信息区高度、元素排布位置）。

最终按**搜索词 × 页面内**颗粒度输出整体评测结论。

## 核心概念

### 页面布局对齐

**定义：** 页面内各功能区域（搜索框、Tab栏、头卡/POI卡、排筛条、列表卡片区）的左右边界是否整体对齐。

**检查要点：**

1. 不检查具体像素距离，只查是否存在**明显的对齐错位**。
2. 典型错位表现：某个功能区域整体偏移、区域之间出现不该有的错层、列表卡片区域因头图尺寸不一致导致信息区起始位置参差不齐。
3. 正常表现：各功能区域左右边界一致，无明显偏移或错层。

### 同类卡片视觉结构统一

**定义：** 结果列表中属于同一类型的卡片，其视觉结构是否保持一致。

**检查三要素：**

1. **头图尺寸比例**：同类卡片的头图是否采用一致的尺寸和比例（如统一为正方形、统一为竖向矩形大图）。
2. **信息区高度**：同类卡片的信息区行数、内容量是否基本一致（不因设计规范差异导致一张卡片信息显著多于另一张）。
3. **元素排布位置**：价格、评分、标签等关键元素的相对位置是否统一。

**同类卡片的判定：** 同一业态/频道下出现的同类型商家卡视为同类卡片。例如同一列表中的外卖商家卡之间互比，到店商家卡之间互比。

### 两类核心不达标场景

#### 场景一：1.0/2.0 新旧卡混排

同一页面的列表中，同类型卡片出现了1.0和2.0两种设计规范的混用。典型表现：

- **履约/功能标签位置不同**：一张卡片的"外卖"标签在标题左侧作为前缀（2.0样式），另一张的"闪购"标签在右上角独立展示（1.0样式）。
- **信息区行数差异明显**：2.0样式的卡片标签信息展示1行，1.0样式的卡片标签信息展示2行，导致信息区高度差异显著。
- **商品横滑区展示不一致**：一张卡片的商品横滑区带折扣角标（1.0），另一张不带（2.0）。

只要在同一页面的列表中观察到上述新旧规范混用，即判定为 🔴 不达标。

#### 场景二：大小头图混排

同一页面的列表中，不同卡片的头图尺寸比例出现明显差异，导致对齐错乱。典型表现：

- 到店商家卡使用竖向大矩形头图，外卖商家卡使用正方形中小头图，两种卡片在列表中交替排列。
- 头图宽度不一致导致右侧信息区的起始位置参差不齐。
- 连续浏览时视觉节奏被打断（大-小-大的头图尺寸交替变化）。

只要在同一页面的列表中观察到大小头图混排导致对齐错乱，即判定为 🔴 不达标。

## 评估标准

对**每个搜索词的整个页面**给出一个整体结论，需同时考量两个维度：

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 页面各区域整体对齐，**且**同类卡片视觉结构一致 | 视觉秩序统一，浏览体验流畅 |
| 🔴 不达标 | 存在明显错位，**或**同类卡片视觉结构差异明显 | 视觉秩序混乱，影响浏览体验 |

**触发 🔴 不达标的条件（任一触发即不达标）：**

1. 页面功能区域之间存在明显的对齐错位或错层。
2. 同类卡片之间存在1.0/2.0新旧设计规范混排（履约标签位置不同、信息行数差异明显、展示风格不一致）。
3. 同类卡片之间存在大小头图混排（头图尺寸比例不一致，导致信息区起始位置参差不齐、视觉节奏被打断）。
4. 同类卡片之间关键元素（头图、标题、价格）的相对位置关系不一致（如一张左图右文、另一张右图左文）。

**以下情况不算不达标：**

1. **数据量差异导致的高度不同**：同类卡片因优惠标签多少、商品推荐数量不同导致卡片整体高度不等，只要关键元素位置关系一致，不算不达标。
2. **数据缺失导致的局部空出**：某张卡片因无评分数据导致评分行消失，只要其余元素位置关系不变，不算不达标。
3. **运营叠加元素差异**：某张卡片多了活动角标、优惠券浮层等运营叠加元素，但底层卡片结构一致，不算不达标。

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 用户提供页面截图（单张或多张）。使用图片读取工具加载所有截图。
2. 识别每张截图的**搜索词**（顶部搜索栏文字）。
3. 识别当前 **Tab/频道**（全部、外卖、团购等），若页面无 Tab 可省略。
4. 若为多屏截图，记录屏次。
5. 按搜索词分组——每个搜索词作为一个独立的评测单元。

### Step 2：识别页面功能区域并检查布局对齐

对每个搜索词的页面，从顶部到底部识别所有功能区域：

**2a. 识别功能区域**
- 状态栏、搜索框、Tab栏、日期条（如酒店类场景）、快筛/排序条、运营横幅（如618活动）、推荐词区域（如"大家还在搜"）、列表卡片区。
- 为每个区域记录名称。

**2b. 检查左右边界对齐**
- 观察各功能区域的左右边界是否整体一致。
- 重点关注列表卡片区域：列表中各卡片的左右边界是否对齐，是否因头图尺寸差异导致信息区起始位置参差不齐。
- 记录是否存在明显错位或错层。

### Step 3：识别列表中的卡片并检查视觉结构统一性

**3a. 逐一识别列表中的卡片**
- 从上到下逐一识别列表中的每张卡片。
- 为每张卡片编号并记录：商家/商品名称、卡片类型（外卖商家卡、到店商家卡等）、设计规范版本（1.0/2.0，若可识别）。

**3b. 按类型分组并提取布局结构**
- 将同类型卡片归为一组。
- 对每张卡片，描述其布局结构要点：
  - 头图位置及尺寸比例（正方形中小图 / 竖向大矩形图 / 横向宽图）
  - 履约/功能标签位置（标题左侧前缀 / 右上角独立 / 标题下方行内）
  - 信息区行数（评分行、销量行、配送行、标签行各几行）
  - 商品横滑区特征（有无折扣角标、价格标注方式）

**3c. 同类卡片间对比**
- 逐项比较同类型卡片之间的布局结构。
- 重点检查：
  - 是否存在1.0/2.0新旧规范混用（对照上方「场景一」的典型表现）
  - 是否存在大小头图混排（对照上方「场景二」的典型表现）
  - 关键元素（头图、标题、价格）的相对位置关系是否一致
- 记录所有发现的不一致问题及具体表现。

**3d. 不同类型卡片间的混排检查**
- 若列表中出现不同类型的卡片交替排列（如商家卡与套餐商品卡），先按类型分别检查同类卡结构；**卡片类型混排本身不是问题，也不得仅因头图尺寸、内容行数或下挂形态不同判定不达标。**
- 只有混排同时造成可见的页面级对齐错误（例如列表左右边界错层、同一列信息起点无规律跳变，或可由截图明确识别的同类新旧规范混排）时，才将该具体错位纳入页面级判定。不得只凭单个标题的 x 坐标不同作出不达标结论；必须确认比较对象同卡型，并在证据中同时标明至少两张对照卡的关键锚点和肉眼可见的错层。

### Step 4：页面级评级

综合 Step 2（页面布局对齐）和 Step 3（同类卡片视觉结构统一）的分析结果，对该搜索词的整个页面给出评级：

1. 检查是否触发任一 🔴 不达标条件 → 是则 🔴 不达标。
2. 以上均无 → 🟢 优秀。

### Step 5：输出结果

**5a. 评测明细表：**

| 搜索词 | Tab | 页面布局对齐 | 同类卡片视觉结构统一 | 具体问题描述 | 评级 |
|--------|-----|-----------|---------------|-----------|:----:|
| 搜索词 | Tab名 | 对齐分析结论 | 统一性分析结论 | 问题详述（无问题则填"无"） | 🟢/🔴 |

**5b. 评级分布汇总：**

| 搜索词 | Tab | 评级 |
|--------|-----|:----:|
| 搜索词 | Tab名 | 🟢/🔴 |

**5c. 总结说明：**

在表格下方附一段文字总结，包含：
- 每个搜索词页面的整体视觉秩序评价。
- 🔴 不达标页面的具体问题描述（如"花店页面存在1.0/2.0新旧卡混排：鲜花岛为2.0样式、邮氧森林为1.0样式，履约标签位置不同，信息行数差异明显"）。
- 🟢 优秀页面的表现亮点。
- 跨搜索词的整体结论。

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 单张截图、单个搜索词 | 直接分析，输出明细表 + 汇总 + 总结 |
| 多张截图、同一搜索词不同屏 | 分屏分析后合并，同类卡片跨屏统一对比，输出一份整体结论 |
| 多张截图、不同搜索词 | 每个搜索词独立评测，最终汇总所有搜索词的评级分布 |
| 同一搜索词多个 Tab | 每个 Tab 独立作为一个评测单元，分别评级 |
| 列表中仅有 1 张卡片 | 无同类对比对象，视觉结构统一性默认为"一致"；仅检查页面布局对齐 |
| 卡片底部被截断 | 仅分析可见部分；若关键元素已完整呈现，可正常参与对比 |
| 同一卡片横跨两屏截图 | 以信息更完整的一屏为准，只分析一次 |
| 页面中存在运营横幅/活动 banner | 运营横幅作为独立功能区域，检查其与上下区域的对齐；不影响列表卡片的结构统一性判断 |
| 页面中混合多种业态卡片（如全部 Tab 同时出现外卖卡和到店卡） | 先按类型分组各自对比视觉结构统一性；不同类型卡片不以标题或文字列横坐标直接互比。仅在页面整体确有肉眼可见的左右边界错层或连续节奏紊乱时，才判定不达标，并同时提供至少两张卡的对照证据。 |
| 列表中同类型卡片的头图尺寸不一致（非跨类型混排） | 同类型卡片内部出现头图尺寸差异（如同为外卖商家卡但一张为大图一张为小图），属于同类卡片视觉结构不统一，判定 🔴 不达标 |
| 页面中出现异构卡（品牌卡/运营平台卡） | 异构卡（如"美团无忧通"、沉浸式品牌卡）与普通商家卡结构设计不同，不参与同类卡片视觉结构统一性对比；但需检查异构卡是否导致页面整体布局对齐错乱 |
| 搜索词/场景无法识别 | 询问用户确认搜索词或页面场景 |
| 用户要求与之前分析合并 | 回溯之前的分析结果，按统一格式输出完整报告 |
| 用户自定义了不同的判断标准 | 以用户自定义标准为准，替换本 Skill 的默认评估标准 |

## Gotchas

- **颗粒度是页面内整体，不是按组件类型拆分**：每个搜索词的页面给出一个整体结论（🟢或🔴），不需要拆到每种组件类型分别评级。页面内只要存在任何一处不达标问题，整个页面即判定为 🔴。
- **1.0/2.0混排是高优先级检查项**：美团搜索结果页存在1.0和2.0两种设计规范，同一页面中不应同时出现两种规范的卡片。典型识别线索包括：履约标签位置不同（标题左侧 vs 右上角独立）、标签信息行数不同（1行 vs 2行）、商品横滑区是否带折扣角标。发现混用直接判 🔴。
- **大小头图混排关注列表整体视觉节奏**：不同类型卡片（如到店大头图卡 vs 外卖中小头图卡）在同一列表中交替排列时，会导致头图右边界参差不齐、信息区起始位置不统一。虽然不同类型的卡片设计不同本身可以理解，但如果混排导致页面整体对齐错乱、视觉节奏被打断，仍应判定为 🔴。
- **数据量差异导致的高度不等不是不达标**：同类卡片因优惠标签多少、商品数量不同导致高度不等，只要关键元素位置关系一致，不算视觉结构不统一。不要因为视觉上"长短不齐"就判定不达标。
- **运营叠加元素不影响底层结构判断**：优惠券浮层、活动角标等临时运营元素的有无不影响底层卡片结构的一致性判断。应将运营叠加元素与底层结构分开分析。
- **页面布局对齐是宏观检查**：不检查具体像素距离，只检查是否存在"肉眼可见的明显错位"（如某个功能区域整体偏移、列表卡片区域因头图尺寸不一致导致的信息区错位）。
- **不同页面各自使用1.0或2.0都是正常的**：问题在于**同一页面内**出现混用。如果所有截图中，搜索词A的页面统一用1.0、搜索词B的页面统一用2.0，两者各自正常，不算不达标。
- **不同类型卡片之间不做视觉结构统一性对比**：外卖商家卡和到店商家卡本身设计结构不同是合理的，不应要求它们视觉结构一致。但要关注它们在同一列表中混排时是否导致页面整体对齐错乱。
- **识别1.0/2.0需要实际观察卡片细节**：不能仅凭业态（外卖/到店/闪购）来推断规范版本，需要实际观察履约标签位置、标签信息行数、横滑区展示风格等细节特征来判断。
- **异构卡不参与同类对比但需检查对整体对齐的影响**：品牌卡、运营平台卡（如"美团无忧通"、沉浸式品牌卡）与普通商家卡结构设计不同，不参与同类卡片视觉结构统一性对比。但如果异构卡的尺寸或位置导致其与上下功能区域的对齐出现明显错位，仍应纳入页面布局对齐检查。
