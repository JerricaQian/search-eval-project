## 工具定位

本 Skill 用于评测搜索结果页或信息页整页截图的**色彩运用逻辑性**，颗粒度为**按搜索词 × 页面**统计一次（不逐组件拆分）。AI 通过 Python 脚本对整页截图做像素级 HSV 分析：先由人工标定并排除商家图片、商品图片、营销类元素（营销图片/banner/腰封）、金刚 icon、图筛/金刚位的分类配图（照片类内容图）所在的矩形区域，再对剩余有效像素统计两个指标——总颜色数量（36 色标准，占比 ≥ 1% 计入）与主导色数量（7 色标准，占比 > 5% 计入），最终按标准给出评级。

**与同系列 Skill 的边界：**

- 本 Skill 关注"整页颗粒度下，色彩数量是否可控、是否存在视觉主导色"（页面级色彩复杂度问题），产出一个页面一条结论。
- `eval-3-color-logic`（`color-logic-scanner`）关注"逐组件颗粒度下，每个商卡/组件内部的有彩色系数量"（组件级色彩复杂度问题），产出多条结论。
- `single-element-color-scanner` 关注"单一元素（如某个标签）内部的颜色数量是否 ≤ 2"（元素级色彩复杂度问题），颗粒度更细。
- 三者互不重叠，颗粒度从粗到细依次为：页面（本 Skill）→ 组件（eval-3）→ 单一元素（single-element）。同一张截图可能同时被三个 Skill 从不同颗粒度分别评测。

## 核心概念

### 两个统计指标

**总颜色数量（页面中颜色数量）：** 按 36 色标准统计整页有效像素中，占比 ≥ 1% 的色系数量。反映页面整体使用了多少种"色相方向"。

**主导色数量（页面中视觉权重高的颜色数量）：** 按 7 色标准统计整页有效像素中，占比 > 5% 的色系数量。反映页面是否存在明确的视觉焦点色，而不是色彩权重分散。

两个指标的分母相同：均为**排除后的全部有效像素数**（含黑白灰中性色），而非仅有彩色像素数。这样占比才能反映"这个颜色在整页视觉中占多大分量"，而不是"在有彩色像素中占多大分量"。

### 36 色标准（用于总颜色数量）

所有像素先从 RGB 转为 HSV（H: 0–360°，S: 0–100，V: 0–100）。饱和度 S < 12 的像素视为黑白灰中性色，不参与计数。饱和度 S ≥ 12 的有彩色像素按色相 H 值分为 9 个色相区间，每个区间再按明度分深浅两档（共 18 个有彩色格），深浅两档合并计为同一色系：

| 色相区间 | H 范围 | 色系 |
|---------|--------|------|
| 红 | 0–15° / 330–360° | red |
| 橙 | 15–45° | orange |
| 黄 | 45–68° | yellow |
| 黄绿 | 68–85° | yellow-green |
| 绿 | 85–150° | green |
| 青 | 150–195° | cyan |
| 蓝 | 195–250° | blue |
| 紫 | 250–290° | purple |
| 品红 | 290–330° | magenta |

统计"总颜色数量"时，逐一计算这 9 个色系在全部有效像素中的占比，保留占比 ≥ 1% 的色系，计数即为总颜色数量。

### 7 色标准（用于主导色数量）

在 36 色标准的 9 个色相基础上，将相邻或视觉相近的色相合并为 7 个基础色相：黄绿并入绿、品红并入红，得到红、橙、黄、绿、青、蓝、紫 7 个色系。统计"主导色数量"时，逐一计算这 7 个色系在全部有效像素中的占比，保留占比 > 5%（严格大于，5% 本身不计入）的色系，计数即为主导色数量。

> 7 色标准的合并方式仅用于计算主导色数量，与 36 色标准分开独立统计，不要混用同一份色相占比表——品红在 36 色里单独算一个色系，在 7 色里要先并入红再判断占比是否超过 5%。

### 排除范围（两个指标共用同一套排除规则）

以下内容不参与任一指标的统计：

- **黑白灰中性色**：饱和度 S < 12 的像素，无论明度高低（含白色背景、黑色文字、各级灰色）。
- **商家图片 / 商品图片**：菜品实拍图、商品包装图、店铺头图、商品渲染图等。这类图片的色彩由商家/供给方决定，不是 UI 设计控制的色彩，天然色相丰富，若不排除会导致几乎所有页面都被判不达标。
- **营销类元素**：营销图片、banner、腰封等平台运营投放的推广素材（**不含标签本身**——活动标签、优惠标签等 UI 标签保留统计，因为标签颜色由设计规范控制）。
- **金刚 icon**：金刚位入口图标，色彩由运营配置决定，非 UI 设计色彩。
- **图筛/金刚位的分类配图（照片类内容图）**：图筛/快筛行中各分类项配发的照片类内容缩略图（如榴莲页的"金枕/黑刺/托曼尼"等品类配图），色彩由运营/供给决定而非 UI 设计控制，排除理由与金刚 icon 相同。仅排除配图本身；分类项的文字标签、选中态（下划线/描边/底色）等 UI 部分不在排除之列。

**不排除的内容：** 标题、价格、评分、标签（含叠加在图片上的角标）、按钮等 UI 设计元素的色彩，以及图筛/快筛项中的文字标签、选中态等 UI 部分，即使它们紧邻或叠加在被排除的图片/营销素材/分类配图上，也应保留参与统计。

### 排除方式：人工标定矩形区域

与逐组件/逐元素评测不同，页面级排除**不采用自动照片检测算法**。原因：整页截图版式差异大（商卡数量、图片位置、营销区域形态各不相同），自动检测容易产生两类误判——把纯色 UI 标签误判成照片而排除，或者漏检商家 Logo 类小图标、品牌横排缩略图等非典型照片区域。因此本 Skill 采用"人工读图标定坐标 + 脚本按坐标排除"的方式，准确率更可控，且每次结果可追溯、可复核。

标定流程：先用 `grid_overlay.py` 给整页截图叠加水平网格线和 y 坐标刻度，人工目视读出需要排除的商家图片/商品图片/营销素材/金刚icon/图筛分类配图所在的 `[y1, y2, x1, x2]` 矩形范围，再将这些矩形传入 `page_color_analysis.py` 的 `exclude_regions` 参数。

## 评估标准

对**每张页面**给出一条整体评级：

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 总颜色数量 ∈ [0, 6] 且 主导色数量 ∈ [1, 2] | 色彩数量克制，且存在明确的视觉主导色 |
| 🟡 达标 | 总颜色数量 ∈ [7, 10] 或 主导色数量 = 3 | 色彩数量偏多，或主导色略多但仍可控 |
| 🔴 不达标 | 总颜色数量 > 10 或 主导色数量 = 0 或 主导色数量 > 4 | 色彩过多，或视觉焦点缺失/过于分散 |

**判定优先级（用于覆盖三条规则未穷尽的组合区间）：** 三条规则依次按"不达标 → 优秀 → 达标"的顺序判断，命中即停止：

1. 先判断是否命中**不达标**条件（总颜色数量 > 10，或主导色数量 = 0，或主导色数量 > 4）。命中则评级为 🔴 不达标，不再继续判断。
2. 若未命中不达标，再判断是否**同时满足**优秀条件（总颜色数量 ∈ [0, 6] 且 主导色数量 ∈ [1, 2]）。同时满足则评级为 🟢 优秀。
3. 其余情况（既未命中不达标、也未同时满足优秀条件，例如总颜色数量=5 但主导色数量=4 与"不达标"的">4"不符实为=4，或总颜色数量=8 但主导色数量=3 这类不落在优秀区间、也不落在不达标区间的组合）一律评级为 🟡 达标。

> **为什么需要这个优先级：** 总颜色数量的两个区间 [0,6] 与 [7,10] 本身首尾相接、没有数值重叠，但主导色数量维度仍存在交叉地带——例如"总颜色数量=5（属于优秀区间）且主导色数量=4"，字面上既不满足"优秀"的主导色条件（4 不在 [1,2]），也不满足"不达标"的主导色条件（4 不是 0 也不 >4，是等于 4），而"不达标"的总颜色条件也不满足（5 不 >10）。此时既非优秀也非不达标，按"宁中不严"原则归入达标档，避免评级空缺。

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 用户提供整页截图（单张或多张）。使用图片读取工具加载所有截图，确认图片尺寸。
2. 识别搜索词（顶部搜索栏文字）；若为非搜索场景，识别页面所属场景名称代替搜索词。
3. 识别当前 Tab/频道（全部、外卖、团购等），若页面无 Tab 概念可省略。
4. 确认截图为**整页截图**（包含搜索栏/Tab栏/筛选栏等页面级元素，纵向涵盖多个商卡）。若用户提供的是单个商卡/组件的裁剪图，不适用本 Skill，应改用 `eval-3-color-logic`（组件颗粒度）。
5. 若提供了多张截图，先判断它们之间的关系，这决定了 Step 3 用哪种脚本模式、以及最终产出几条评级结论：同一搜索词 + 同一 Tab + 内容首尾能拼接续接（如第一屏底部商卡与第二屏顶部商卡是同一批结果的连续部分）→ 视为**同一页面的多屏滚动截图**，走多屏合并模式，只产出 1 条结论；只要搜索词、Tab、或页面场景任一不同，就应拆分为独立的页面分别处理，各自产出 1 条结论（参见「分支处理」）。

### Step 2：生成坐标网格辅助图，标定排除区域

1. 运行 `scripts/grid_overlay.py`，用 100px 间距给整页截图叠加网格线，得到全局坐标概览图。
2. 目视识别页面中需要排除的区域：商家/商品图片（头图、菜品图、商品缩略图、店铺 Logo 小图标）、营销类元素（banner、腰封、活动海报，注意腰封上如果叠加了独立标签，标签本身不排除但整条腰封底图排除）、金刚 icon 区、图筛/金刚位的分类配图（只框配图本身；同一分类项的文字标签与选中态保留，配图与文字标签上下相邻时用局部放大网格图核实分界线）。
3. 对边界不确定的区域（如商卡内图片与标签的分界线、营销卡片内产品图与"特价团"标签的分界线），用更小的 step（如 20px）对该局部区间重新生成放大网格图，精确读出上下边界的 y 坐标，避免把标签误框入排除区、或把图片边缘遗漏在排除区外。
4. 记录所有排除矩形，格式为 `[y1, y2, x1, x2]`（y 为纵向范围，x 为横向范围；若排除整行宽度，x1=0，x2=图片宽度）。

### Step 3：运行色彩分析脚本

脚本支持两种调用模式，根据 Step 1 判断的截图数量选择：

**单图模式**（单个搜索词只有一张完整整页截图）：

```
python3 scripts/page_color_analysis.py '{"image": "page.png", "exclude_regions": [[y1,y2,x1,x2], ...], "out_debug": "debug.png"}'
```

**多屏合并模式**（同一搜索词的多张滚动截图，需合并为一条结论）：

```
python3 scripts/page_color_analysis.py '{"pages": [
  {"image": "page1.png", "exclude_regions": [[y1,y2,x1,x2], ...], "out_debug": "debug1.png"},
  {"image": "page2.png", "exclude_regions": [[y1,y2,x1,x2], ...], "out_debug": "debug2.png"}
]}'
```

多屏模式下，脚本会对每张截图分别构建排除 mask 并各自生成调试图（供 Step 4 逐张核对），再将所有截图的有效像素直接拼接成一份样本统一统计占比与评级——即等价于把这些截图当作同一个页面的延续内容来看待，而不是分别评级后再取平均或加权，这样才能反映"用户完整滚动浏览这个搜索结果页"所感知到的真实色彩分布。

无论哪种模式，脚本都会自动排除白色背景（RGB 三通道均 ≥ 247）与 `exclude_regions` 覆盖的像素，对剩余有效像素做 HSV 分析，分别按 36 色标准和 7 色标准统计占比，输出总颜色数量、主导色数量、各色系占比明细及评级结果（JSON 格式）。

### Step 4：核查调试图，确认排除准确性

1. 查看脚本生成的调试图（黄色半透明覆盖表示被排除区域）。
2. 核对两点：一是商家图片/营销素材/金刚icon/图筛分类配图是否被完整覆盖排除；二是标签、文字、价格、按钮、图筛文字标签与选中态等 UI 元素是否**没有**被误框进排除区域（尤其注意标签紧贴图片边缘、营销卡片内标签与产品图上下相邻、图筛配图与其文字标签上下相邻的情况）。
3. 若发现排除不准确（漏排或误排），回到 Step 2 重新读取精确坐标，修正 `exclude_regions` 后重新运行 Step 3，直至调试图核查通过。

### Step 5：输出结果

**5a. 页面级评测明细表：**

| 搜索词 | Tab/场景 | 总颜色数量 | 主要色系占比（36色） | 主导色数量 | 主导色系占比（7色） | 评级 |
|--------|----------|:---------:|---------------------|:---------:|---------------------|:----:|
| 搜索词 | Tab名 | N | 色系1 X%、色系2 X%… | N | 色系1 X%、色系2 X%… | 🟢/🟡/🔴 |

**5b. 评级分布汇总（若为多张截图/多个搜索词）：**

| 搜索词 | 页面 | 🟢 优秀 | 🟡 达标 | 🔴 不达标 |
|--------|------|:------:|:------:|:--------:|
| 搜索词 | 页面数 | N | N | N |

**5c. 总结说明：**

在表格下方附一段文字总结，包含：各页面的评级成因解读（例如"总颜色数量处于优秀区间但主导色为 0，说明有彩色元素分布分散、缺乏统一的视觉焦点"）、不达标/达标页面的具体优化方向（哪些色系可以合并或收拢成统一强调色）、以及页面之间的横向对比趋势（如多个搜索词是否存在共性问题）。

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 单张整页截图、单个搜索词 | 直接按 Step 2–5 分析，使用脚本的单图模式（`image` 参数），输出一条评级结论 |
| 多张截图、同一搜索词不同屏（滚动截图，共同构成一个完整页面） | 每屏各自用网格图标定排除区域（Step 2 对每张图分别做一遍），再用脚本的多屏合并模式（`pages` 参数）一次性传入所有截图及各自的 `exclude_regions`/`out_debug`；脚本会拼接所有截图的有效像素统一统计并给出**一条**合并评级，而非逐屏分别评级后取平均。Step 4 需要逐张核对每屏各自生成的调试图 |
| 多张截图、不同搜索词 | 每个搜索词独立执行完整流程（Step 2–5），最终在 5b 汇总所有搜索词的评级分布 |
| 多张截图、同一搜索词不同 Tab | 每个 Tab 独立分析，分别标定排除区域、分别运行脚本、分别产出评级 |
| 页面几乎全部是照片/营销素材（如信息流广告页） | 排除后有效像素可能极少，脚本会报错"有效像素为 0"；此时应与用户确认该页面是否适用本评测维度，或适当放宽排除粒度（如保留部分图片边缘的过渡像素） |
| 页面为深色/非白色背景 | RGB ≥ 247 的白色背景阈值不适用于深色主题页面，需要额外将背景色本身（而非仅白色）也纳入人工标定的排除区域，或与用户确认改用其他背景检测方式 |
| 评级卡在优秀/不达标之外的中间组合（如总颜色数在优秀区间但主导色为 4） | 按评估标准中的"判定优先级"规则，统一归入 🟡 达标，不需要额外与用户确认 |
| 商家 Logo 类小图标（非头图/菜品图，而是品牌横排缩略图，如药品/数码品牌图标区） | 视为商品图片的一种，同样标定为排除区域，不因为面积小而遗漏 |
| 图筛/金刚位的分类配图（如"金枕/黑刺"等品类照片缩略图） | 视为运营/供给决定的内容图片，逐项配图各自标定为排除区域，不因单张面积小而遗漏、也不把整条图筛行合并成一个大矩形；同一分类项的文字标签与选中态是 UI 部分，必须保留统计，不得把整项一并框除 |
| 营销 banner/腰封上叠加了独立标签 | banner/腰封底图整体排除，但标签本身若能与底图区分出独立的矩形范围，应将标签范围排除在 exclude_regions 之外以保留统计；若标签与底图完全融合无法拆分矩形，可整体排除并在总结中注明"该营销区域标签色彩未纳入统计" |
| 用户要求同时输出组件级明细 | 页面级颗粒度是本 Skill 的固定输出范围，若用户需要组件级明细，应说明这是 `eval-3-color-logic` 的职责并建议追加调用该 Skill，不在本 Skill 内越界输出 |
| 图片路径不存在或脚本报错 | 检查图片路径是否正确、`exclude_regions` 坐标是否超出图片边界，修正后重新运行 |

## Gotchas

- **不做自动照片检测，必须人工标定排除区域**：本 Skill 与组件级的 `eval-3-color-logic` 不同，不使用轮廓分类等自动算法识别照片，因为整页版式差异极大、自动检测在本颗粒度下误判率偏高。每次分析都需要重新读图标定坐标，不能复用上一张图的排除区域。
- **排除区域的坐标必须逐张图核实，不能凭经验估算**：不同截图即使搜索词相似，商卡内图片位置、营销区域高度也可能不同（如本轮实践中，同一批截图里营销 banner 的位置在不同图中相差数百像素）。标定坐标前务必先看网格图，标定后务必看调试图核对，两头都不能省略。
- **标签与图片的分界线容易搞错，需要放大局部网格图核实**：整体网格图（100px 间距）容易把标签和图片当作同一块处理，导致标签被误排除或图片边缘遗漏。遇到临界情况，切到 20px 间距的局部放大网格图逐像素核实。
- **两个指标的分母相同，都是全部有效像素（含中性色），不是有彩色像素数**：如果错误地用"有彩色像素数"作分母，会人为放大占比、导致主导色数量虚高，评级结果失真。
- **36 色与 7 色是两套独立的分类体系，不能混用同一份占比结果**：品红在 36 色里单独占一格，在 7 色里要先并入红再统计占比；如果直接拿 36 色的品红占比去跟 5% 比较，会漏算真正应该归入红色系的部分像素，导致主导色数量被低估。
- **占比阈值是"≥"还是">"要严格区分**：总颜色数量用"≥ 1%"（含 1% 本身），主导色数量用"> 5%"（不含 5% 本身）。阈值恰好卡在边界值时结果不同，脚本中已按此实现，人工复核时也要留意。
- **营销类元素排除的是底图，不是标签**：banner、腰封本身要排除，但叠加在其上的独立标签（如"享2.8折"红色标签）是 UI 设计元素，应尽量拆分出标签的矩形范围保留在统计内。完全无法拆分时才整体排除，并在总结里如实说明这一处理方式，不要默默吞掉这部分信息。
- **评级三条规则本身有交叉地带，必须按 Step 5 之前"评估标准"里的优先级顺序判断**：不要凭直觉套用某一条规则就下结论，尤其是主导色数量恰好等于 4、或总颜色数量恰好等于 6/10 这些边界值时，容易判错档位。
- **调试图是排除区域是否准确的唯一验证手段**：不看调试图直接输出结果，无法发现排除范围是否漏项或过度覆盖，评级结果不可信。每次修正坐标后都要重新生成调试图复核，直到确认无误再进入 Step 5。
- **JSON 输出注意 numpy 类型转换**：脚本内部已将 numpy 数值类型转换为 Python 原生类型，若在此基础上二次开发脚本，务必保留这一步，否则会出现 JSON 序列化报错。
- **完成评测后保留中间调试文件**：网格辅助图、调试图等中间产物用于人工核对和复盘，不属于最终交付物但不得删除；应归档到 `.artifacts/过程文件-评测结果与审计/<批次>/<搜索词>/phase3/` 并记录生成参数与用途。

## 示例

### 示例：某搜索词整页截图评测为 🟡 达标

搜索词：库迪

页面结构：搜索栏、Tab栏、筛选栏、3 张商卡（各含 1 张主播直播海报 + 2–3 张饮品营销图，均已标定为排除区域），保留"特价团""享2.8折""直播中""秒提""神券"等 UI 标签及评分、价格文字参与统计。

排除后统计结果：总颜色数量 = 6（紫12.54%、红11.82%、橙8.34%、蓝3.94%、品红1.71%、黄1.28%），主导色数量 = 3（红13.53%、紫12.54%、橙8.34%）。

评级依据：总颜色数量 6 属于优秀区间 [0,6]，但主导色数量为 3，命中"达标"规则中的"主导色数量 = 3"，因此不满足优秀条件（需要主导色数量 ∈ [1,2]），最终评级为 🟡 达标。

成因解读：红、紫、橙三种强调色并存——紫色来自品牌直播海报，红橙来自大量促销标签，二者色彩体系不同（品牌调性 vs 促销调性），导致主导色数量多出 1 个。若希望提升到优秀档，可考虑将促销类标签的色系收拢统一，减少与品牌色之间的视觉竞争。

### 示例：同一搜索词 3 屏滚动截图，多屏合并模式评测为 🔴 不达标

搜索词：啤酒（全部 Tab，滚动截图共 3 屏）

处理方式：3 张截图各自用 `grid_overlay.py` 标定排除区域后，一次性传入 `page_color_analysis.py` 的 `pages` 参数做多屏合并模式，脚本将 3 屏的有效像素拼接为一份样本统一统计，并各自生成调试图供逐屏核对。

合并后统计结果：总颜色数量 = 7（绿13.14%、红10.53%、橙7.62%、黄5.62%、青5.48%、蓝4.74%、黄绿1.03%），主导色数量 = 5（绿14.17%、红10.69%、橙7.62%、黄5.62%、青5.48%）。

评级依据：主导色数量 5 > 4，命中不达标条件中的"主导色数量 > 4"，直接判定为 🔴 不达标（不再继续判断优秀/达标条件）。

成因解读：页面中同时存在多种啤酒品牌包装图之外的强调色（促销标签红/橙、品类导航或图筛的绿/青/蓝等），彼此占比接近、没有形成 1–2 个明显的视觉主导色，说明整页的强调色使用比较分散。建议排查图筛/快筛/标签体系中是否有可以统一收拢的色系。
