- 【技能专属】`observableFact` 必须写清页面区域、缺失模块或空白状态。
- 【技能专属】示例输出：`结果列表首屏下半区为空，未显示应有的结果卡，评级为不达标。用户无法继续浏览与搜索词相关的供给。`

- 达标或不达标结论的 `assessmentRows` 必须保留整页核查事实、命中规则及评级解释（技能专属覆盖模式：达标/不达标才需要）；优秀不要求保留 `assessmentRows`。
- `details.evidenceMode`、优秀排除规则同 7 个 skill 逐字相同条款，详见 [[页面框架评测通用契约]]。

## Phase2 事实输入契约

- 页面模块、坐标、可见状态、列表前置营销、结果列表及卡片数量必须读取 Phase2 `pageFacts.modules`、`cards[].structure`、`pageFactInventory`；不因模块未被猜测式列入而判缺失。
- 模块是否“应当存在”、大面积空白是否构成框架异常仍由本 Skill 按适用性证据终判；`uncertain` 只能触发 Phase2 复核，不得用于问题或优秀结论。

## 工具定位

本 Skill 用于评测搜索结果页或信息页截图中的**供给呈现质量——模块/组件完整性维度**，即页面中的重要模块与组件是否完整加载、是否存在整体性缺失或布局异常。AI 负责识别页面中每个重要模块/组件的加载状态，判断是否存在未加载、大面积空白、布局渲染异常等问题，并按标准给出评级结论。模块检查仅作为页面框架判断证据；最终按**搜索词 × 页面**颗粒度输出一条页面级评测结论，报告不得将问题拆成组件级评级。

**与同系列 Skill 的边界：**

- 本 Skill 关注"页面的重要模块/组件是否整体性缺失或布局异常"（模块级完整性问题，粒度较粗）。
- `supply-completeness-scanner` 关注"单个组件内部的信息元素是否缺失"（元素级完整性问题，粒度较细，如商卡内缺标题/价格/评分等）。
- 两者是不同粒度的互补关系：本 Skill 先判断"模块/组件本身是否存在"，`supply-completeness-scanner` 再判断"已存在的组件内部信息是否齐全"。

## 核心概念

### 重要模块/组件

**定义：** 搜索结果页或信息页中，构成完整页面框架所必需的独立功能区域。每个模块/组件承担特定的用户功能，缺失会直接影响用户的浏览、筛选或决策体验。

**页面重要模块/组件清单：**

| 模块/组件 | 说明 | 典型位置 |
|-----------|------|----------|
| 搜索栏 | 显示搜索词、返回按钮、地图入口等 | 页面顶部 |
| Tab栏 | 页面频道切换（如全部/外卖/团购/地点/笔记） | 搜索栏下方 |
| 快筛栏 | 筛选/排序条（如位置距离/综合排序/价格等筛选项） | Tab栏下方 |
| 图筛区 | 带品类图片/图标及对应分类文字的意图细分入口；仅在当前页面有明确容器/占位、同一页面结构对照或已配置业态规则时适用 | Tab栏或快筛栏附近 |
| 营销横幅 | 活动入口、优惠提示条（如神券膨胀提示） | 快筛栏下方 |
| 商卡列表 | 搜索结果的核心内容区，由多张商卡组成 | 页面主体区域 |
| 头部卡片 | 品牌直达、官方旗舰、聚合入口等特殊卡片 | 商卡列表上方或首位 |
| 业态特有模块 | 特定业态独有的功能模块，如酒店的日期选择栏、外卖的配送地址栏等 | 视业态而定 |

> 不同搜索词/业态的页面结构可能不同，并非所有模块都必须存在。判断"缺失"时需结合该业态的正常页面框架，而非机械套用上述全部清单。业态特有模块（如日期选择栏）仅在该业态下计入基线。

### 模块/组件缺失

**定义：** 页面中某个重要模块/组件出现以下情况之一，即判定为"缺失"：

1. **完全不存在**：该模块/组件在页面中没有任何呈现（如应有Tab栏但页面中完全看不到）。
2. **加载异常/渲染不完整**：模块/组件存在但明显不完整，如商卡列表只占据页面部分区域而其余区域为大面积空白、图片全部为占位图、整个模块呈灰色/白色加载态等。
3. **布局严重异常**：模块/组件虽然存在，但布局明显不符合正常设计——如商卡列表应双列展示却只有单列且另一侧大面积留白、列表应全宽展示却只占一半屏幕宽度等。

**判断关键：** 核心标准是"用户能否正常使用该模块的功能"。大面积空白是最显著的异常信号——正常页面不会在内容区域出现大块无内容的空白。

### 模块重要程度分类

模块/组件按其对用户浏览体验的影响程度分为两级：

**核心模块（缺失即不达标）：**

- **商卡列表**：搜索结果的核心展示区域，是用户浏览和决策的主要信息来源。包括列表的布局完整性（是否铺满正常展示区域，不应存在大面积空白）。
- **Tab栏**：频道切换入口，缺失会导致用户无法在不同频道间切换。

**辅助模块（缺失为达标，不触发不达标）：**

- **搜索栏**：顶部搜索区域。
- **快筛栏**：筛选/排序功能条。
- **营销横幅**：活动/优惠提示。
- **图筛区**：条件性意图细分入口，不是所有首屏默认模块；仅在满足适用性证据时才可计入基线。
- **头部卡片**：品牌直达等特殊卡片（并非所有搜索词都有，仅在该业态设计中应有而未出现时才计缺失）。
- **业态特有模块**：如酒店的日期选择栏、外卖的配送地址栏等，仅在对应业态下计入基线。

**分类原则：** 核心模块是用户完成"浏览搜索结果 + 切换频道"两个基本动作所必需的页面框架；辅助模块是提升筛选效率和获取优惠信息的增强功能，缺失会降低体验但不阻断基本浏览。

## 评估标准

模块扫描仅用于形成页面级判断证据，**不输出模块/组件的独立评级或问题条目**。

**页面级评级：**

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 页面内所有适用的重要模块均完整加载，无缺失、无布局异常 | 页面框架完整 |
| 🔴 不达标 | 页面内存在任一核心模块缺失（完全不存在/加载异常/布局严重异常） | 页面框架存在严重缺失 |
| 🟡 达标 | 核心模块均正常，但存在辅助模块缺失 | 基本框架完整但辅助功能有缺失 |

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 用户提供页面截图（单张或多张）。使用图片读取工具加载所有截图。
2. 识别搜索词（顶部搜索栏文字）；若为非搜索场景（如详情页、列表页），识别页面所属场景名称代替搜索词。
3. 识别当前 Tab/频道（全部、外卖、团购等），若页面无 Tab 概念可省略。
4. 若为多屏截图，记录屏次，最终需合并为一份完整报告。

### Step 2：确定该页面的模块基线

在扫描缺失之前，先判断"这个搜索词/业态的页面，正常情况下应包含哪些重要模块/组件"，避免把"设计上本就没有该模块"误判为"缺失"。

1. 根据搜索词判断业态（餐饮/酒店/生活服务/商品/医药等）。
2. 确定该业态页面的**标准模块基线**：
   - 所有搜索结果页默认包含：搜索栏、Tab栏、快筛栏、商卡列表。
   - 图筛、营销横幅、头部卡片为可选模块；图筛仅在当前截图有明确图筛容器/空占位、同一页面结构对照明确存在，或可追溯的“搜索意图×业态×Tab”规则要求时才计入基线。仅凭“首屏未看到图筛”不得报问题，更不得将图筛定为核心模块。
3. 不同业态的商卡列表布局可能不同（如餐饮类为全宽单列、酒店类可能为半宽带详情的单列），需结合该业态的正常布局模式判断是否异常。**关键判断依据**：同一页面中，商卡列表是否占满了其应有的展示区域？是否存在不合理的大面积空白？

### Step 3：逐模块/组件扫描完整性

对页面中基线内的每个模块/组件，依次检查：

**3a. 检查存在性**：该模块/组件在页面中是否可见？
- 完全不存在 → 记录为"缺失（完全不存在）"

**3b. 检查加载状态**：模块是否正常加载完成？
- 整体呈加载中/占位态 → 记录为"缺失（加载异常）"
- 内容区域为纯空白/纯色块 → 记录为"缺失（加载异常）"

**3c. 检查布局完整性**（重点针对商卡列表）：
- 商卡列表是否铺满正常展示区域？
- 是否存在大面积空白（如列表只占屏幕一半、另一半完全空白）？
- 列表布局是否符合该业态的正常模式（单列全宽/双列瀑布流等）？
- **空白判定原则（证据优先）**：若列表旁存在明显的连续空白区域（目测超过屏幕宽度的 1/4 以上），且该空白区域无任何功能性内容（如地图、侧边栏、详情面板等），并能说明正常布局预期，才可判定为“布局严重异常”。仅因无法判断设计意图不得判异常；页面不达标结论必须写明当前截图中的可见异常和该模块的适用性依据。

**3d. 对每一处缺失，记录：**
- 缺失模块/组件名称
- 缺失形式（完全不存在/加载异常/布局严重异常）
- 具体表现描述（如"商卡列表仅占屏幕左侧约50%宽度，右侧约50%区域为大面积空白"）
- 所属重要程度类别（核心模块/辅助模块）

### Step 4：汇总与评级

1. 将模块核查结果汇总为一个页面框架结论，不给单个模块/组件单独评级。
2. 按页面结论：
   - 存在任一核心模块 🔴 → 该搜索词整体评级 🔴 不达标
   - 核心模块均 🟢，但存在辅助模块 🔴 → 该搜索词整体评级 🟡 达标
   - 所有模块均 🟢 → 该搜索词整体评级 🟢 优秀

### Step 5：输出结果

**5a. 页面级评测结论：**

| 搜索词 | 页面 | 页面框架核查摘要 | 核心模块是否完整 | 整体评级 |
|--------|------|------------------|:--------------:|:-------:|
| 搜索词 | Tab名 | 已核查的页面模块及异常概述 | 是/否 | 🟢/🟡/🔴 |

**5b. 问题说明（仅不达标/达标页面）：**

每个问题以**页面框架问题**表述：说明异常所在的页面区域、缺失形式和用户影响，但不得以“组件X不达标”或逐组件评级的方式展示。示例："结果列表区域出现大面积无功能留白，页面主内容未完整加载，影响连续浏览。"

**5c. 总结说明：**

在表格下方附一段文字总结，包含页面框架问题及典型表现、可能原因推测和建议研发排查方向。

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 单张截图、单个搜索词 | 直接分析，输出明细表格 + 汇总评级 + 总结 |
| 多张截图、同一搜索词不同屏 | 分屏分析后合并为一份完整报告 |
| 多张截图、不同搜索词 | 每个搜索词独立评测，最终汇总所有搜索词的评级 |
| 多张截图、同一搜索词不同Tab | 每个 Tab 独立分析，分别输出明细表格和评级结论 |
| 商卡列表存在大面积空白 | 重点关注空白区域的位置和比例，判断是"布局异常"还是"该业态正常布局"；若同业态其他搜索词的列表为全宽展示而当前页面为半宽+大面积空白，应判定为布局异常 |
| 商卡列表底部被截断 | 底部截断属于正常滚动行为，不视为缺失；但若可见区域内商卡数量异常少（如仅1-2张且页面大量留白），需判断是否为加载异常 |
| 页面为空结果（无任何商卡） | 若页面显示"暂无结果""没有找到相关内容"等空态提示，属于正常空态设计，商卡列表不计为缺失，整体评级根据其余模块完整性判断；若无空态提示且商卡区域完全空白，判定为加载异常 |
| 页面存在非标准布局（如地图+列表左右分栏） | 需识别为该业态的正常布局模式（如酒店搜索的地图模式），列表占据部分宽度为设计意图，不判定为布局异常 |
| 某辅助模块在同业态其他页面中从未出现 | 判定该模块对此业态不适用，不计入基线 |
| 某辅助模块在同业态其他页面中存在但当前页面缺失 | 判定为该页面缺失，不得以"非必要模块"为由豁免 |
| Tab栏内容与搜索词业态不匹配 | 仅评测Tab栏是否存在、是否可见，不评测Tab项内容是否正确（内容正确性属于其他评测维度） |
| 搜索词/场景无法识别 | 询问用户确认搜索词或页面场景 |
| 用户明确指出某处异常要求复查 | 重新仔细审视指出的区域，不能简单归因为"正常设计"，需提供充分理由或修正判断 |

## Gotchas

- **大面积空白是最关键的异常信号（宁严勿松）**：正常的搜索结果页不会在主内容区域出现大块无功能的空白。当商卡列表旁出现明显的连续空白（目测超过屏幕宽度 1/4 以上）且无任何功能性内容时，**默认判定为布局异常**，不要轻易归因为"该业态的正常布局"。只有当空白区域有明确的功能性设计意图（如地图视图、侧边详情面板等）时，才可豁免。这是本 Skill 最容易误判的地方——错误地将异常合理化为"正常设计"。
- **"正常布局"不能随意认定**：在没有充分证据的情况下，不要将明显异常的布局（如列表只占半屏）简单解释为"该品类的正常布局样式"。只有当存在明确的功能性设计意图（如地图视图、侧边筛选面板等占据了另一部分空间）时，才能判定为正常。
- **先看整体再看细节**：本 Skill 的评测粒度是"模块/组件级"，关注的是页面框架是否完整。不要一上来就钻进单个商卡内部检查元素缺失（那是 `supply-completeness-scanner` 的职责），先从全局视角扫描页面的模块组成和布局状态。
- **底部截断 ≠ 缺失**：截图底部的商卡被截断是正常的滚动行为，不应判定为缺失。但要注意区分"正常截断"和"异常截断"——如果可见区域内只有极少量商卡且页面大面积留白，可能是加载未完成。
- **空态页面需区分正常与异常**：搜索无结果时页面显示空态提示是正常设计；但如果搜索词明显应有大量结果（如"火锅""酒店"等高频词）却显示空态或商卡极少，可能是加载异常，应在总结中标注供研发排查。
- **不同截图间不能互相豁免**：每个搜索词的页面独立评测。不能因为"搜索词A的页面正常"就降低对"搜索词B的页面"的评判标准。
- **"列表内有内容"不代表"列表布局正常"**：即使商卡列表中的每张卡片本身信息完整（标题、价格、图片等齐全），但如果列表整体只占据了屏幕一半的宽度、另一半为空白，仍然属于布局严重异常。不要因为"卡片内部没问题"就忽略"列表整体布局有问题"。模块级评测关注的是整体框架，不是单卡内容。
