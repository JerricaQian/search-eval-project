## 评审对象与共同契约

遵循 [[页面框架评测通用契约]]（`phase3-page_framework-eval/页面框架评测通用契约.md`）。每个搜索词×页面只输出一个框架结论；模块核查只是其证据，不展示为组件级评级。组件内标题、价格等缺项交给组件供给完整性。

## Phase2 事实门槛

- 模块、坐标、可见状态、结果列表与卡片数量只读 `pageFacts.modules`、`cards[].structure`、`pageFactInventory`；`uncertain` 只触发 Phase2 复核。
- 必须先以当前页面的业态与可见结构确认适用基线。搜索框、Tab 栏、头部卡、结果列表/商家卡是当前已确认适用时的核心模块；图筛、排筛区、营销横幅和业态特有模块仅在当前截图有容器/空占位、可靠结构对照或明确的“意图×业态×Tab”规则时计入；未看到不是缺失。
- 本 Skill 只看模块是否整体出现和加载，不检查已经出现的商卡内部标题、价格、标签或图片。这些属于组件供给完整性，不能因同一截图同时在两个 Skill 扣分。

## 判定标准

| 类型 | 适用模块 | 缺失后的页面评级 |
|---|---|---|
| 核心 | 当前已确认适用的搜索框、Tab 栏、头部卡、商卡/结果列表（含可确认的严重布局异常） | 不达标 |
| 辅助 | 快筛、图筛、排筛区、营销横幅、其他适用的业态模块 | 达标 |

全部适用模块完整为优秀。严重布局异常必须能说明正常展示区域、当前无功能的大面积空白与适用性；仅因设计意图不明不得判异常。

先区分“无模块”和“模块中元素不完整”：前者才是本 Skill 候选。对每个适用模块检查存在、完整加载、正常呈现与占位四个状态；截图自然未覆盖、当前业态不适用、或事实为 `uncertain` 时不当作缺失，应回到 Phase2 复核。

## 评分与聚合

- 一个页面只有一个评级。任一确认的核心模块缺失/严重异常即不达标；没有核心问题但存在辅助模块问题为达标；其余优秀。
- 多个辅助问题仍是一个页面级达标结论，多个核心问题也只是一条不达标结论。
- `weightedScore = weight[rating]` 且只写一次：优秀 `0`、达标 `-1`、不达标 `-2`，不按模块数扣分。

## 固定评审流程

1. 从 Phase2 模块事实建立仅属于当前页面的适用基线，为每项标记核心或辅助及适用证据。
2. 逐项核验“存在、正常加载、正常占位”；有候选时核对是否只是组件内元素缺项或自然未覆盖。
3. 对确认问题写模块区域、缺失/空白/加载异常形式和可见表现；`uncertain` 先请求 Phase2 复核。
4. 按核心优先规则输出唯一页面评级和 `weightedScore`。

## 输出与反误判

- 固定字段：`pageId`、`applicableModules`、`moduleChecks`、`rating`、`finding`、`observableFact`；达标/不达标保留 `assessmentRows`，优秀遵循共同契约。
- 不得把“截图未覆盖”“元素缺项”“猜测应有图筛”写成框架缺失，也不得用其他搜索词或历史页面补基线。

## Gotchas

- 结果列表只有卡内标题缺失时，列表模块仍在，不是页面模块缺失。
- 空白区必须同时有模块适用性和无功能/加载异常的可见证据；纯留白或设计节奏不够。
- 其他搜索词页面有图筛，不代表当前页面也应有图筛。
