## 三档解释与页面级证据展示契约

问题解释统一契约（必填）通用条款见 [[页面框架评测通用契约]]（`phase3-page_framework-eval/页面框架评测通用契约.md`），本 Skill 不重复列出。

### 简洁问题卡输出与示例（强制）

- 【技能专属】`observableFact` 必须写清首屏功能区数量及主要区域。
- 【技能专属】示例输出：`首屏在搜索栏下方展示 Tab、图筛、快筛、营销横幅和 4 类结果卡，共 8 个独立功能区，评级为不达标。核心结果列表被多层前置内容推后，增加首次获取结果的成本。`

- 达标或不达标结论的 `assessmentRows` 必须保留整页核查事实、命中规则及评级解释（技能专属覆盖模式：达标/不达标才需要）；优秀不要求保留 `assessmentRows`。
- `details.evidenceMode`、优秀排除规则同 7 个 skill 逐字相同条款，详见 [[页面框架评测通用契约]]。

## Phase2 事实输入契约

- 首屏边界、模块类型、坐标、部分可见状态以及普通结果列表/主卡/异构卡实例必须读取 `pageFacts.modules` 和 `pageFactInventory`；不得将 Tab、快筛、图筛或业务图筛的内部子项重复当模块。
- 本 Skill 只按既定合并与计数规则完成首屏功能区计数；模块是否独立仍以 Phase2 记录的可见功能和几何边界为证据。卡内榜单、折扣、票券、价格、标签和下挂信息均是组件内部元素，绝不得作为页面功能区计数或页面降档理由。

## 工具定位

本 Skill 用于评测搜索结果页或信息页截图中的**静态组件复杂度——首屏功能区数量维度**，即页面首屏中独立功能区的个数是否合理。首屏功能区越多，用户需要滚动更远才能到达核心内容（商卡列表），信息层级越深，页面越复杂。AI 负责识别页面首屏中的所有独立功能区并计数，按标准给出评级结论。最终按**搜索词 × 页面**颗粒度输出评测结论。

**与同系列 Skill 的边界：**

- 本 Skill 关注"首屏有多少个独立功能区"（页面框架级复杂度，颗粒度为整个页面），判断页面结构是否过于臃肿。
- `static-element-complexity-scanner` 关注"每个组件内部的标签样式/icon样式数量"（组件级静态元素复杂度），颗粒度更细。
- 两者是不同层级的互补关系：本 Skill 先判断"页面塞了多少个功能区"，`static-element-complexity-scanner` 再判断"每个功能区内部的元素是否过于复杂"。

## 核心概念

### 首屏

**定义：** 用户打开搜索结果页后，在不滚动的情况下能看到的全部内容区域。对于手机截图，首屏大致对应屏幕可视区域内的所有内容。

**判定方式：** 以截图中从顶部状态栏到屏幕底部边缘的完整可视范围为首屏边界。若截图为长截图（滚动拼接），则以一个标准手机屏幕高度为首屏范围（约前 2/3 至 3/4 的截图高度，具体视手机分辨率而定）。底部仅露出顶部一小条的功能区（如商卡仅露出标题行）仍计入首屏功能区。

### 独立功能区

**定义：** 页面中承担独立用户功能、具有明确视觉边界的区域块。每个功能区在视觉上与其他区域有明确分隔（通过间距、背景色、分割线等方式），且承担不同的用户交互目的。

**功能区类型清单：**

| 功能区类型 | 说明 | 典型表现 |
|-----------|------|---------|
| Tab | 页面频道切换栏 | 问小团/全部/外卖/团购/地点/笔记/攻略 |
| 图筛 | 带图片的品类筛选区 | 带图片的横滑品类入口，如奶茶页的"珍珠奶茶/黑糖奶茶/果茶…"、理发页的"女士剪发/儿童理发/男士剪发…" |
| 业务图筛 | 业务品类导航（常见于旅游/景点类） | 带icon的品类横排，如"推荐/景点/酒店/美食/旅游产品/演出" |
| 快筛 | 筛选/排序条 | 地址选择/综合排序/距离最近/神券/价格筛选/漏斗图标 |
| 营销栏（优惠筛选） | 优惠活动入口/提示条 | "团购券 满28减2 满39减3"、"已获取全部大额神券 2张可用"、"恭喜获得满32减6外卖优惠券" |
| 主卡 | 品牌秀/阿拉丁/地标卡等特殊卡片 | 搜索直达的品牌/地标/POI卡片，如搜索"迪士尼"出现的上海迪士尼度假区阿拉丁卡、品牌视频秀卡 |
| 商卡 | 普通搜索结果商家/商品卡片 | 列表中的商家卡、商品卡、套餐卡等标准结果卡片 |
| 异构卡 | 非标准布局的特殊结果卡片 | 品牌直达卡、运营平台卡等与普通商卡布局结构明显不同的卡片 |
| 侧边栏组件 | 页面侧边的辅助功能 | 悬浮侧边栏、快速导航等 |
| 大家都在搜 | 相关搜索推荐区 | "大家还在搜"区域，展示相关搜索词推荐 |

### 功能区计数规则

**核心原则：按独立功能区块计数。** 大部分功能区类型只要出现即计 1 个（不论内部有多少条目），但主卡和异构卡因各自占据独立大面积区域，按实例分别计数。

**详细规则：**

1. **顶部搜索框不计入：** 搜索框是所有搜索结果页的固定基础元素，不纳入功能区统计。
2. **状态栏不计入：** 手机系统状态栏（时间、信号、电量等）不纳入统计。
3. **搜索框上方的关联搜索入口不计入：** 部分搜索词在搜索框上方或 Tab 上方会出现关联搜索词入口（如搜索"迪士尼"出现的"迪士尼排队攻略"文字链），这类入口不属于独立功能区，不纳入统计。
4. **商卡按类型合并：** 首屏内无论出现多少张普通商卡，统一计为 1 个"商卡"功能区。商卡本质上是搜索结果列表中的多条数据，同属一个功能区。
5. **主卡按实例计数：** 若首屏中出现多个视觉上独立的主卡（如阿拉丁卡 + 品牌秀视频卡），即使它们都属于"主卡"大类，但因为各自占据独立的大块页面空间、承担不同的信息展示功能，**按实例分别计数**。这是与商卡计数规则的关键区别——主卡是"占据大面积、独立承载完整信息"的特殊功能区，多个主卡对首屏复杂度的影响远大于多张商卡。
6. **异构卡按实例计数：** 异构卡（品牌直达卡、运营平台卡等）与主卡类似，每个异构卡在首屏中占据独立区域，按实例分别计数，不与商卡合并。
7. **图筛与业务图筛分别计数：** 图筛（品类图片筛选）和业务图筛（业务导航icon）是两种不同类型的功能区，即使视觉位置相邻也应分别计数。
8. **仅部分露出的功能区也计入：** 若某功能区在首屏底部仅露出一部分（如商卡只露出标题行和头图上沿），仍计为 1 个功能区。判断依据：用户能否在首屏看到该功能区的存在并理解其用途。
9. **图筛/业务图筛中的子Tab不额外计数：** 图筛或业务图筛区域内部的切换项（如“热门品牌/推荐品牌”“口味/品牌”）属于父筛选区的内部结构，不单独计为功能区；即使其视觉上换行展示，只要仍切换同一筛选容器内容，就必须与父筛选区合并。

## 评估标准

对**每个搜索词的首屏页面**给出一条评级：

| 评级 | 条件 | 含义 |
|------|------|------|
| 🟢 优秀 | 功能区数量 ≤ 4 个 | 首屏结构简洁，用户快速到达核心内容 |
| 🟡 达标 | 功能区数量 = 5 个 | 首屏结构尚可，功能区数量处于临界 |
| 🔴 不达标 | 功能区数量 ≥ 6 个 | 首屏过于复杂，功能区过多挤占内容空间 |

## 执行步骤

### Step 1：接收截图并确认评测范围

1. 用户提供页面截图（单张或多张）。使用图片读取工具加载所有截图。
2. 识别每张截图的**搜索词**（顶部搜索栏文字）。
3. 识别当前 **Tab/频道**（全部、外卖、团购等），若页面无 Tab 概念可省略。
4. 确认首屏范围：截图为标准手机屏幕截图时，整张截图即为首屏范围；截图为长截图时，取前一个屏幕高度作为首屏范围。
5. 按搜索词分组——每个搜索词作为一个独立的评测单元。

### Step 2：识别首屏内所有独立功能区

从搜索框下方开始，**从上到下**逐一识别首屏范围内的所有独立功能区：

**2a. 逐层扫描**

自顶向下扫描页面，遇到每个视觉上独立的区域块时，判断其属于哪种功能区类型（参照「功能区类型清单」）。

**2b. 记录每个功能区**

对识别出的每个功能区，记录：
- 序号（按从上到下的出现顺序编号）
- 功能区类型（Tab/图筛/业务图筛/快筛/营销栏/主卡/商卡/异构卡/侧边栏组件/大家都在搜）
- 具体内容摘要（如 Tab 的具体频道项、快筛的具体筛选项、商卡的商家名等）
- 是否完整可见（完整/部分露出）

**2c. 应用计数规则**

- 检查是否有多张商卡 → 合并为 1 个"商卡"功能区。
- 检查是否有多个主卡 → 按实例分别计数。
- 确认搜索框、状态栏、筛选区内部子Tab及卡内标签/票券均未被计为独立功能区。

### Step 3：计数与评级

1. 汇总首屏功能区总数。
2. 按评估标准判定评级：
   - ≤ 4 → 🟢 优秀
   - = 5 → 🟡 达标
   - ≥ 6 → 🔴 不达标

### Step 4：输出结果

**4a. 功能区识别明细表（每个搜索词一张）：**

| 序号 | 功能区类型 | 具体内容 | 是否完整可见 |
|------|----------|---------|------------|
| ① | Tab | 问小团/全部/外卖/团购/地点/笔记 | 完整 |
| ② | 快筛 | 望京恒电大厦/综合排序/距离最近/神券 | 完整 |
| ③ | 营销栏 | 团购券 满28减2 满39减3 满69减5 | 完整 |
| ④ | 商卡 | 商家卡×3（盒马鲜生代购等） | 部分露出 |

**4b. 按搜索词汇总评级表：**

| 搜索词 | 功能区明细 | 功能区数量 | 评级 |
|--------|----------|:---------:|:----:|
| 盒马 | ①Tab ②快筛 ③营销栏 ④商卡 | 4 | 🟢 |
| 咖啡 | ①Tab ②快筛 ③营销栏 ④商卡 | 4 | 🟢 |

**4c. 总结说明：**

在表格下方附一段文字总结，包含：各搜索词页面的首屏结构特点、不达标页面的功能区堆叠原因分析、达标率统计、以及跨搜索词的共性问题归纳（如旅游类搜索词普遍存在"主卡+业务图筛+快筛"的三层筛选堆叠）。

## 分支处理

| 场景 | 处理方式 |
|------|---------|
| 单张截图、单个搜索词 | 直接分析首屏，输出明细表 + 汇总评级 + 总结 |
| 多张截图、不同搜索词 | 每个搜索词独立评测，最终汇总所有搜索词的评级分布 |
| 多张截图、同一搜索词不同 Tab | 每个 Tab 独立作为一个评测单元，分别统计功能区数量和评级 |
| 多张截图、同一搜索词多屏滚动 | 仅分析第一屏，后续屏次不纳入首屏功能区统计 |
| 截图为长截图（滚动拼接） | 以一个标准手机屏幕高度为首屏边界，仅统计该范围内的功能区；若无法准确判断屏幕高度，以截图中第一张完整商卡的底部作为首屏的参考下边界 |
| 首屏中出现多个独立主卡 | 每个主卡按实例分别计数，不合并为 1 个功能区。例如阿拉丁卡 + 品牌秀视频卡 = 2 个功能区 |
| 首屏中出现多张商卡 | 所有商卡合并为 1 个"商卡"功能区，不论商卡数量 |
| 图筛与业务图筛同时出现 | 分别计为 2 个功能区。图筛（品类图片）和业务图筛（品类icon导航）承担不同的用户交互功能 |
| 图筛区域含子Tab（如"口味/品牌"） | 子Tab属于图筛内部结构，不额外计为功能区 |
| 功能区仅部分露出 | 只要用户能识别出该功能区的存在和类型，即计入统计 |
| 首屏底部刚好卡在某功能区的上边缘 | 若仅露出几个像素、肉眼无法识别功能区类型，不计入；若能看出是商卡标题行或图筛图片，计入 |
| 营销栏与快筛视觉紧邻难以区分 | 按功能判断：筛选/排序功能 = 快筛；优惠信息/活动入口 = 营销栏。即使视觉上紧邻，只要功能不同就分别计数 |
| 页面中出现「大家都在搜」 | 计为 1 个独立功能区。该区域承担相关搜索推荐功能，与商卡、快筛等功能区有本质区别 |
| 首屏中出现异构卡 | 异构卡按实例计数，每个异构卡计为 1 个独立功能区，不与商卡合并 |
| 两个主卡视觉上紧密相连（如阿拉丁卡底部直接接品牌秀卡） | 只要两者在信息内容和交互功能上是独立的（如一个展示基本信息+价格，另一个展示视频+子模块入口），仍按 2 个功能区计数，不因视觉上缺少明显间距而合并 |
| 搜索框上方出现关联搜索入口（如"迪士尼排队攻略"文字链） | 不计入功能区统计，该入口不属于独立功能区 |
| 无法识别某区域属于哪种功能区类型 | 描述该区域的视觉特征和内容，按最接近的功能区类型归类，并在总结中注明判断依据 |
| 用户自定义了不同的功能区类型或评级标准 | 以用户自定义标准为准，替换本 Skill 的默认功能区清单或评级阈值 |
| 搜索词/场景无法识别 | 询问用户确认搜索词或页面场景 |
| 页面存在已标注的红框/蓝框 | 标注框仅作为辅助识别参考，功能区的判断应以页面原始内容为准，不因标注框的划分方式而改变功能区的类型判定 |

## Gotchas

- **搜索框不计入是硬性规则**：搜索框是所有搜索结果页的基础框架元素（类似浏览器地址栏），不属于"独立功能区"。不要因为搜索框占据了首屏空间就将其计入。
- **商卡合并、主卡不合并，两者计数逻辑不同**：这是最容易混淆的地方。商卡是列表中的标准结果项，多张商卡本质上是同一功能区（搜索结果列表）的多条数据，合并计 1。主卡（品牌秀/阿拉丁/地标卡）则是独立的大块功能区，每个主卡承载不同的信息和交互目的，应按实例计数。典型场景：搜索"迪士尼"时，阿拉丁卡展示基本信息和价格，品牌秀视频卡展示品牌视频和子模块入口，两者虽都属于"主卡"类型，但在首屏中占据了两块独立的大面积区域，应计为 2 个功能区。
- **旅游/景点类搜索词容易不达标**：这类搜索词通常同时出现主卡（阿拉丁卡）+ 业务图筛（景点/酒店/美食等品类导航）+ 快筛 + 营销栏 + 商卡，功能区天然较多。评测时应如实统计，不因"该业态本身需要更多功能区"而降低标准。
- **图筛和业务图筛的区别**：图筛是带品类图片的横滑筛选区（如奶茶页面的"珍珠奶茶/黑糖奶茶"配图入口），业务图筛是带icon的业务品类导航（如旅游页面的"推荐/景点/酒店/美食"配icon入口）。两者虽然都起到分类筛选作用，但视觉形态和承载的信息维度不同（前者按品类细分，后者按业务线划分），应分别计为独立功能区。
- **营销栏的判定依据是"功能"而非"位置"**：营销栏可能出现在快筛下方、商卡上方、甚至商卡列表之间。只要其内容是优惠信息/活动入口（如"团购券满减"、"已获取大额神券"、"恭喜获得优惠券"），就属于营销栏，不因为位置变化而改变类型判定。
- **底部部分露出的功能区不要遗漏**：首屏底部经常出现只露出一小部分的商卡或功能区（如只看到第三张商卡的标题行），这些仍应计入。遗漏会导致功能区数量被低估，进而高估页面简洁度。
- **不要把功能区的"子元素"拆分为独立功能区**：Tab 栏内部的各频道项（全部/外卖/团购）是 Tab 的子元素，不应把每个频道项计为独立功能区。同理，快筛栏中的各筛选项（综合排序/距离最近/价格）是快筛的子元素。判断标准：这些子元素是否在同一个视觉容器中、承担同一个宏观功能（频道切换 / 筛选排序）。
- **「大家都在搜」容易被忽略**：该区域通常出现在商卡列表底部或中间，视觉上不太突出，但它是一个独立的功能区（相关搜索推荐），必须计入。
- **视觉上紧密相连 ≠ 同一功能区**：两个主卡之间可能没有明显的视觉间距（如迪士尼页面的阿拉丁卡底部直接衔接品牌秀视频卡），但只要两者承载的信息和交互功能是独立的，就应分别计数。判断标准是"功能独立性"而非"视觉间距"。
- **异构卡不要与商卡混为一谈**：异构卡（品牌直达卡、运营平台卡等）的布局结构与普通商卡明显不同，它在首屏中占据独立的展示区域，承担特殊的品牌/运营功能。应按实例单独计为功能区，不与商卡合并。
- **标注框仅作参考，不替代独立判断**：如果用户提供了已标注红框/蓝框的截图，标注框可以作为识别功能区的辅助线索，但最终的功能区类型判断和计数必须基于页面内容本身。标注可能存在遗漏（如漏标了某个功能区）或过度拆分（如把快筛的两行拆成两个框），不能直接采信。

## 示例

### 示例 1：简洁页面 → 🟢 优秀（4 个功能区）

搜索词：盒马

首屏功能区识别：①Tab（问小团/全部/外卖/团购/地点/攻略）→ ②快筛（望京恒电…/综合排序/距离最近/神券/3km/筛选）→ ③营销栏（团购券 满28减2 满39减3 满69减5）→ ④商卡（盒马鲜生代购×3）。

首屏结构简洁，搜索框下方仅有 Tab + 快筛 + 营销栏三层辅助信息后即进入商卡列表，用户快速到达核心内容。

结果：功能区数量 = 4 → 🟢 优秀

### 示例 2：临界页面 → 🟡 达标（5 个功能区）

搜索词：理发

首屏功能区识别：①Tab（问小团/全部/外卖/团购/地点/笔记）→ ②图筛（女士剪发/儿童理发/男士剪发/洗吹/烫染，带图片横滑）→ ③快筛（望京恒电大厦/综合排序/神券/1km内/一次性/筛选）→ ④营销栏（团购券 满37减3 满94减7）→ ⑤商卡（佟剪世家等×3）。

页面在 Tab 下方插入了图筛（品类图片入口），使功能区数量达到 5 个，处于达标临界。图筛对理发品类有一定的分流引导价值，但增加了一层首屏信息。

结果：功能区数量 = 5 → 🟡 达标

### 示例 3：复杂页面 → 🔴 不达标（6 个功能区）

搜索词：迪士尼

首屏功能区识别：①Tab（问小团/全部/外卖/团购/地点/笔记）→ ②主卡-阿拉丁（上海迪士尼度假区基本信息+价格+景点门票/附近酒店/景酒套餐子tab）→ ③主卡-品牌秀（上海迪士尼度假区视频卡+进店了解+超值门票/十岁庆典等子模块入口）→ ④业务图筛（推荐/景点/酒店/美食/旅游产品/演出，带icon）→ ⑤快筛（全部分类/距离/综合排序/美团618/筛选）→ ⑥商卡（疯狂动物城，部分露出）。

首屏同时出现两个独立的主卡形态（阿拉丁卡和品牌秀视频卡各自占据大块区域），加上业务图筛和快筛两层筛选，功能区达到 6 个。用户需要滚动较远才能看到第一张普通商卡。

结果：功能区数量 = 6 → 🔴 不达标

### 示例 4：含「大家都在搜」→ 🔴 不达标（6 个功能区）

搜索词：奶茶

首屏功能区识别：①Tab（问小团/全部/外卖/团购/地点/笔记）→ ②图筛（珍珠奶茶/黑糖奶茶/果茶/泰式奶茶…，含口味/品牌子Tab）→ ③快筛（望京恒电大厦/综合排序/距离最近/神券/年夜饭预订/筛选）→ ④营销栏（恭喜获得满32减6外卖优惠券）→ ⑤商卡（LELECHA乐乐茶、茉莉奶白等）→ ⑥大家都在搜（瑞幸咖啡/沪上阿姨/茉莉奶白/兰州拉面…）。

页面在 Tab 下方有图筛+快筛+营销栏三层信息后才进入商卡列表，且首屏底部还出现了「大家都在搜」推荐模块，使总功能区数量达到 6 个。

结果：功能区数量 = 6 → 🔴 不达标

## 输出清单（自检）

每次输出评测结论前，确认：

- [ ] 是否确认了首屏范围，未将滚动后才可见的功能区计入？
- [ ] 搜索框和状态栏是否已排除在外，未被计入功能区？
- [ ] 多张商卡是否已合并为 1 个"商卡"功能区？
- [ ] 多个主卡（如阿拉丁卡+品牌秀卡）是否按实例分别计数，而非合并？
- [ ] 图筛与业务图筛是否分别计数（若同时存在），且各自的内部子Tab未被重复计数？
- [ ] 是否排除了卡内榜单、折扣、票券、价格和标签，未将组件内部元素误计为页面功能区？
- [ ] 底部部分露出的功能区是否已计入？
- [ ] 「大家都在搜」等容易遗漏的区域是否已检查？
- [ ] 功能区明细表中每个功能区是否标注了类型和具体内容？
- [ ] 评级是否严格按"≤4优秀 / =5达标 / ≥6不达标"判定？
- [ ] 总结说明中是否包含了不达标页面的原因分析和跨搜索词的共性问题？
