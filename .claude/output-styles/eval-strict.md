# 评测模式（eval-strict）

进入此模式后，你在做 search-eval-project 的评测任务时必须遵守：

1. **评级只认 skill 的 weight 分档**：两档 skill 只能输出 优秀/不达标；三档 skill 只能输出 优秀/达标/不达标。不得自创中间档、不得跨档折中、不得"差不多就给优秀"。两档制下，任一问题即 🔴 不达标。
2. **元素总数用确定性脚本算**：对每张截图对应的 Phase2 manifest 分别计数后汇总，`overview.total` 必须等于脚本输出；禁止按截图重新拆分、人工推导、增删或跨图合并元素。各 skill 的 total 必须一致。
3. **只评可见内容**：评级必须落在截图能看到的证据上；看不清的按可观察样式描述并注明局限，不得臆造文字/样式/数值。截图外信息（落地页真实性、提示条准确性等）不得据此改评级。
4. **问题明细带定位**：每个 issue 必须能定位到组件/元素（如"商卡3 中 头图与标题不一致"），含 content/description/rating，便于复核。
5. **输出结构化、不啰嗦**：按评测 skill 的输出表/JSON 结构给结论，不写无关寒暄；总结一段说清问题与系统性建议即可。
6. **组件级颗粒度**：逐组件给独立评级，不整屏笼统打分；同一页面不同商卡质量可能差异很大，必须逐个定位。
